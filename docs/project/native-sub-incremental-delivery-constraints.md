# 原生 Sub 小步发布全局约束

## 1. 目标与事实源

- 本轮只在官方 Sub2API 原生后端、前端、运维页面和宿主发布链中嵌页面或增加功能。
- 不建设、恢复或切换 `external-primary`，不新增平行控制面、平行账务源或平行管理入口。
- 当前代码、测试和生产只读证据优先于历史计划；本文件和 `native-sub-task-package-queue.md` 优先于派生线程聊天上下文。
- 每个任务包只交付一个用户可感知或管理员可验证的垂直功能，不顺带实施相邻任务。

## 2. 派生线程启动规则

- 根线程按队列严格串行派生任务；前一任务包未完成线上验证或明确冻结时，不启动下一实现线程。
- 每个派生线程必须先读取本文件、任务队列、`AGENTS.md`、项目进度总账及自己的任务包描述。
- 每个派生线程必须从根目录当时最新且干净的 `main` 创建自己的 `codex/<task-name>` 分支和独立 worktree；禁止从其他任务分支、旧候选或生产运行提交派生。
- 派生线程先在自己的 worktree 登记总账，再写自己的规格书和实施计划；规格书、计划、代码、测试和验证证据都归入同一任务包。
- 派生线程不得改动其他任务包文件，不得自行扩大需求，不得触碰生产，不得自行合并 `main`、推送或部署。

## 3. 任务包完成与汇报协议

- 派生线程完成实现、定向测试、类型检查或构建、diff 自查和独立复审后，状态只能是 `READY_FOR_ROOT_REVIEW`，不能声明已完成或已部署。
- 汇报必须包含：任务包编号、基线 `main` SHA、提交 SHA、变更文件、测试结果、未验证项、迁移变化、配置变化、`downtime_required`、回滚方式和剩余风险。
- 根线程确认该任务包是当前队列唯一可部署候选后，发送带目标 `main` SHA 的 `AUTHORIZE_MERGE_TO_MAIN` 指令。
- 派生线程收到明确指令后才能把自己的已审查分支合入根目录 `main`；合并前必须确认根目录干净、目标 SHA 未漂移、没有其他合并或部署在进行。
- 合并完成后派生线程只汇报合并 SHA 和冲突/验证结果，继续等待；不得推送或部署。

## 4. 根线程快速发布协议

- 根线程在合并后的 `main` 只运行与当前任务包直接相关的回归、必要构建/类型检查、迁移检查和发布预检，不重复扩大到无关功能。
- 生产推送和部署只能来自已经验证的 `main`；禁止从派生 worktree、临时目录或候选分支直接发布。
- 发布准备不得使用 GitHub Actions，继续使用已审查的本地/宿主脚本和蓝绿链。
- 发布预检必须明确输出 `downtime_required=true|false`。为 `false` 时根线程可按已确认队列执行快速部署；为 `true` 时必须在任何停服、迁移、重启或切换动作之前停止。
- 一旦某次候选需要停机，本次及其后所有部署都暂停，等待用户人工确认；不得绕过、拆分或把停机包装成普通蓝绿更新。
- 部署成功后必须完成该任务包的线上专项验证和健康检查，再更新总账、授权清理对应 worktree/分支并派生下一任务。
- 部署或验证失败时保留工作区、分支、失败证据和回滚依据，在原任务包继续修复，不启动下一任务包。

## 5. 产品与数据边界

- 错误转译不新增平行页面。管理员在“管理后台 -> 用量明细 -> 错误请求 -> 错误详情”查看“管理员诊断”；运维总览的请求错误/上游错误详情复用同一诊断结构。
- 用户只看到脱敏中文含义和可执行建议；管理员可看到错误阶段、归属、是否已选账号、账号/分组、原始上游状态与原始错误，但不得把凭据、完整 API Key 或敏感请求体返回用户。
- 上游错误优先复用 Sub 原生错误透传规则；本站限流、鉴权、路由和请求体读取失败使用同一解释字典的本地分支，不伪装成上游错误。
- 大上下文上传问题按入站链路处理：保留请求体大小和安全边界，修复固定 300 秒代理窗口对慢速上传的误伤；不得仅把 502 改文案而不处理根因。
- Sub/New 原生账单返回是唯一事实源。上游实际扣费空白按 `0` 持久化或投影，利润继续计算；不增加对账状态、估算值、模糊匹配或外部账务前置条件。
- “控制面暂时不可用 / 完整性 unknown”从原生账号监控、用量和利润页面移除，不以其他外部控制面提示替代。
- “暂不建议入组”保持轻提示：桌面悬浮或点击、移动端点击，仅显示一到两行原因，不新增常驻说明区。
- 全局评分权重与分组评分权重独立持久化，复用现有分组评分设置交互，不改变既有排序之外的调度行为。
- 官方更新无冲突时快速准备；出现冲突立即停止、保存完整冲突日志，禁止猜测解决或自动部署，界面固定提示：`存在冲突，需要手动查看冲突日志并更新。`

## 6. 禁止事项

- 禁止把多个任务包合成一次大发布。
- 禁止同时让多个派生线程操作根目录 `main`。
- 禁止在任务包中引入 `external-primary`、relay-ops 主路径依赖或新的平行控制面。
- 禁止为了清理工作区而丢弃未合并提交、未提交内容或失败证据。
- 禁止在没有线上验证时把任务标记为“已完成”。
- 禁止在检测到冲突、停机需求或目标 `main` 漂移后继续自动推进。
