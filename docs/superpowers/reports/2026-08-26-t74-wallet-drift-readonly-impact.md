# T74 钱包与原生余额漂移 — 生产只读影响报告

查询时间：2026-08-26 17:16（Asia/Shanghai）。查询只读取生产 PostgreSQL，未写入任何记录。

## 口径

- 运行时真实可消费余额：`users.balance`。
- 管理端钱包显示余额：`user_wallets.paid_quota_balance_usd + user_wallets.gift_quota_balance_usd`。
- 漂移：钱包显示余额减运行时余额；仅统计未删除用户且绝对差大于 `0.00000001`。

全部差额方向均为钱包高于实际可消费余额，符合 T67 后原生推理只扣 `users.balance` 的根因。

## 执行边界

T74 不批量写生产数据。发布后，新推理扣费会在同一原生事务中把该用户的钱包投影先校准到本次扣费前的真实原生余额，并插入一条可审计的 `migration_projection`，随后插入本请求对应的 `usage_consumption`；这样不静默覆盖历史、也不改变用户实际余额。

对于不再发生请求但仍有漂移的用户，后续另立生产账务操作：先重新只读核算，再经用户确认，使用带唯一 reference/idempotency 的 `legacy_balance_adjustment` 或受控对账命令逐项创建审计流水。不得用裸 SQL 覆盖钱包或 `users.balance`。
