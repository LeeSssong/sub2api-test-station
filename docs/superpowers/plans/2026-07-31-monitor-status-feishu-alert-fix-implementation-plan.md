# 监控状态与飞书历史错误码修复实施计划

## 目标

修复监控页当前状态的历史失败误导，并修复飞书账号告警残留 `balance_exhausted` 导致的无可用账号误报。

## 实施步骤

1. **监控状态单元测试**：增加“旧失败 + 最新成功”以及“最新失败但近期有成功”的失败测试，先确认当前实现失败。
2. **监控状态实现**：将分组状态判定改为按探测时间使用最新结果，并保留过期/无数据保护；运行服务包测试。
3. **飞书账号健康单元测试**：增加历史余额耗尽后最新成功，以及最新仍余额耗尽的失败测试，先确认当前实现失败。
4. **飞书告警实现**：让聚合结果保留最新样本的错误语义；成功样本清除旧错误码对分类的影响；运行相关测试。
5. **复核与回归**：检查 diff，运行两个服务的目标包测试及必要的全包测试，并复核项目进度总账。

## 风险与回滚

- 探测时间字段为空或顺序异常时可能误选样本；实现必须保留现有新鲜度检查和稳定排序。
- 错误码仅用于展示时不能重新影响当前 Tier；测试需分别锁定“当前判定”和“原因展示”。
- 代码改动集中在监控状态聚合和账号健康分类，可按提交粒度回退。

## 完成条件

本地测试通过只代表“准备完成”；项目总账在推送、部署、线上验证完成前保持“进行中”或“工程代码/配置差异待部署”。
