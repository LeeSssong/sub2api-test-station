# Sub2API 0.1.166 Qualified Image And Cache Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge official Sub2API `v0.1.166` into the current Xingqiao-customized core, produce and deliver a qualified Linux AMD64 image to production, and reclaim production BuildKit cache without starting the application update.

**Architecture:** Official GitHub Releases remain the version source, while the current Xingqiao-customized Sub2API remains the single application core. The official `v0.1.165..v0.1.166` source delta is merged with three-way Git history, tested in isolation, built on the local Colima builder, transferred as a Docker image artifact, and accepted by the existing host updater only after label and image-ID verification. Production cache cleanup targets BuildKit records only; application images, rollback tags, containers, volumes, and release backups remain untouched.

**Tech Stack:** Git, Go 1.26.5, Node.js 24, pnpm 9, Docker Buildx/BuildKit, Bash, SSH, Docker Compose

## Global Constraints

- Keep Sub2API as the single customized core for this release.
- Official base changes are exactly `e9a58c1cb8b5ef626a75c93b4d953fde5e67aa29..dc893dd0b8eab41df5be595ae9fcd1aa74a062b8`.
- Preserve all Xingqiao source customizations unless an official change supersedes the same behavior and the merged tests prove compatibility.
- Build `linux/amd64` outside production; production only receives the completed image artifact.
- The delivered image tag is `xingqiao-sub2api:upstream-0.1.166`.
- Required labels are:
  - `com.xingqiao.sub2api.qualified=true`
  - `com.xingqiao.sub2api.upstream.version=0.1.166`
  - `com.xingqiao.sub2api.upstream.commit=dc893dd0b8eab41df5be595ae9fcd1aa74a062b8`
  - `com.xingqiao.sub2api.source.commit=<current root repository commit>`
- Do not call the update API, change `infra/compose.yaml`, recreate containers, or mutate production business data.
- Build cache cleanup must not use `docker system prune`, `docker image prune`, `docker volume prune`, or `docker buildx prune --all`.
- Preserve at least 3 GiB of BuildKit cache and cap retained cache at 5 GiB.
- Push the completed source branch only after tests, image inspection, production delivery, and readiness checks pass.

### Task 4: Build And Inspect The Linux AMD64 Image

**Files:**

**Interfaces:**

- [ ] **Step 1: Build the image locally**

Run from `upstream/sub2api`:

```bash

  --platform linux/amd64 \
  --load \
  --build-arg VERSION=0.1.166 \
  --build-arg COMMIT=dc893dd0b8eab41df5be595ae9fcd1aa74a062b8 \
  --label com.xingqiao.sub2api.qualified=true \
  --label com.xingqiao.sub2api.upstream.version=0.1.166 \
  --label com.xingqiao.sub2api.upstream.commit=dc893dd0b8eab41df5be595ae9fcd1aa74a062b8 \
  --label com.xingqiao.sub2api.source.commit="$(git rev-parse HEAD)" \
```
