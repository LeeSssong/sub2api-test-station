# ACC01 单个订阅账号真实验收清单

**当前状态：** 未执行；账号未购买  
**默认对象：** 独立 OpenAI ChatGPT Plus 样本  
**安全规则：** 本清单只记录非敏感结果。密码、Token、Cookie、OAuth 凭据、2FA 恢复码和支付信息不得写入 Git、普通文档或聊天。

## 1. 前置条件

- [ ] 用户已自行购买 1 个通过评分的真实候选。
- [ ] 订单金额不超过 CNY 300，订单号只记录脱敏引用。
- [ ] 商品快照、售后条款、购买时间和到期日已保存到受控位置。
- [ ] 当前平台条款和 D12 已复核并允许继续测试。
- [ ] 账号没有共享、组织托管、卖家恢复权或绕过要求。

任一项不满足：停止验收，将候选标记为失败或退换，不导入 Sub2API。

## 2. 控制权接管

- [ ] 买方可独立访问并控制主邮箱。
- [ ] 恢复邮箱或恢复方式已归买方控制。
- [ ] 密码已由买方在正常入口设置或更改。
- [ ] 2FA 已由买方在正常入口设置，恢复码进入密码管理器。
- [ ] 卖家、学校、组织管理员或共享用户不能恢复该账号。
- [ ] 平台显示的产品和档位与商品描述一致。
- [ ] 到期日和剩余天数已记录到资产台账。

## 3. Sub2API 导入

- [ ] 在管理后台选择 `OpenAI -> OAuth`，不使用 Token/Cookie 提取工具。
- [ ] 账号名称设为 `ACC01-openai-plus-sample-01`。
- [ ] 分组使用 `acc01-openai-plus-test`，不加入 UP01 或正式售卖分组。
- [ ] `concurrency = 1`、`rate_multiplier = 1.0`。
- [ ] 填写真实 `expires_at`，开启到期自动暂停。
- [ ] 授权后账号状态、订阅档位和到期信息可读取；没有把凭据写入文档。

## 4. 功能测试

每次测试记录时间、请求 ID、公开模型名、HTTP 状态、首字耗时、总耗时、输入/输出 Token 和账号 ID；不记录提示词正文或认证信息。

- [ ] 非流式请求成功，返回结构与客户端协议一致。
- [ ] 流式请求成功，SSE 结束标记完整，无重复片段。
- [ ] 工具调用请求成功，参数和工具结果往返正确。
- [ ] 长上下文请求成功，未出现无解释截断或计费异常。
- [ ] 请求日志指向 ACC01 测试账号和独立分组。
- [ ] Token、请求数和对外扣费记录可追溯。
- [ ] 第二个并发请求按并发 1 的规则等待或拒绝，没有越限。

## 5. 故障和隔离测试

- [ ] 手工禁用 ACC01 后，新请求不会继续选中该账号。
- [ ] 恢复后只有显式测试请求使用该账号。
- [ ] 429/配额耗尽能进入冷却或不可调度状态，不会形成紧密重试。
- [ ] 流式响应开始后发生错误时，不跨账号自动重试并产生重复内容。
- [ ] ACC01 失败不会影响 UP01 分组。
- [ ] 到期模拟或到期字段检查能触发自动暂停逻辑。

## 6. 24 小时观察和成本

- [ ] 观察至少 24 小时，记录成功请求、失败请求、429、重授权和卖家售后事件。
- [ ] 计算有效可用天数和可用 Token，不使用卖家宣称的理论额度替代实测。
- [ ] 有效单位成本包含购买价、失败浪费、补偿和不可用时间。
- [ ] 有效单位成本低于拟定对外售价，并保留至少 20% 完全成本毛利空间。
- [ ] 账号可独立禁用、替换和追踪，不需要绑定同一卖家的额外库存。

## 7. 结论

- [ ] `accepted`：全部控制权、功能、隔离和成本项通过，可提交 D07 分组与售价建议。
- [ ] `conditional`：只存在可量化的小问题，保持测试分组且不扩池。
- [ ] `rejected`：控制权、正常授权、共享/托管、条款、成本或稳定性任一关键项失败。
