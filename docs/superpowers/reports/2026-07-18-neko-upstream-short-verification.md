## 接口与模型

公开 OpenAI 兼容 Base URL 为 `https://api.999555999.com/v1`。

`GET /v1/models` 返回 HTTP 200，当前共 8 个模型；本次需要的以下模型均存在：

- `gpt-5.6-sol`
- `gpt-5.6-terra`
- `gpt-5.6-luna`

模型目录请求从当前管理端观察约为 1.54 秒。目录可见只证明当时可路由，不代表长期可用或已获商业转售授权。

所有目标模型均通过 `POST /v1/chat/completions` 非流式最小请求并返回 HTTP 200 和预期文本。

| 模型 | 当前管理端端到端耗时 | 站方记录总耗时 | 结果 |

| `gpt-5.6-sol` | 2.29 秒 | 741 毫秒 | 通过 |
| `gpt-5.6-terra` | 2.67 秒 | 1.02 秒 | 通过 |
| `gpt-5.6-luna` | 4.05 秒 | 2.57 秒 | 通过 |

## 计费核对

- 测试共 11 个推理请求、204 个站方计费 Token。
- 站方标准费用合计 `$0.0026`，实际费用逐请求合计约 `$0.000182`，页面四位小数汇总显示 `$0.0002`。
- 实际费用与标准费用之比约为 `0.07x`，与 Pro 池标称倍率一致。
- 前 6 个功能请求的标准费用为 `$0.0016`，实际逐请求费用合计 `$0.000112`，也精确对应 `0.07x`。

API 响应中的 usage Token 与站方计费明细并非每笔完全一致，尤其 `gpt-5.5` 和 `gpt-5.6-sol` 流式样本存在明显差异。后续若接入 Sub2API，必须单独验证“用户扣费所用 Token、上游实际计费 Token、上游实际金额”三者，不能只依赖模型响应中的 usage 字段判断毛利。

## 并发核对

对 `gpt-5.6-sol` 使用相同最小请求：

| 并发 | 总墙钟时间 | 单请求耗时范围 | HTTP 结果 |
|---:|---:|---:|---|
| 2 | 2.39 秒 | 2.38 至 2.39 秒 | 2/2 为 200 |
| 3 | 2.39 秒 | 2.36 至 2.39 秒 | 3/3 为 200 |

总墙钟时间接近单请求最大耗时，证明本次短测至少支持 3 路真实并发，没有出现串行排队。该结果不是供应商 RPM、TPM 或长期并发承诺。

## 当前判断

NekoAPI Pro 池已通过模型、非流式、流式、短请求计费和 3 路并发短测，透明 `0.07x` 成本也已由逐请求账单验证。它可以进入候选池，但尚不能直接成为首版唯一生产上游，原因包括：

1. 可见监控样本时间短，公开可用率约 97.70%，长期稳定性尚未验证。
2. PriceAI 将 Pro 池标记为混合渠道，底层来源和持续性不透明。
3. 站方条款允许调整价格、模型和额度，且未明确授予商业转售权。
4. 尚未从腾讯云首尔生产机和中国大陆三网分别做持续时延、长流和错误率测试。
5. usage Token 与实际计费 Token 的差异尚未在 Sub2API 用户扣费闭环中验证。

因此维持 D03 方案一不变：生产继续只使用 UP01；NekoAPI 作为已通过短测的候选，后续采用隔离账号、小额余额、无用户分组的方式做 24 至 72 小时稳定性和三方计费复测。候选通过前不修改生产路由。
