# Whole-Site Accounting Ledger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a whole-site CNY accounting ledger that uses Sub2API usage logs for customer revenue and resource cost, records only minimal manual cash events, and produces idempotent daily snapshots after a controlled accounting reset.

**Architecture:** Add an `internal/accounting` domain/service package to calculate daily figures from the Sub2API PostgreSQL public schema and persist cash events plus daily snapshots in the existing `relay_ops` schema. A protected Relay Ops accounting page/API supplies the only manual input: a cash event recorded after an account purchase or upstream payment. The scheduler recomputes the previous three Shanghai calendar days after 00:10, so late usage and late event entry converge without duplicate accounting.

**Tech Stack:** Go 1.24, pgx v5/PostgreSQL 18, existing Relay Ops HTTP server and admin-session verifier, server-rendered HTML/CSS/vanilla JavaScript, Ruby shell safety tests.

## Global Constraints

- Report in CNY only: one consumed USD of site balance is one CNY of recognized customer revenue.
- Do not use FX conversion or account-cost amortization.
- Do not create group-level accounting, group-level allocation, or group-level profit output.
- Exclude administrators and configured internal users/API keys from revenue; include their resource consumption in cost.
- Calculate resource cost as `COALESCE(account_stats_cost, total_cost) * COALESCE(account_rate_multiplier, 1)`.
- Use `Asia/Shanghai` calendar days and run daily settlement no earlier than 00:10 local time.
- Keep only six operator-entered cash-event fields: `event_type`, `paid_at`, `amount_cny`, `source_kind`, `account_id`, and optional `notes`.
- Do not store supplier, batch, external reference, group, API key, token, cookie, password, or OAuth credential fields.
- Preserve accounts, groups, API keys, routing, and model-pricing configuration during the accounting-baseline reset.
- Historical usage prior to `ledger_start_date` must never enter an accounting snapshot.
- Every mutation requires an authenticated active Sub2API administrator, origin validation, request-size limits, audit actor capture, and an idempotency key generated by the page.
- Preserve the existing dirty changes in `infra/.env.example`, `infra/compose.yaml`, and `监控日报-2026-07-28.md`; do not stage them.

Implement `ReadUsageTotals` against `public.usage_logs`, `public.users`, and `public.accounts`:

```sql
SELECT
  COALESCE(SUM(ul.actual_cost) FILTER (
    WHERE u.role <> 'admin'
      AND NOT (ul.user_id = ANY($3::BIGINT[]))
      AND NOT (ul.api_key_id = ANY($4::BIGINT[]))
  ), 0) AS external_revenue_cny,
  COUNT(*) FILTER (
    WHERE u.role <> 'admin'
      AND NOT (ul.user_id = ANY($3::BIGINT[]))
      AND NOT (ul.api_key_id = ANY($4::BIGINT[]))
  ) AS external_requests,
  COUNT(*) FILTER (
    WHERE u.role = 'admin'
       OR ul.user_id = ANY($3::BIGINT[])
       OR ul.api_key_id = ANY($4::BIGINT[])
  ) AS internal_requests,
  COALESCE(SUM(
    COALESCE(ul.account_stats_cost, ul.total_cost)
      * COALESCE(ul.account_rate_multiplier, 1)
  ) FILTER (WHERE customer predicate), 0) AS customer_resource_cost_cny,
  COALESCE(SUM(
    COALESCE(ul.account_stats_cost, ul.total_cost)
      * COALESCE(ul.account_rate_multiplier, 1)
  ) FILTER (WHERE internal predicate), 0) AS internal_resource_cost_cny,
  COALESCE(SUM(
    COALESCE(ul.account_stats_cost, ul.total_cost)
      * COALESCE(ul.account_rate_multiplier, 1)
  ) FILTER (WHERE a.type='oauth'), 0) AS owned_oauth_cost_cny,
  COALESCE(SUM(
    COALESCE(ul.account_stats_cost, ul.total_cost)
      * COALESCE(ul.account_rate_multiplier, 1)
  ) FILTER (WHERE a.type='apikey'), 0) AS upstream_apikey_cost_cny
FROM public.usage_logs ul
JOIN public.users u ON u.id=ul.user_id
LEFT JOIN public.accounts a ON a.id=ul.account_id
WHERE ul.created_at >= $1 AND ul.created_at < $2;
```

Use only `[start, end)` UTC boundaries derived from an `Asia/Shanghai` date. Reject `ledger_start_date` windows before activation in the service layer, not by deleting historical rows during ordinary report reads.

```go
func (s Service) RecomputeRecent(ctx context.Context) ([]DailySnapshot, error) {
    yesterday := LocalDay(s.now().In(s.Timezone)).AddDate(0, 0, -1)
    first := yesterday.AddDate(0, 0, -2)
    if first.Before(s.StartDate) {
        first = s.StartDate
    }
    snapshots := make([]DailySnapshot, 0, 3)
    for day := first; !day.After(yesterday); day = day.AddDate(0, 0, 1) {
        snapshot, err := s.RecomputeDate(ctx, day)
        if err != nil {
            return nil, fmt.Errorf("recompute %s: %w", day.Format("2006-01-02"), err)
        }
        snapshots = append(snapshots, snapshot)
    }
    return snapshots, nil
}
```

`RecomputeDate` must read one native usage window and one cash-event window, call `BuildSnapshot`, and upsert exactly one snapshot. It must not delete any Sub2API rows.
