# T132 管理员赠送/扣除额度与用户记录弹窗收敛

## 目标

依据 Figma 原型调整独立测试站管理员用户管理页：将原有管理员 `add/subtract` 操作明确为“赠送/扣除”，并将两者限制在赠送额度域；重构“用户充值和并发变动记录”弹窗，使其展示三类余额摘要并移除不属于该页面的额度流水和支付渠道退款入口。

## 范围

- `UserBalanceModal`：`add` 显示“赠送”，只增加 `gift_quota`；`subtract` 显示“扣除”，只减少 `gift_quota`。
- 扣除弹窗的“全部”只填充当前赠送额度；金额校验不得超过赠送额度。
- 弹窗展示可用额度、充值额度、赠送额度和操作后可用额度。
- `UserBalanceHistoryModal`：保留充值/并发变动记录、类型筛选、赠送/扣除入口和历史摘要。
- 移除额度流水页签及其查询渲染；移除支付渠道退款按钮、订单查询区域及事件。
- 更新中英文管理员用户相关文案为赠送/扣除语义。

## 非目标

- 不删除或改写历史 `user_quota_ledger_entries`、兑换码或支付订单数据。
- 不移除全局管理员订单页中的支付渠道退款能力。
- 不改变充值额度、用户消费扣费、原生钱包计算、后端账务事实源或数据库结构。
- 不新增迁移、配置、外部服务或并行账务源。

## 当前行为与约束

当前 `UserBalanceHistoryModal` 同时包含 legacy 充值/并发记录、quota ledger 页签和支付渠道退款入口；`UserBalanceModal` 已读取额度摘要，但 `add/subtract` 的用户可见文案仍为充值/退款。当前后端余额调整接口继续接收 `add/subtract`，本任务保持接口兼容，只收敛前端语义并确保 `subtract` 以赠送额度为上限。

## 数据与交互契约

1. 打开记录弹窗时读取现有 `getUserQuotaSummary` 和 `getUserBalanceHistory`。
2. 顶部摘要分别展示 `total_quota_balance_usd`、`paid_quota_balance_usd`、`gift_quota_balance_usd`。
3. “赠送”调用现有 `updateBalance(id, amount, 'add', notes)`；“扣除”调用现有 `updateBalance(id, amount, 'subtract', notes)`。
4. 成功后关闭操作弹窗并由父视图刷新用户列表/记录弹窗数据。
5. 额度流水 API 客户端可以保留供其他功能兼容，但本记录弹窗不再调用或渲染该接口。

## 失败与安全语义

- 金额必须大于 0；未加载余额摘要时禁止提交。
- 扣除金额大于赠送额度时禁止提交并显示额度不足提示。
- 任何操作失败继续使用现有脱敏错误提示，不泄露凭据或支付信息。
- 移除页面退款入口不改变后端支付退款接口，也不删除历史退款记录。

## 验收矩阵

- 原 `add` 入口显示“赠送”，弹窗金额字段显示赠送额度语义，提交操作仍为 `add`。
- 原 `subtract` 入口显示“扣除”，弹窗金额字段显示扣除额度语义，提交操作仍为 `subtract`。
- `subtract` 的“全部”填充赠送额度而不是可用额度；超过赠送额度的提交被拒绝。
- 两种弹窗均展示可用、充值、赠送额度，操作后预览使用可用额度计算。
- 记录弹窗无“额度流水”页签、无“支付渠道退款”按钮、无退款订单区域。
- 记录弹窗仍可加载并筛选充值和并发变动记录，赠送/扣除按钮仍可打开对应操作弹窗。
- 中英文文案测试、组件测试、类型检查和前端构建通过。
