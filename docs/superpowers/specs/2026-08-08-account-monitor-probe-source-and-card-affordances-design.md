# Spec: 账号监控统一探测口径与卡片交互增强

## Problem

账号监控卡片当前把真实用户请求窗口和主动监控探测同时投影到同一张卡片，成功率与近期探测柱状图容易被理解为同一口径。账号成本来源、上游账号链接和评分分项也缺少直接可见的解释。

## Goal

让账号监控卡片的主质量指标统一使用主动探测证据，并补充成本来源警示、账号名称上游外链和评分构成悬浮展示。

## Non-goals

- 不改变真实请求日志、用户计费、调度排序或账号健康探测任务本身。
- 不新增数据库表或迁移。
- 不把真实请求数据删除；调用明细继续独立展示，但不再作为卡片主质量证据。
- 不引入 GitHub Actions 或维护停机发布。

## User/System Flow

1. 管理员打开账号监控页。
2. 卡片的成功率、TTFT、总耗时、评分、排名资格和证据来源均由主动探测聚合生成。
3. 真实请求数/失败数只在“调用明细”区域展示。
4. 成本卡片根据倍率来源或采购成本来源显示感叹号及悬浮说明。
5. 有合法 `homepage_url` 时，点击账号名称在新标签页打开上游站点。
6. 鼠标悬停评分区域查看成本、成功率、TTFT、总耗时分项和权重。

## Contract and Data Changes

- 保持 `/admin/accounts/monitor` 路由不变。
- 后端投影中的卡片质量证据改由最新有效主动探测聚合提供；不得回退到真实请求窗口。
- 为评分悬浮展示增加稳定的分项字段（成本、成功率、TTFT、总耗时及权重），分项数值必须与后端总分使用同一公式和取整规则。
- 复用现有 `homepage_url`、`multiplier.source`、`procurement_cost_cny` 和 `estimated_usable_quota_usd` 字段。

## UI States

- 探测成功：显示探测成功率和探测样本数。
- 探测失败/过期/无样本：保留失败事实，主指标显示待确认或不可用，不伪造真实请求成功率。
- 手工成本：成本卡片右上角显示感叹号，悬浮说明手工来源。
- 上游原生成本：不显示警告感叹号，悬浮说明来自上游原生字段。
- 无合法上游网址：账号名称保持普通文本。
- 评分不可计算：悬浮层显示“暂无足够探测证据”。

## Test Strategy

- 后端服务测试：验证窗口内即使真实请求成功，卡片证据仍取主动探测；验证探测失败保留失败事实。
- 前端组件测试：验证成功率口径文案、成本来源图标/悬浮文案、外链属性和评分分项展示。
- 运行相关 Go/Vitest 测试、前端 typecheck/build；不执行无关上游资格或容量门禁。

## Acceptance Criteria

- [ ] 截图场景中卡片成功率不再显示真实请求 100%，而显示主动探测窗口的成功率/状态。
- [ ] 卡片 TTFT、总耗时、评分、排名资格和证据来源均来自主动探测。
- [ ] 真实调用数和失败数仅在调用明细区域出现。
- [ ] 手填倍率或成本右上角有感叹号，悬浮文案说明手工来源；原生字段说明上游来源。
- [ ] 点击有合法主页的账号名称在新标签页打开对应站点。
- [ ] 悬停评分展示四项分数、权重和合计，数值与后端总分一致。
- [ ] 生产蓝绿切换期间 `downtime_required=false`，线上监控 API 与页面验证通过。

## Risks

- 低真实流量账号将更依赖主动探测，需明确显示探测样本不足/过期状态。
- 评分分项若只在前端重算可能与后端取整不一致，因此优先由后端返回分项。
- 生产发布仍必须保留最小相关验证，不能以“无停机”替代健康检查。
