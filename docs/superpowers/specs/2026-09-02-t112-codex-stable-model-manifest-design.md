# T112 Codex 分组级稳定模型目录规格

**日期：** 2026-09-02

**状态：** 已确认，候选工作区实施中；不推送、不部署。

## 背景与原生能力判断

Sub 原生已经有两套相关能力：原生 `/v1/models` 可以合并配置模型映射，真实 OpenAI 请求也会按请求模型筛选账号能力；Codex `/models` 则是独立的实时上游 manifest 透传链路，目前只选一个账号请求上游。因此同一分组内账号上游目录不一致时，Codex 客户端模型选择器会随随机账号漂移。

本任务不新建模型事实源，也不改原生调度语义。它只在现有 `OpenAIGatewayService` 与 `CodexModels` handler 之间补充分组级实时 manifest 聚合层。

## 目标

- 同一 API Key 分组的 Codex `/models` 在账号轮换时返回稳定的模型集合。
- 只展示至少一个持久资格账号真实上游成功返回的模型，不直接信任静态 `model_mapping`。
- 保留 OAuth、API Key、自定义上游、Composite 分组的现有兼容路径。
- 保留现有失败切号、账号认证错误处理、单账号上游缓存和客户端条件请求语义。

## 非目标

- 不修改真实请求的账号选择、模型映射、优先级、配额、重试预算或会话粘性。
- 不把静态 `model_mapping` 转换成 Codex manifest。
- 不跨不同 API Key 分组共享模型目录。
- 不把上游失败账号的旧模型并入新结果，除非该账号仍在分组聚合缓存的可用保留期内。
- 不修改数据库、生产配置、发布链或 GitHub Actions。

## 行为合同

### 1. 聚合范围

对一个分组请求，读取与原生模型能力诊断相同的持久资格账号池：状态为 active、可调度、绑定该分组、平台为 OpenAI；Composite 分组沿用现有 OpenAI Codex 路由。暂不纳入仅由瞬时调度状态排除的账号，因为目录发现需要避免单个账号的临时 429/过载造成目录抖动。

每个候选账号最多请求一次当前分组 manifest。请求参数、认证和 API Key/OAuth/Agent Identity/Composite 兼容行为全部复用 `FetchCodexModelsManifest`。

### 2. 成功与失败

- 至少一个账号成功且 manifest envelope 合法：合并所有成功 manifest 的 `models` 数组，按 `slug` 去重，并保持确定性排序；同 slug 的完整对象优先采用排序后最先出现的成功 manifest，确保结果稳定。
- 某些账号失败：忽略失败账号，使用其他成功账号的并集；失败不覆盖成功结果。
- 所有账号失败：若存在尚未过期的分组聚合缓存，返回缓存；否则返回原生上游错误，不能返回空的伪造目录。
- 没有持久资格账号：保持现有 `No available OpenAI accounts` 语义。
- 客户端取消请求：立即停止等待并不写入聚合缓存。

现有“可重试错误”只用于已有单账号故障处理；聚合请求对每个候选账号独立执行，不扩大永久 4xx 的重试语义，也不因一个账号的永久错误中止其他账号。

### 3. Manifest 形态与 ETag

聚合只改变顶层 `models` 数组，保留第一个成功 manifest 的其他顶层字段。模型对象必须保持上游原始字段；仅去重 slug 和确定性排序。聚合正文使用紧凑 JSON 编码计算服务端 ETag，格式沿用已有 `codexModelsManifestBodyETag`。

客户端 `If-None-Match` 只与聚合正文 ETag 比较；不能直接把任一账号上游 ETag 透传为分组 ETag。单账号 `upstreamETag` 仍只用于单账号缓存向上游做条件请求。

### 4. 缓存与并发

- 缓存键至少包含分组 ID、客户端版本、平台/路由形态以及参与聚合的持久资格账号身份与凭据指纹，防止账号增删、凭据变更或版本协商复用旧目录。
- 聚合缓存沿用现有 fresh TTL、stale TTL、最大条目数和 singleflight 风格，避免多个 Codex 客户端同时刷新造成上游请求风暴。
- fresh 命中直接返回；stale 命中先返回旧聚合结果并异步刷新；miss 由一个请求负责刷新，其余请求共享结果。
- 刷新成功才替换缓存；刷新部分失败但有成功 manifest 时仍替换为成功并集；全失败不覆盖旧缓存。

### 5. 请求路径

`CodexModels` handler 改为调用分组级服务方法，并继续设置服务端聚合 ETag、处理 304 与错误映射。真实 `/responses`、`/chat/completions`、WebSocket 和其他转发路径不变。

## 验收标准

- 两个账号分别返回 `gpt-5.5` 与 `gpt-5.6` 时，连续请求目录均返回两者，不随账号选择漂移。
- 重复 slug 只出现一次，结果字段和排序确定，聚合 ETag 在账号顺序变化时保持一致。
- 一个账号 5xx/超时、另一个成功时返回成功账号目录；所有账号失败且无缓存时返回 502/503，不返回 200 空目录。
- 聚合缓存命中、stale 异步刷新、条件请求 304 均有直接测试。
- OAuth、API Key、自定义 `/models` 转换、Composite 分组和 Agent Identity 既有测试继续通过。
- 仅运行本地直接相关测试、必要构建与 diff 检查；不推送、不部署。
