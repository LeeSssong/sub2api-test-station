# Sub2API 定制外置迁移手册

## 目标与边界

Sub2API 官方核心继续拥有身份、2FA、账号/分组/API Key、路由、实时请求链、原始计费和核心业务表的唯一写入权。`relay-ops-service` 只承载事件消费、监控、盈利、账务、余额/账单/倍率采集、对账、通知和可重建读模型。

外置服务不得直接写 `accounts`、`groups`、`usage_logs` 或其他核心业务表。需要改变核心状态时，只能调用版本化、白名单的窄适配器命令；请求链通过事务 Outbox 异步发出最小事件，不能让实时路由依赖控制面。

## 管理员体验

迁移采用同域双读和 feature flag。管理员仍使用原 Sub2API 域名、账号、2FA、会话、菜单、URL、字段、筛选、排序、分页、刷新和 CSV 导出。外置控制面不可用时，用户请求、原生管理页和核心账号操作继续工作；页面显示“数据暂不可用/最后更新时间”，不伪造余额、利润、成本或对账结果，也不清理主站会话。

每个页面切换前必须完成：旧/新查询双读对比、权限与会话验证、筛选排序分页导出回归、空数据和延迟状态回归、控制面故障降级演练，以及从快照和事件重建读模型的金额/数量核对。

## 分阶段迁移

1. 冻结定制清单和管理员体验黄金样本。
2. 部署核心 Outbox、版本化事件/命令合同和控制面消费器。
3. 以只读双读迁移账号监控、盈利、账务、对账和 CSV。
4. 迁移余额、账单和倍率采集；核心写入仅经受控命令。
5. 保留请求完成、健康变化等最小核心适配器，删除重复业务实现。
6. 连续两个官方候选通过资格矩阵后，关闭旧定制读路径。

每一阶段都必须先在项目总账登记“进行中”。只有“已推送到服务端 + 已部署 + 已验证生效”才能标为“已完成”。

## 数据库门禁

Expand-only 迁移可在非活动槽位和生产克隆中验证后受控应用。涉及删除、重命名、收窄约束、不可逆数据转换或破坏旧版读取的迁移，一律标记 `blocked`，不得进入自动蓝绿通道；需单独备份、恢复演练、人工授权和旧版兼容证明。迁移失败不自动回滚，回退运行时前必须证明旧版仍兼容已应用 schema。

## 验收清单

- 核心请求、路由和计费在控制面停止时仍可用。
- 事件重复、乱序、断点续费和死信均有稳定结果；读模型可重建。
- 控制面 API 仅接受同域管理员会话，401/403 不会导致主站登出。
- 读模型响应含 `generated_at`、`source_watermark`、`freshness_seconds`、`completeness`、`calculation_version`。
- 新旧页面数据、筛选、分页、排序、导出和降级状态一致。
- 生产切换前预检输出 `update_performed:false`、`promotion_performed:false`，并保留 JSON 证据。
