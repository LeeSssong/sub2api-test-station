# 监控当前状态与飞书历史错误码修复设计

## 背景

监控页当前把同一分组的所有探测结果做历史汇总，历史失败会压过最近一次成功；飞书账号健康链路则把滚动窗口内最近一次失败错误码保存在 `LastErrorCode`，成功样本不会清除它，导致历史 `balance_exhausted` 被误当成当前不可用。

## 已确认产品口径

“当前状态”的主证据是**最新一次渠道探测结果**。

## 设计

### 监控页

- 每个分组先按探测时间选取最新一条有效探测。
- 最新探测成功（`operational`）时，分组当前状态为 `operational`，页面展示“正常”。
- 最新探测失败时：若近期仍有成功证据，展示 `degraded`（近期有波动）；若全部最新探测均失败或结果已过期，展示 `unavailable`。
- 无探测或无法确认新鲜度时保留 `unconfigured/insufficient_data`。
- 请求成功率、P95 等指标继续独立展示，不改变其统计口径。

### 飞书账号告警

- 账号可用性以滚动一小时内的最新探测样本为主。
- 最新样本成功时，账号恢复为可用；窗口内更早的 `balance_exhausted` 不得继续让账号不可用。
- 只有最新样本仍为 `balance_exhausted` 时，才将其作为不可用原因。
- 没有窗口样本时继续沿用现有累计投影回退，避免历史读取失败导致容量被错误缩小。
- 告警状态机的去抖/恢复机制保持不变；本修复只纠正当前容量和错误原因的证据选择。

## 不在本次范围

- 不把真实用户请求成功率并入“当前状态”主判据。
- 不修改飞书卡片视觉结构、告警阈值或部署配置。

## 验收标准

1. 最新探测成功、较早探测失败时，监控分组状态为 `operational`。
2. 最新探测失败且近期有成功时，监控分组状态为 `degraded`；连续失败才为 `unavailable`。
3. 账号历史包含 `balance_exhausted`、最新样本成功时，账号为 `healthy`，分组容量不再变为 0。
4. 最新样本仍为 `balance_exhausted` 时，仍按不可用处理并展示余额耗尽原因。
5. 既有无样本、过期样本、日报和告警恢复测试不回归。
