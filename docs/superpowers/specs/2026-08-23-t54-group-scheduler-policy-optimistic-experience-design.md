# T54 分组调度策略与乐观体验卡设计

## 1. 问题证据与当前行为

T52 已在原生 `settings` 和 `SettingsView` 上增加全局高级调度权值、公平调度参数以及 JSON 分组覆盖，但当前交互仍是全局参数加文本 JSON，不能让管理员先选分组，再明确选择“调度权值覆盖”或“公平调度”。公平预设也不会自动回填权值，且权值字段缺少面向业务角色的约束。

Monitor V2 当前分组指标来自原生账号试用探测投影，而不是分组真实请求指标。可调度账号按分组建立 scope，查询再按 `account_id` 连接 `account_monitor_results`；同一账号属于多个分组时，探测结果会被投影到多个分组。Pro 指标在某些窗口偏差，可能来自可调度账号数量、探测新鲜度、探测模型/凭据或样本构成，而不是 Pro 客户真实体验。

## 2. 目标

- 为每个分组提供独立调度策略配置。
- 每个分组在“调度权值覆盖”和“公平调度”之间二选一。
- 公平调度提供特惠、均衡、Pro 三个业务预设；选择预设时自动回填对应调度权值和公平参数。
- 自定义权值字段具有服务端和前端一致的上限、下限及有限数校验。
- 公平模式避免长期冷落合格账号，同时保留现有 S1/S2 资格、并发、故障域、sticky 和安全重放边界。
- 分组体验卡只展示成功样本形成的乐观主指标：可用性、首字速度、平均耗时及时间线；页面不展示探测样本数、失败数、失败原因或其他探测旁证。
- 继续保留原生主动探测作为后台调度资格、健康判定和评分输入，不改变其数据源或写入事实。

## 3. 非目标

- 不把试用探测改造成真实客户流量统计。
- 不新增第二套计费、账务、错误或质量事实源。
- 不修改 S1/S2 的硬预算、错误分类、重试安全边界或流式输出后的禁止重放规则。
- 不在本任务中修复所有真实生产事件缺失；Pro/Plus 事件缺失只补充必要的分组归属/查询合同测试和只读诊断，不新增事件表。
- 不引入无条件 round-robin、并行竞速、shadow 请求或新的上游请求类型。

## 4. 方案比较与选择

### 方案 A：继续全局参数加 JSON 分组覆盖

变更最少，但管理员难以理解和维护，无法表达策略二选一和业务预设，长期冷落问题也只能靠手工填 JSON。放弃。

### 方案 B：分组策略对象复用现有 settings，页面提供模式、预设和受限编辑

沿用 `GET/PUT /api/v1/admin/settings`、现有公平调度解析和分组 ID 覆盖；新增策略模式与预设字段，页面把 JSON 编辑替换为分组选择器、模式分段控件和受限表单。公平模式仍消费现有候选池探索，增加最长闲置优先和最低探索机会约束。无新表、无新事实源、可回滚。采用。

### 方案 C：为每组建立独立调度器和持久化状态表

可表达能力强，但会复制原生调度资格、错误、账务和健康状态，增加迁移、并发和回滚风险，违反原生优先边界。放弃。

## 5. 产品策略

### 5.1 分组策略模式

管理员先选择分组，再选择模式：

- `调度权值覆盖`：显示受限的权值表单，管理员可自定义；公平参数不参与该组运行。
- `公平调度`：显示预设选择器；预设自动填充权值和公平参数，权值作为只读解释值展示。

每个分组只能有一个有效模式。未配置分组继续继承全局兼容默认值。

### 5.2 预设

- **特惠**：连续性优先，在通过 S1/S2 和并发资格的候选中提高成本/利润权重，允许更高延迟，公平探索保持较低但不为零。
- **均衡**：稳定性、首字延迟、总耗时和利润均衡，使用中等探索比例。
- **Pro**：先满足稳定性和低首字延迟门槛，再在健康候选中提高利润权重；公平探索和最长闲置保护高于特惠，避免少数账号长期独占。

预设的具体数值必须在实现计划中以现有权值键和运行时范围表固定，并由后端单元测试锁定。预设不直接修改价格、倍率或账务。

### 5.3 乐观体验卡

主卡仅展示成功样本形成的体验值：可用性、首字速度、平均耗时和成功时间线。不得展示探测样本数、失败数、失败原因、探测来源标签、失败状态或常驻诊断说明。失败探测仍可影响后台资格和调度，但不能在该卡片中以旁证形式出现。

## 6. 数据与控制流

1. 请求进入原生网关，先解析目标 `group_id`。
2. 调度器读取全局设置并按 `group_id` 解析有效策略对象。
3. S1/S2、模型能力、并发、故障域、余额/资格和当前请求排除仍先执行。
4. 权值覆盖模式沿用现有评分和 Top-K；仅使用该分组的权值。
5. 公平模式在合格候选中执行：
   - 超过最长闲置阈值的账号优先获得探索机会；
   - 未达到阈值时按探索比例抽取最久未使用账号；
   - 探索候选仍经过最终资格、并发和抢槽检查；
   - sticky、previous response、强制重试和半开探测保持现有顺序与语义；
   - 候选池按目标分组隔离；第一版继续复用原生账号级 `LastUsedAt` 信号，不新增 per-group 使用状态表，因此公平机会是“按组候选池计算、按账号最近使用时间排序”，不是跨副本精确的每组配额。
6. 主卡继续读取原生 Monitor V2 成功投影，但仅投影乐观体验字段；后台探测写入和调度资格不变。

## 7. 接口与字段契约

继续使用 `GET/PUT /api/v1/admin/settings`。在现有分组覆盖对象上增加：

- `mode`: `weighted_override | fair`
- `preset`: `special_offer | balanced | pro` when `mode=fair`; `custom` is represented by `mode=weighted_override`
- `weight_overrides`: 现有调度权值字段的受限对象
- `fairness`: 现有候选池、公平比例、最长闲置阈值、公平权重字段

兼容规则：旧客户端省略新字段时保留旧配置；旧 JSON 覆盖可读入并按 `weighted_override` 兼容解释。非法模式、预设、字段、超限值、NaN/Infinity 或未知分组 ID 更新必须返回 400，并保持旧配置不变。保存成功后沿用现有 settings cache 失效，目标生效延迟不超过 5 秒。

## 8. 失败与安全语义

- 配置解析失败 fail-closed，保留上一份有效配置。
- 公平策略不能绕过任何 S1/S2 veto、模型能力、并发、故障域、余额或当前请求排除。
- 不因公平探索重放已输出或有副作用请求。
- 没有合格候选时沿用原生耗尽和错误语义，不伪造成功。
- 乐观卡片只改变展示投影，不修改调度资格、账务、错误记录或原生探测结果。

## 9. 兼容性与迁移

不新增数据库表、列或迁移；复用 settings JSON。旧全局配置和旧分组覆盖继续生效。现有 Monitor V2 API 保持字段兼容，只删除前端主卡对探测样本/失败旁证字段的展示依赖，不删除后台响应字段，避免影响其他管理员诊断入口。

## 10. 验收矩阵

| 场景 | 预期 |
|---|---|
| 选择特惠分组 + 权值覆盖 | 只显示并保存该组权值，公平参数不参与 |
| 选择 Pro 分组 + 公平调度 + Pro 预设 | 自动填充 Pro 权值、公平比例和闲置阈值，保存后按组生效 |
| 选择不同分组 | A 组修改不影响 B 组；未配置字段继承全局 |
| 输入超限、NaN、Infinity 或非法 JSON | 返回 400，旧配置保持不变 |
| 长时间未使用的合格账号 | 公平模式在阈值内获得探索机会，仍经过最终资格检查 |
| sticky、强制重试、半开探测 | 行为保持既有语义，不被公平探索抢占 |
| Pro/Plus 真实事件缺失 | 不伪造事件；查询按真实 `group_id` 和配置过滤 |
| 乐观体验卡 | 只显示可用性、首字、平均耗时和成功时间线；不显示探测样本数、失败数、失败原因、失败状态或探测旁证 |
| 旧客户端保存设置 | 新字段不被清空，旧配置继续生效 |

## 11. 测试策略

- Go：策略模式解析、预设展开、范围校验、旧 JSON 兼容、按组解析、最长闲置探索、最低探索机会、sticky/S1/S2 不绕过、非法更新保留旧值。
- 前端：先选分组、模式二选一、预设自动回填、字段禁用/只读、超限校验、旧 payload 回显、乐观卡片不渲染探测旁证、移动端无横向溢出。
- 直接门禁：相关 Go/Vitest、`go build ./cmd/server`、`pnpm typecheck`、`pnpm build`、`git diff --check`。

## 12. 发布、回滚与线上验证

- 无迁移、无生产数据回填，预期 `downtime_required=false`。
- 发布后读取管理员 settings API，验证三个分组策略、预设展开和旧配置兼容；读取 Monitor V2 页面确认主卡只保留乐观体验字段。
- 只读核对 Pro/Plus 的真实 `usage_logs`、`ops_error_logs` 分组归属，不为了制造样本写入生产数据。
- 回滚优先清空分组策略或恢复旧全局/JSON 覆盖；二进制回滚沿用上一已验证蓝绿镜像。

## 13. 待决事项与批准记录

- 预设具体数值必须在实现计划中固定，并以现有运行时权值范围和当前生产默认值为基线；实现计划必须明确每个预设的权值、探索比例和闲置阈值。
- 该规格已根据用户确认删除“探测样本数、失败数、失败原因”展示；探测仅保留后台资格和健康判定用途。
