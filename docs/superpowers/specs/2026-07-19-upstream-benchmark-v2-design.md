# 上游接入评测 V2 设计规格

**日期：** 2026-07-19  
**状态：** 已获用户确认，待规格审阅后实施  
**目标：** 将现有上游评测 V1 升级为“发现模型、逐项验证、取证定价、计算倍率、汇报决策、获批后配置并回验”的可重复工作流。

## 1. 范围与边界

V2 覆盖 OpenAI 兼容上游的文本模型接入评测。它发现并分类全部模型，但首版只对文本模型自动验收；图片、音频、Realtime 和未知模型只记录分类与未覆盖原因，不套用文本计费或测试结论。

V2 生成报告和 Sub2API 配置草案，但评测阶段不写生产配置、不切换生产流量、不删除现有生产账号、不充值付款。只有用户明确采纳指定报告和配置草案后，Skill 才能执行对应的 Sub2API 配置操作。

上游凭据不从聊天输入。用户在已登录供应商页面创建临时 Key，Skill 通过供应商或 Sub2API 页面完成隔离配置；Key 不进入聊天、文件、命令参数、台账或报告。

## 2. 组成

V2 保留现有项目 CLI 与 `benchmark-upstream-channel` Skill 的分层：

- **项目 CLI：** 执行确定性模型测试、容量阶梯、计费计算、证据台账、价格建议和配置草案生成。
- **Skill：** 引导供应商页面取证、创建日期隔离的 Sub2API 账号/分组/用户/Key、汇报结果、等待用户采纳、应用配置、回验和清理。
- **追加式台账：** 每次运行、价格证据和决策都追加记录；纠错使用 `supersedes`，不覆盖旧记录。

现有 V1 命令和记录格式保持兼容。V2 新增能力应通过版本化 profile 和新增字段实现，不破坏已存在的 Neko/Aliu 历史记录。

## 3. 输入与证据

### 3.1 自动发现

- Base URL 和协议类型。
- `/models` 返回的完整模型目录。
- 模型可用状态和名称。
- 是否支持 OpenAI 兼容文本端点。
- 模型分类：`text`、`image`、`audio`、`realtime`、`unknown`。

### 3.2 浏览器取证

供应商已登录页面用于核对：

- 每个模型的输入、输出、缓存读取、缓存写入价格。
- 币种、计费单位和价格生效时间。
- 上游标准费用、实际费用、账单 Token。
- 供应商公布或页面显示的并发、RPM、TPM、套餐和限额。
- 价格调整、退款、容量和再分发条款状态。

若价格或账单信息无法取得，字段必须为 `unknown`；V2 不从其他模型猜测价格，也不把广告倍率当作实测倍率。

### 3.3 运营参数

默认参数如下，均可在运行 profile 或定价场景中覆盖：

```text
异常准备率：10%
目标完全成本毛利率：50%
支付费率：0%，除非提供真实费率
内测用户组倍率：1.0
商业建议倍率：由成本和运营参数计算
```

## 4. 文本模型测试

对每个被分类为文本的模型执行最低闭环：

1. 一次最小非流式请求。
2. 一次 SSE 请求，必须确认正常结束事件（如 `[DONE]`）。
3. 记录 HTTP 状态、错误类别、Token、TTFT、总耗时和响应结构。

V2 不把只通过模型目录探测、只通过非流式或只通过代表模型测试的结果标记为 `verified`。

## 5. 容量探测

默认并发阶梯：

```text
1 → 2 → 3 → 5 → 8 → 10
```

默认 RPM 阶梯：

```text
6 → 12 → 20 → 30
```

容量探测优先使用成本低、输出短的文本请求。任一级出现 429、5xx、超时、协议错误或明显排队，立即停止继续升阶，并记录最后稳定档位。最高档通过时，结论只能是“至少支持该档位”，不能声称已测出供应商绝对上限。

建议配置为最后稳定档位的 70% 至 80%，向下取整且不低于 1。并发与 RPM 是独立指标；未测出的 TPM、队列深度和长期容量必须保持 `unknown`。

## 6. 定价与倍率

### 6.1 模型价格

对每个可开放模型生成四类 Sub2API 价格字段：

```text
input_price
output_price
cache_read_price
cache_write_price
```

公开价格或供应商账单缺失的字段保持 `unknown`。若预计用量大于 0 而价格未知，该模型不能进入可开放列表。

默认计费映射为：

```text
billing_model_source = requested
restrict_models = true
public_name → upstream_name
```

### 6.2 成本倍率

对每个模型计算：

```text
实测成本倍率 = 上游实际扣费 ÷ 上游标准费用
```

当多个模型存在有效样本时，账号建议成本倍率取保守值，并同时保留逐模型倍率和样本精度说明。只有实际费用和标准费用能够解释时，才允许标记为 `verified`。

### 6.3 用户组倍率

V2 同时生成两套方案：

- **内测方案：** 用户组倍率固定为 `1.0`，用于免费签到和服务稳定性测试。
- **商业方案：** 根据成本倍率、异常准备、支付费率、固定成本分摊和 50% 目标完全成本毛利率计算。

变量成本的理论最低倍率为：

```text
风险后成本倍率 = 实测成本倍率 × (1 + 异常准备率)
最低商业倍率 = 风险后成本倍率 ÷ (1 - 支付费率 - 目标完全成本毛利率)
```

最终还要用预计用量分摊服务器、域名、监控等固定成本，输出理论最低、支付后最低、含固定成本最低和推荐商业倍率。推荐值按配置步长向上取整。

Neko 示例：

```text
实测成本倍率：0.07
风险后成本倍率：0.077
50% 毛利理论最低倍率：0.154
支付费率 3% 时最低倍率：约 0.164
建议首发商业倍率：0.18
内测倍率：1.0
```

## 7. 结果状态与产物

模型和渠道状态使用：

- `verified`：模型、同步、SSE、价格和计费证据完整。
- `partial`：技术通过但价格、账单、网络或条款有缺失。
- `blocked`：认证、TLS、模型、SSE、计费或清理出现硬阻断。
- `unknown`：尚未测试，不推断通过。

每次 V2 运行生成不含凭据的：

```text
<channel>-benchmark-<timestamp>.json
<channel>-benchmark-<timestamp>.md
<channel>-sub2api-proposal-<timestamp>.yaml
```

配置草案包含模型白名单、模型映射、四类 Token 单价、计费来源、账号成本倍率、建议并发、建议 RPM、内测倍率、商业倍率和证据引用。

## 8. Skill 决策与执行闭环

Skill 的交互顺序：

```text
创建临时上游 Key
→ 运行 V2 评测
→ 取得价格和账单证据
→ 生成报告与配置草案
→ 向用户总结事实、建议和未知项
→ 明确询问是否采纳指定 proposal
→ 用户明确回复“采纳”
→ 保存当前 Sub2API 配置快照
→ 先应用隔离配置并做最小验证
→ 应用已批准的生产配置
→ 执行同步、SSE、计费、健康和路由回验
→ 汇报结果并清理临时资源
```

批准记录绑定 `channel_id`、`report_id`、`proposal_id`、`proposal_hash` 和批准时间，防止误应用旧报告。用户未采纳前，生产配置必须保持不变。

配置失败时尝试恢复快照；恢复失败只告警并停止后续写操作，不自动重试可能造成重启循环或重复变更的动作。

价格、模型、倍率、并发和 RPM 可以在用户采纳后自动应用。充值、付款、删除现有生产账号、永久关闭旧上游和无法回滚的外部条款操作仍不自动执行。

## 9. 清理与安全

- 测试 Key 由用户在供应商页面创建，完成后停用或删除。
- 删除临时 Sub2API Key、测试用户、隔离分组和隔离账号。
- 生产账号、生产用户和历史台账不删除。
- Key、Cookie、密码、TOTP、完整提示词和完整模型输出不进入聊天、文件、命令参数、日志、Git 或报告。
- 清理不完整时，报告状态保持 `partial`，不能宣称测试完成。

## 10. 验收标准

- V2 CLI 能发现并分类完整模型目录。
- 每个文本模型都有独立同步和 SSE 结果。
- 并发/RPM 阶梯按停止条件工作，未测指标保持未知。
- 价格字段、成本倍率和 50% 毛利计算可复算。
- 缺失价格或无法解释计费的模型不会进入可开放列表。
- 报告、配置草案、台账和审批引用可追溯且无敏感值。
- Skill 能从浏览器取证、隔离测试、总结汇报到采纳后配置形成完整闭环。
- 用户未采纳时生产配置不变。
- 用户采纳后有配置快照、回验、失败恢复和清理证据。
- V1 既有测试和历史记录继续通过验证。
