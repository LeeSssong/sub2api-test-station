# 账号卡片成本倒挂预警实施计划

## 目标

在管理员账号监控卡片上接入通用的上游原生倍率、成本证据和当前分组成本倒挂状态；兼容 Sub2API 与 New API；不新增经营看板，不改变用户计费，不新增或迁移现有金额型投入产出区。

## 实施任务

1. **成本证据数据模型与迁移**
   - 在 `upstream_cost_attempts` 保存本站模型标准费用 `site_standard_cost`。
   - 从 Sub2API usage log importer 写入本站标准费用，保留现有用户实际扣费字段。
   - 为新字段增加可重复执行的数据库迁移、模型字段、序列化和 repository 测试。
   - 有效样本必须能关联本站请求、上游账单交易和正数本站标准费用。

2. **成本守卫聚合服务与管理员 API**
   - 按账号、模型聚合已确认的上游实际扣费与本站标准费用，计算成本折合本站倍率。
   - 按当前分组倍率计算 `loss_confirmed`、`loss_observing`、`pricing_risk`、`zero_margin`、`cost_covered`、`insufficient_samples`、`unknown`。
   - 至少 6 笔有效逐笔实际扣费样本才允许 `loss_confirmed`；分组倍率变化后使用保留样本即时重算。
   - 提供账号监控分组投影所需的 `cost_guard` 对象，返回当前分组倍率、触发模型、样本数、来源、差额和证据时间，不返回金额账单明细。
   - 增加服务层、HTTP handler 和 API 契约测试。

3. **上游原生倍率接入**
   - Sub2API 使用已有 billing/effective multiplier 投影。
   - New API 统一使用本站账号到上游分组的映射，从 `/api/pricing` 的 `group_ratio` 读取实时倍率；不得硬编码供应商、账号或倍率。
   - 原生倍率优先于主动额度测算；映射缺失、接口失败或无对应分组时返回 `null` 与待确认来源。
   - 增加 resolver 与账号监控投影测试，覆盖多个账号和多个映射分组。

4. **账号监控后端投影和前端 API**
   - 将 `cost_guard` 加入 Sub2API account monitor 类型、relay-ops 投影类型及 API 响应。
   - View 在当前分组请求中加载对应成本守卫投影，并按账号传递给卡片。
   - 保持已有 operations 投入产出数据链路和金额区块不变。

5. **账号卡片展示和倒挂强提醒**
   - 增加“上游原生倍率、倍率来源、成本折合本站倍率、成本来源、当前分组倍率、成本状态”。
   - 展示触发模型、有效样本数、证据更新时间等轻量辅助信息。
   - `loss_confirmed` 使用红色“成本倒挂”告警条；其他状态使用对应低强度提示，不把成本状态伪装成服务状态。
   - 增加组件测试，覆盖确认亏损、观察中、可能亏损、待确认和成本覆盖。

6. **验证、合并和部署**
   - 执行 relay-ops Go 测试、Sub2API 后端测试、前端单测/类型检查/构建。
   - 在本 worktree 提交实现；获取并合并 `main` 最新内容，解决冲突并重新验证。
   - 合并回主工作区 `main`，保留其他线程未提交文件；清理本 worktree 和分支。
   - 按现有蓝绿发布 runbook 推送、部署，验证健康接口、账号监控 API 和管理员页面字段/红色告警。
   - 只有“已推送到服务端 + 已部署 + 已验证生效”后，才将项目进度标记为已完成。
