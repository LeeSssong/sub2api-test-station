# T117 飞书余额卡片静默按钮与 T114 调度排名对齐规格

**日期：** 2026-09-02

**状态：** 待用户审阅批准

**任务包：** T117

**范围：** 飞书上游余额告警卡片、现有互动静默回调能力，以及卡片内账号分组排名的数据来源

## 1. 用户问题与结论

用户反馈的卡片存在两个问题：

1. 此前设计的“静默 1 小时”等按钮没有显示。
2. 卡片中的账号排名应使用 T114 已实现的调度排名，并随 T114 的五分钟质量快照周期更新。

代码核对后的结论如下：

- `RenderUpstreamBalanceCard` 已实现“静默 1 小时 / 6 小时 / 24 小时”三个按钮。
- 按钮仅在卡片输入包含一次性 `SilenceToken` 时渲染。
- `SilenceToken` 只有在飞书回调密钥成功从受保护文件加载、静默 repository 完成接线后才生成。
- 因此截图中的无按钮卡片不是布局遮挡或模板删除，而是生成卡片时互动回调能力未启用，模板按现有安全规则省略了按钮。
- 当前卡片排名通过 `AccountMonitorService.ListWindow("24h")` 间接读取各分组的 `SchedulerRank`。虽然它已比旧质量排名更接近真实调度，但接口入口仍带有“24h 监控页”语义，没有明确保证卡片读取的是 T114 `1h + 24h + 7d` 综合质量调度快照。

本规格恢复按钮的可用部署合同，并将卡片排名显式绑定到 T114 调度投影，不创建第二套排名算法。

## 2. 原生能力核对

本任务必须复用以下现有能力：

- 飞书余额事件账本 `ops_alert_events` 的 generation、lease、CAS、失败退避与去重。
- T98-R3 已实现的 `silenced_until`、一次性 action token 摘要、飞书回调鉴权和三个固定静默时长。
- T114 已实现的 OpenAI 账号质量事实源、`1h + 24h + 7d` 综合质量分、五分钟 PostgreSQL 刷新节流、原生资格门禁、利润分区、实时负载和调度投影。
- 现有 BaseURL 余额聚合、余额新鲜度、凭据指纹和发送前复核。

不得新增平行静默表、平行排名表、单独的飞书排名 SQL 或第二套调度公式。

## 3. 目标

1. 余额告警卡片在互动回调能力完整可用时稳定显示：
   - 静默 1 小时
   - 静默 6 小时
   - 静默 24 小时
2. 点击按钮后只静默当前规范化 BaseURL 的活动余额事件，保持现有鉴权、幂等和过期语义。
3. 卡片中每个关联账号的分组排名读取与实际选号相同的 T114 调度投影。
4. T114 质量底座最多每五分钟刷新一次 PostgreSQL；新告警或重复提醒使用发送时可获得的最新快照。
5. 已经发送的历史卡片不回写、不轮询更新，保留发送时证据。
6. 排名或互动回调异常不得阻断余额不足告警本身。
7. 卡片明确显示排名快照时间和排名来源，避免把旧监控分数误认为当前调度顺序。

## 4. 非目标

- 不每五分钟修改已经发送的飞书卡片。
- 不创建常驻卡片更新任务或新的飞书消息生命周期。
- 不改变余额阈值、聚合 BaseURL、告警重复周期、余额事实源或凭据新鲜度规则。
- 不改变 T114 的评分公式、窗口权重、样本置信度、慢首输出规则、资格门禁或调度选择。
- 不修改账号分组、账号状态、优先级、价格、倍率、账务或生产业务数据。
- 不把排名失败解释为余额恢复，也不因排名失败延迟告警。
- 不新增数据库迁移；T98-R3 已有静默字段继续使用。
- 不使用 GitHub Actions。

## 5. 方案比较

### 5.1 仅把当前 `ListWindow("24h")` 改成其他窗口

实现最少，但窗口参数仍属于账号监控页面语义，无法锁定 T114 多窗口质量快照和实际调度投影的一致性。不采用。

### 5.2 每五分钟回写所有已发送卡片

视觉上始终显示最新排名，但需要保存消息 ID、创建持续更新任务、处理卡片已删除/过期/限流，并会抹掉告警发送时的历史证据，明显扩大飞书投递链路。不采用。

### 5.3 复用 T114 调度投影，发送时读取最新快照

新增一个只读、窄接口，直接返回 T114 调度排名快照；新告警和重复提醒在发送前读取一次，历史卡片不变。排名与调度一致，改动范围小，审计语义清楚。采用。

## 6. 端到端控制流

```text
余额刷新与有效性校验
→ 按规范化 BaseURL 聚合活动 API Key 账号
→ 读取 T114 最近可用质量快照
→ 对每个账号所在分组生成只读调度投影
→ 余额事件 Evaluate / Claim
→ 发送前再次核对余额、凭据指纹和事件 generation
→ 生成一次性 SilenceToken（互动能力可用时）
→ 渲染卡片：余额 + 账号明细 + T114 调度排名 + 静默按钮
→ 飞书发送并确认 delivery
```

按钮点击流保持现有设计：

```text
飞书卡片回调
→ 校验回调 token
→ 校验操作者 OpenID
→ 校验一次性 action token 摘要
→ 校验 1h / 6h / 24h
→ 原子更新当前 BaseURL 活动事件 silenced_until
→ 清除投递 lease，并把 next_attempt_at 推迟到静默截止时间
```

## 7. 排名事实源与刷新语义

### 7.1 唯一事实源

飞书卡片不得自行计算排名。唯一来源为 T114 调度器的只读 projection：

```text
原生账号资格
→ 模型/协议能力
→ 状态、余额、冷却、并发槽
→ 原生利润保护分区
→ T114 综合质量分
→ success_score
→ P50 TTFT
→ account_id
```

卡片使用 projection 返回的 `Rank`，不使用旧 `quality_rank`、`group_rank`、账号 priority 或监控权重重新排序。

### 7.2 五分钟语义

- T114 质量 provider 继续维持现有一分钟 freshness TTL 与五分钟 PostgreSQL refresh throttle。
- 本任务不新增第二个 ticker，也不强制每次发送扫描 PostgreSQL。
- 每次新告警或重复提醒在发送前读取当前 provider 快照，并基于当前原生资格和短 TTL 实时负载生成 projection。
- 同一次卡片生成过程固定使用一个 `snapshot_at`，所有账号排名必须来自同一代快照。
- 历史卡片不更新。用户已于 2026-09-02 明确确认该语义。

### 7.3 分组语义

- 一个账号属于多个分组时，逐组显示排名。
- 排名分母只包含该分组在同一投影时点的合格候选。
- 卡片账号顺序按其最佳有效分组排名升序，再按账号 ID 升序。
- 不合格账号仍可作为同 BaseURL 的余额关联账号显示，但对应分组显示“当前不可调度”，不得伪造名次。
- 分组未启用 T114 统一质量调度时，显示“未启用 T114 排名”，不得用旧监控排名冒充。

## 8. 接口与字段契约

在 service 层增加或提取窄的只读合同，概念结构如下：

```text
ReadT114SchedulerRankingSnapshot(ctx, accountIDs)
  snapshot_at
  stale
  groups[]
    group_id
    group_name
    t114_enabled
    candidates[]
      account_id
      eligible
      rank
      rank_total
      quality_score
      reason_code
```

具体 Go 命名可在实施计划中遵循现有代码风格，但语义不得退回 `ListWindow("24h")`。

飞书 card input 增量字段：

```text
RankingSnapshotAt
RankingStale
Ranks[].RankTotal
Ranks[].Eligible
Ranks[].T114Enabled
Ranks[].ReasonCode
```

卡片展示合同：

- 正常：`GPT-Pro：第 3 / 12 名`
- 当前不合格：`GPT-Pro：当前不可调度`
- 非 T114 分组：`GPT-Pro：未启用 T114 排名`
- 冷启动无快照：`GPT-Pro：排名暂不可用`
- 使用旧快照：顶部追加 `排名快照延迟 · YYYY-MM-DD HH:mm:ss`
- 正常快照：顶部显示 `T114 调度排名 · YYYY-MM-DD HH:mm:ss`

不得在卡片中展示质量明细、内部 reason code、凭据指纹或其他调度敏感实现细节。

## 9. 静默按钮启用合同

### 9.1 必要条件

只有同时满足以下条件才生成 `SilenceToken`：

1. `SUB2API_UPSTREAM_BALANCE_FEISHU_CALLBACK_TOKEN_FILE` 指向存在的常规文件。
2. 文件权限为 `0600`，父目录权限为 `0700`。
3. 文件内容非空且通过现有受保护文件加载器。
4. 静默 repository 和飞书回调 route 已完成接线。
5. 当前事件 claim 成功并生成一次性 action token。

### 9.2 失败语义

- 任一条件不满足时，不渲染按钮，避免生成无法验证或无法执行的动作。
- 余额告警正文继续发送，不因按钮不可用而丢失告警。
- worker 必须输出结构化告警，明确 `feishu_silence_actions=disabled` 及非敏感原因码。
- 不得记录回调 token、action token、登录密码或 API Key。
- 发布验收只有在真实新卡片包含三个按钮且回调验证通过后，才可宣称按钮恢复完成。

## 10. 失败与安全语义

| 场景 | 行为 |
|---|---|
| T114 快照新鲜 | 使用当前快照排名 |
| T114 刷新失败但有旧快照 | 使用旧快照，标记“排名快照延迟” |
| T114 冷启动且无快照 | 余额卡片照常发送，排名显示“暂不可用” |
| 单个分组 projection 失败 | 仅该分组显示“暂不可用”，其他分组继续 |
| 回调密钥缺失或权限错误 | 不显示按钮，卡片照常发送并记录非敏感告警 |
| action token 无效/过期 | 回调拒绝，不改变事件 |
| 非接收人点击 | 回调拒绝，不改变事件 |
| 重复点击 | 保持幂等，返回“已处理或告警已失效” |
| 静默期间余额恢复 | 现有 Resolve 结束事件，静默自然失效 |
| 静默到期仍余额不足 | 下一次到期提醒读取新的 T114 快照并生成新 token |

排名读取和卡片渲染必须保持只读，不获取账号槽、不创建 sticky、不修改冷却、不触发上游请求。

## 11. 兼容性与迁移

- 不新增数据库迁移。
- 继续兼容没有回调密钥的环境：告警可发送，但无按钮，并带结构化运维告警。
- 旧卡片不回写；旧 action token 按其原事件状态自然失效。
- 不改变飞书 webhook、余额事件表或现有回调 payload 的字段语义。
- 排名字段只做进程内 service/card input 增量，不新增对外管理员 API。若实施发现必须增加外部 API，停止实施并退回规格审查。

## 12. 场景化验收矩阵

| 场景 | 预期 |
|---|---|
| 互动配置完整的新余额告警 | 卡片显示 1h/6h/24h 三个按钮 |
| 点击“静默 1 小时” | 当前 BaseURL 事件一小时内不再 claim；其他 BaseURL 不受影响 |
| T114 快照排名为 9 | 对应分组显示 `第 9 / N 名`，与同快照 scheduler projection 一致 |
| 五分钟后排名变化并产生重复提醒 | 新提醒显示新排名；旧卡片保持原排名 |
| 同一 BaseURL 关联多个账号 | 全部有效关联账号出现，并按最佳 T114 排名排序 |
| 一个账号属于多个分组 | 逐组显示各自排名，不混用全站质量顺序 |
| 账号冷却或余额 veto | 显示“当前不可调度”，不保留旧名次 |
| T114 刷新失败 | 告警仍发送；使用旧快照并显示延迟，或无快照时显示暂不可用 |
| 回调密钥未配置 | 卡片无按钮、告警正文仍发送、worker 有结构化告警 |
| 无效 token/非接收人/错误时长 | HTTP 拒绝且事件不变 |

## 13. 测试策略

直接相关测试至少覆盖：

1. service：卡片排名不再通过 `ListWindow("24h")` 获取。
2. service：同一 T114 snapshot 生成各组 projection，并保留 snapshot time/stale 状态。
3. service：资格、冷却、余额 veto、无快照、旧快照和单组失败语义。
4. notify：三个按钮条件渲染、排名总数、不可调度、非 T114、延迟和暂不可用文案。
5. repository/handler：1h/6h/24h 静默、action token 摘要、操作者鉴权、幂等和过期。
6. wiring/config：受保护回调文件存在时启用按钮；缺失、`0644`、父目录非 `0700` 时禁用并告警。
7. 回归：余额告警在排名或静默能力失败时仍可 claim、渲染和发送。
8. 必要 `go build ./cmd/server`、gofmt 和 `git diff --check`。

不发送真实飞书消息，不制造生产余额异常，不修改生产账号或业务数据。

## 14. 发布、线上验证与回滚

- 实施候选必须从届时最新、干净且已推送的 `main` 创建独立 worktree。
- 候选只在直接相关测试通过后进入 `READY_FOR_ROOT_REVIEW`。
- 发布只能从干净且 `HEAD == origin/main` commit/tree 的根 `main` 发起。
- 本规格预计无迁移；最终 `downtime_required` 以根发布预检为准。
- 主站发布仍需要满足项目定义的明确授权；本规格和用户对规格的批准不构成部署授权。
- 线上验证必须使用真实新生成的测试告警卡片或受控测试事件，确认三个按钮、一次有效 1h 回调、错误身份拒绝，以及卡片名次与同一 snapshot 的 T114 projection 一致。
- 不为验收制造真实上游余额耗尽或修改生产账号余额。
- 回滚使用上一已验证蓝绿槽/镜像；配置层可移除回调密钥以立即回到“告警有正文、无按钮”的安全降级状态。
