## 根因

统一质量调度已经接入普通 HTTP Responses、Chat Completions 和 Embeddings，并按成功率、TTFT、实时成本和账号 ID 排序。缺陷位于质量快照事实源：`ListOpenAIAccountQuality` 只读取 `usage_logs`，而账号已选中后的大量 429/5xx 位于 `ops_error_logs`；失败 attempt 没有进入质量分母，导致有成功流水但失败很多的账号仍被误判为高质量并持续选中。

## 修复

- 保留成功 attempt 和延迟样本来自原生 `usage_logs`。
- 将已选账号后的非客户端、非业务限制、非模型不支持错误从原生 `ops_error_logs` 纳入账号质量分母。
- 按账号和请求键去重，并排除已经存在有效 usage 的同一请求，避免重复计数。
- 不修改 Monitor V4 缓存公式、账号分组、账号状态、倍率或生产数据。
