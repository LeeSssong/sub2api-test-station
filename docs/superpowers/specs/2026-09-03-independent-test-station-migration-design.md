# 独立测试站迁移设计

## 目标

将当前测试站及其测试数据迁移到新服务器 `49.51.203.200`（IPv6 `240d:c000:f07f:9400:5ec6:896c:9636:0`），以独立根路径运行，不再依赖主站 `/admin/lab/` 挂载；主站服务、数据、凭据、网络和卷保持不变。

## 已确认约束

- 旧测试站允许停止，但停止目标只能是测试站专用 Compose project/容器。
- 新站暂不绑定域名，先通过 IPv4/IPv6 裸 IP 访问。
- GitHub 仓库必须为私有仓库。
- GitHub 凭据复用本机 `gh auth` 登录态或系统 keyring，不把明文凭据写入仓库、文档、日志或聊天。
- 发布与部署使用本地/宿主脚本，不使用 GitHub Actions。

## 当前事实

- 代码已有 `infra/compose.admin-lab.yaml`、`ops/release-admin-lab.sh` 和独立测试站实现，但现有拓扑挂载在主机 `/admin/lab/`，且旧部署脚本绑定旧生产宿主，不能直接用于新机。
- 新服务器 SSH 用户为 `ubuntu`，当前为空白主机，无 Docker/Compose 及运行容器。
- 私钥权限已收紧为 `0600`。

## 方案与选择

采用“新机重建运行时 + 停机全量逻辑备份恢复”。不复制整台主机或直接复制 Docker 卷：先停止旧测试站，导出 PostgreSQL、Redis、应用数据和配置清单，再在新机创建独立 project/network/volume 并恢复。旧站和原始备份保留至线上验证完成，失败时可回切。

## 数据与安全边界

- 迁移 PostgreSQL 全库、Redis 持久化数据、`/app/data`/上传数据及测试站专属配置。
- 重新生成新站 JWT、CSRF、Cookie、数据库、Redis 等秘密；禁止复制主站凭据。
- 备份使用受限目录、SHA-256 校验和；不得把真实数据或秘密推送 GitHub。
- 裸 IP 初期可用于受限验证；长期管理员访问必须后续补充 HTTPS、VPN 或来源限制。

## 验收与回滚

验收覆盖登录、用户/账号/余额/账单、API、流式响应、worker、探测器、文件数据、重启持久化、IPv4/IPv6 和主站不受影响。失败时停止新站并恢复旧测试站，不删除旧数据。

## 待执行动作

1. 新机安装 Docker Compose、加固 SSH/防火墙并建立独立目录。
2. 对旧测试站做只读盘点，停止仅测试站 project，生成并校验全量备份。
3. 在新机部署根路径拓扑并恢复数据，执行功能和隔离验收。
4. 创建 GitHub 私有仓库，推送去秘密化代码和运维文件。
5. 记录迁移证据、回滚点和新站运行身份；验证完成前不删除旧站。
