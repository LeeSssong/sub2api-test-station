# 账号监控：分组经营与质量排序设计

**日期：** 2026-08-01（Asia/Shanghai）  
**状态：** 已确认设计，待用户审阅书面规格后再进入实施计划

## 目标

把管理员账号监控页改造成以分组为入口的运营监控台。管理员应能在一个页面中：

1. 先看到全站或某分组的服务质量与经营结果；
2. 再下钻到账号，判断单账号的稳定性、成本、营收与利润；
3. 使用质量评分决定**监控展示顺序**，但绝不隐式改变生产调度或流量分配。

## 已确认的产品规则

- 页面使用 `全站` 与各分组的 Tab；不再将所有分组的账号卡片平铺在同一页。
- `全站` 永远在第一个 Tab；其余分组按分组质量分由高到低排列。
- 分组排名只影响账号监控页的 Tab 与分组展示顺序，不更新 `groups.sort_order`，不影响用户可见顺序、账号调度或流量分配。
- 账号卡片的唯一可编辑调度字段仍是 Sub2API 原生 `accounts.priority`。数值越小，原生调度优先级越高。
- 不创建可编辑的“分组优先级”或第二套账号调度优先级。
- 本组中的账号名次为只读信息；它以原生全局账号优先级为依据，不能编辑。
- 质量分只用于监控排序、健康判断、告警与运营决策；不参与实际调度。
- 默认重点为“今日”，今日的统计窗口为服务器配置时区的当天 `00:00` 至当前时间；同时必须默认可见“历史累计”，不能把今日 0 误解为历史数据删除。

## 页面层级

```text
账号监控
├── 全站 Tab
│   ├── 今日 + 历史累计：成本、营收、利润、利润率、请求、Token
│   └── 全站去重账号列表
└── 分组 Tab（按分组质量分排序）
    ├── 分组状态、质量分、展示名次、可用性与账务汇总
    ├── 当前分组的评分规则
    ├── 正常账号卡片（按账号质量分排序）
    ├── 不可用账号折叠区
    └── 已停用/未启用账号说明区
```

## 顶部总览与 Tab

页面标题保持“账号监控”，副标题明确为“按分组比较服务质量与投入产出；真实请求优先，探测数据补位”。右侧保留“立即刷新探测”。

顶部总览保留深色大统计卡的视觉语言，展示：

- 全部账号：参与监控数与已暂停数；
- 当前可用：数量与可用率；
- 当前不可用：数量与按原因归类的摘要；
- 待确认：没有近期真实请求且探测过期的账号数；
- 今日经营：上游成本、用户营收、利润、利润率；
- 历史累计：上游成本、用户营收、利润、利润率。

分组 Tab 采用截图中横向胶囊筛选项的风格，显示“分组名 · 可用 N / 不可用 N · 质量分”。`全站` Tab 显示去重后的全部账号池；某账号属于多个分组时，在全站只出现一次。

## 分组经营头部

每个分组 Tab 在账号列表上方展示一条分组经营头部：

- 分组名称、状态、暴露状态、质量分、展示名次；
- 可用 / 不可用 / 待确认账号数量；
- 今日：请求、Token、上游成本、用户营收、利润、利润率；
- 历史累计：上游成本、用户营收、利润、利润率；
- “评分规则”入口，用于调整本分组的监控评分权重。

“暴露状态”并非单一数据库字段，而是依据分组状态、专属分组授权、订阅类型与有效订阅综合判断。`inactive` 分组仅显示“已关闭”，不发异常告警；活跃但没有向任何有效用户开放的分组只显示一次运营提示；活跃、已开放且无可用账号的分组才进入异常状态。真实用户请求失败可覆盖该抑制条件。

## 账号卡片：截图为视觉基准

账号卡片必须以现有账号监控的深色卡片组件和截图为基线复用、扩展，不新建一套普通统计卡或表格来替代。实现时应保留该图的双列卡片布局、层级、边框、色彩、状态区和信息密度；新增字段只嵌入既有信息区：

- 左侧状态色边：绿色表示可用，红色表示不可用，灰色/虚线表示暂停或未启用；
- 卡片头部：账号名、ID、平台标签、可用状态；右上角为醒目的综合评分；
- 评分下方：本组质量名次、证据置信度、真实请求或探测样本说明；
- 四格核心指标：账号倍率、成功率、TTFT P50、总耗时 P95；
- “最近 5 分钟监测情况”保留为条形时间序列，并显示成功数或探测补位次数；
- 今日用量行：请求、Token；
- 今日投入产出行：账号成本、用户扣费、利润、利润率；
- 累计投入产出以第二行、较低视觉层级紧随今日数据展示：累计成本、累计营收、累计利润、累计利润率；
- 底部保留数据来源、样本数、更新时间与刷新/历史等动作。

卡片中唯一可编辑项为“账号权重”，其文案应明确为“全局调度优先级”，以避免将其误解为评分权重。编辑成功后，页面立即重新拉取并计算该账号在当前分组中的只读优先级名次；质量排序不随该字段改变而被覆盖。

## 评分与排序

### 账号质量分

每个分组拥有独立的四项评分权重：

- 账号倍率（成本）；
- 成功率；
- TTFT；
- 总耗时。

四项权重必须为非负整数并合计 100%。新分组默认使用成本 30%、成功率 30%、TTFT 20%、总耗时 20%。评分规则仅影响该分组账号的质量分、该分组质量分及页面展示排序。

账号需要满足“当前可调度、探测结果新鲜、评分所需证据充分”才进入正常排序。不可用账号不参与评分，进入独立的红色折叠区；已暂停或未启用账号显示在独立说明区，不计入可用/不可用/评分。

### 分组质量分

分组质量分由该组可参与评分账号的质量分汇总得出。默认按该账号在当前分组的真实请求占比加权；无真实请求时，退回为等权平均。为了避免无证据分组占据前列：

- 没有足够新鲜探测或真实请求证据的分组标记“证据不足”，不进入正常名次；
- 不可用账号不会被隐藏，而是通过可用数量和异常状态显式暴露；
- 同分时按可用账号数、随后按分组名称稳定排序。

排名是自动计算、只读的监控排名。管理员无需手动拖拽或保存排名；更新评分规则或刷新探测后，相关 Tab、分组与账号立即按新的质量分重新排序。

## 账务口径与去重

全站和分组均直接聚合请求流水，而非累加账号卡片或分组卡片：

- 全站：每条 `usage_logs` 仅计入一次，按真实 `account_id`、成本与用户扣费字段聚合；账号跨组不会重复。
- 分组：按每条请求真实记录的 `usage_logs.group_id` 聚合；账号可跨组归属，但一次请求只记入实际服务的那个分组。
- 未带 `group_id` 的流水只计入全站，并在全站经营区单独标为“未归属请求”，以解释分组之和与全站可能存在的差额。
- 利润 = 用户营收 - 上游成本；利润率 = 利润 / 用户营收。用户营收为 0 时，利润率显示为 `—`，不显示误导性的 0%。

## 数据与交互边界

- 卡片与分组均清楚标识“今日（服务器时区）”和“历史累计”。
- 每项经营数值应返回其时间窗与更新时间；刷新探测只更新服务质量证据，不得修改账务流水。
- 全站与分组汇总需要独立的批量聚合接口，避免前端逐卡片相加或产生 N+1 请求。
- 评分规则需要独立、受管理员权限保护的持久化配置；不得借用或覆盖原生账号优先级、分组显示排序或调度模型路由配置。
- 所有新接口继续遵守管理员权限与现有敏感字段脱敏规则，不向浏览器输出账号凭据、Cookie、上游 URL 或原始响应。

## 验收标准

1. 管理员可在全站与任一分组间切换；分组 Tab 和分组列表按质量分自动排序。
2. 修改评分规则后，仅监控质量分与展示顺序变化；账号实际原生调度优先级和分组流量行为不变。
3. 同一账号跨多个分组时，全站请求、成本、营收、利润不重复；分组数据按实际请求 `group_id` 归属。
4. 账号卡复用已确认的深色监控卡视觉与信息层级，并显示服务质量、今日投入产出和累计投入产出。
5. 卡片可直接编辑全局调度优先级；本组名次只读且编辑后刷新。
6. 次日零点后，今日数据归零但历史累计仍可见，页面明确说明统计口径。
7. 停用、未暴露和真实异常分组分别呈现已确认的不同告警语义。
