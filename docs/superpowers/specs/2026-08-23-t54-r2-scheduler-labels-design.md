# T54-R2 调度预设语义、中文参数与有界校验规格

## 1. 背景与证据

T54-R1 已完成分组选择、策略模式二选一、预设回填和管理员命名预设。当前页面仍把服务端预设英文名直接展示给管理员，部分参数标签来自内部英文字段，且参数区间和作用说明不统一。截图只作为现状证据，不改变本规格。

## 2. 目标

- 内置预设保留既有内部 ID：`builtin:special_offer`、`builtin:balanced`、`builtin:pro`。
- 管理员可见名称改为最多 5 个汉字：`体验优先`、`体验均衡`、`利润优先`。
- 预设语义与用户确认一致：体验优先按连续性、延时/耗时、利润排序；体验均衡按连续性优先、延时/耗时与利润并列；利润优先按利润、连续性、延时/耗时排序。
- 自定义参数和预设只读参数统一使用最多 5 个汉字的中文名称，并显示有限区间与简短说明。
- 前端输入约束与后端解析约束保持同一范围；读取旧配置时进行有界归一化，避免历史超界值破坏设置页或运行时。

## 3. 非目标

- 不修改调度评分算法、内置预设数值、S1/S2 硬预算、自动重试、sticky、故障域、并发、候选池语义或 Monitor V2。
- 不保留或新增试用探测样本数、失败数、失败原因等旁证展示；体验卡仍按 T54 既定的完全乐观展示。
- 不新增数据库表、迁移、历史回填、生产业务数据写入或 GitHub Actions。
- 不改内部 JSON 字段名、设置 key、预设 ID 或旧客户端兼容格式。

## 4. 展示契约

### 4.1 内置预设

| 内部 ID | 展示名 | 语义排序 |
|---|---|---|
| `builtin:special_offer` | 体验优先 | 连续性 > 延时/耗时 > 利润 |
| `builtin:balanced` | 体验均衡 | 连续性 > 延时/耗时 = 利润 |
| `builtin:pro` | 利润优先 | 利润 > 连续性 > 延时/耗时 |

服务端继续返回完整底层快照；只改 `name`，不改既有数值和 ID。前端不得根据名称反推 ID。

### 4.2 参数标签、范围与说明

| 内部字段 | 中文名 | 有效范围 | 简短说明 |
|---|---|---:|---|
| `top_k` | 候选数 | 1–32 | 每次参与评分的候选账号数 |
| `priority` | 优先级 | 0–10 | 账号基础优先级影响 |
| `load` | 负载 | 0–10 | 当前负载惩罚强度 |
| `queue` | 排队 | 0–10 | 排队等待惩罚强度 |
| `error_rate` | 错误率 | 0–10 | 历史错误惩罚强度 |
| `ttft` | 首字 | 0–10 | 首字延迟偏好 |
| `reset` | 重置 | 0–10 | 额度重置接近度偏好 |
| `quota_headroom` | 额度余量 | 0–10 | 可用额度余量偏好 |
| `upstream_cost` | 上游成本 | 0–10 | 上游成本排序影响 |
| `previous_response` | 响应连续 | 0–10 | 延续上一响应账号的偏好 |
| `session_sticky` | 会话粘性 | 0–10 | 保持会话账号的偏好 |
| `candidate_pool_mode` | 候选池 | 仅优选/全部可用/混合公平 | 选择候选账号池范围 |
| `exploration_ratio` | 探索比例 | 0–100% | 在候选池内探索低频账号的比例 |
| `starvation_threshold_seconds` | 冷落阈值 | 0 或 300–86400 秒 | 账号最长未被选中的保护阈值 |
| `fairness_weight` | 公平权重 | 0–10 | 公平保护对排序的影响 |

UI 标签和说明必须走中文 locale；内部字段名只存在于 API 类型、序列化和测试中，不直接渲染。

## 5. 归一化与校验

- 新写入：`top_k` 为整数 1–32；十项权值和公平权重为有限数 0–10；探索比例为整数 0–100；候选池为固定枚举；冷落阈值为 0 或 300–86400 秒。
- 旧读取：数值先转为有限数，再夹到对应区间；无法解析的值回退到同一字段的既有默认值；冷落阈值小于 300 且非 0 时归一化为 300，超过 86400 归一化为 86400。
- 运行时与 GET 设置视图使用同一归一化函数，避免页面显示值与调度器实际值不一致。
- 前端 number 控件提供 `min`/`max`/`step` 与说明；提交前再次清洗。后端仍是最终权威，非法请求 fail-closed，不部分写入。
- 基础权值总和为 0 的配置继续拒绝；不改变旧配置的模式、预设引用或快照语义。

## 6. 兼容性

- 旧 `weighted_override`、`fair`、旧英文预设 ID 和旧设置 key 均保持可读；仅在展示层映射为新的中文名称。
- 管理员自定义预设名称继续遵守既有命名和引用删除规则；本任务不改变自定义名称合同。
- 预设模式仍然只读，自定义模式仍然可编辑；三步流程和原生分组读取不回归。

## 7. 测试与验收

- Go：内置预设名称/ID 映射、所有边界值、旧超界值归一化、非法值拒绝、基础权值全零拒绝。
- Vue/Vitest：中文预设名、中文参数名、区间和说明可见；控件 min/max 与 disabled 状态正确；自定义/预设流程、原生分组来源、旧 payload 兼容保持通过。
- 门禁：定向 Go/Vitest、`go build ./cmd/server`、`pnpm typecheck`、`pnpm build`、`git diff --check`。

## 8. 发布与回滚

无迁移、无生产业务数据写入，预计 `downtime_required=false`。候选必须先合并到根 `main`，在已验证的 `main` 上按既有本地/宿主蓝绿链发布；只有根总控执行推送、部署、线上验收和回滚。线上验收确认三种中文预设、参数中文标签/范围/说明、预设只读和旧配置可读。回滚使用上一蓝绿槽或上一发布镜像，不需要数据库回滚。

## 9. Done when

当规格要求的代码、直接相关测试、构建/类型门禁和 diff 检查通过，且候选 handoff 标记 `READY_FOR_ROOT_REVIEW`；生产完成必须由根总控另行记录“已推送、已部署、已验证生效”。
