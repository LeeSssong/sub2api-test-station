# Sub2API 客服联系卡设计

## 目标

优化管理端“联系客服”自定义 Markdown 页面：

- 二维码不再撑满内容区，默认以约 220px 的紧凑尺寸展示。
- 点击二维码可查看大图，保留扫码识别能力。
- QQ 群号 `1080152144` 作为独立信息展示，并提供一键复制。
- 复制成功或失败时给出明确反馈，并兼顾键盘和屏幕阅读器。

## 根因

客服页由 `config/sub2api/support.md` 提供，经 `CustomPageView.vue` 转换和清洗后通过 `v-html` 渲染。通用图片规则仅设置 `max-width: 100%`，因此原始二维码会占据过大的内容区域；QQ群号则只是静态粗体文本，没有交互。

## 设计

### 联系卡布局

`support.md` 使用经过 DOMPurify 清洗的语义化 HTML 标记一个客服联系卡：

- 左侧为 220px 二维码缩略图。
- 右侧为说明、等宽 QQ 群号和“复制群号”按钮。
- 宽屏为两列，窄屏自动堆叠并居中二维码。
- 二维码图片使用稳定尺寸与 `object-fit: contain`，不影响其他 Markdown 图片。

### 复制交互

`CustomPageView.vue` 对 Markdown 容器使用事件委托，识别带 `data-copy-text` 的按钮，并复用项目现有 `useClipboard()`：

- 点击后复制 `1080152144`。
- 成功时按钮短暂显示“已复制”与勾选状态。
- 失败时显示“复制失败”。
- 状态通过 `aria-live` 对辅助技术可见。

复制能力限定在显式的 `data-copy-text` 元素上，不执行 Markdown 中的脚本。

### 二维码放大

二维码缩略图作为按钮使用。点击或键盘激活后打开原生 `<dialog>` 风格的图片预览层：

- 显示完整二维码。
- 支持关闭按钮、点击遮罩和 Escape 关闭。
- 关闭后焦点回到二维码按钮。

### 样式边界

所有新样式以 `.support-contact-card` 为根，避免改变其他自定义 Markdown 页面。继续沿用 Sub2API 的深浅色、边框、主色和按钮视觉。

## 验证

- 单元测试覆盖支持卡 HTML、复制成功/失败、二维码打开和关闭。
- 运维配置测试确认发布的 `support.md` 包含联系卡标记和群号。
- 运行前端测试、TypeScript 类型检查与生产构建。
- 在桌面和移动视口检查二维码尺寸、复制按钮、预览层、溢出和控制台错误。
