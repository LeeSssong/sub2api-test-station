# 候选上游管理台安全录入设计

**日期：** 2026-07-21
**状态：** 用户已批准方案 1，等待规格复核后实施

## 1. 目标

管理员在生产 `/ops` 中一次性录入候选中转站和独立低额度监测 Key。保存后，relay-ops 自动进入既有候选采集流程；管理员不再需要先通过 SSH 安装 Key 文件。

该功能只管理 relay-ops 自身的候选站资料和探测秘密，不修改 Sub2API 分组、路由、倍率、价格、用户余额、生产上游 Key 或飞书命令模式。

## 2. 当前事实

- 候选列表、创建 API、停用 API、定时采集、价格变化事件和显式付费探测门禁已经存在。
- 当前创建 API 只接受服务器秘密文件路径；`/ops` 没有候选录入表单。
- 生产容器根文件系统和 `/run/secrets/candidates` 均为只读。
- 生产保持 `RELAY_OPS_MODE=read_only`、`RELAY_OPS_FEISHU_COMMAND_MODE=dry_run`；候选付费 probe 未获批准。

## 3. 已选方案

采用“管理台一次性提交 Key，服务端安装到专用秘密目录”。

未采用：

1. 仅填写服务器秘密文件路径。安全边界最小，但仍依赖 SSH，不满足管理员自助录入目标。
2. 无 Key 基础监控。可以抓公开页面，但不能立即完成模型发现、TTFT、SSE 和真实 API 可用性验证。

## 4. 管理台交互

在现有“候选上游”列表前增加“录入候选上游”表单：

1. 名称，必填，1-100 字符。
2. OpenAI-compatible HTTPS Base URL，必填。
3. HTTPS 模型定价/倍率页，必填。
4. HTTPS 用量/账单页，必填。
5. HTTPS 性能页，可选。
6. 独立低额度监测 Key，密码框，必填，4-8192 字节。

表单明确提示：Key 只用于候选模型发现和受预算约束的探测，不使用生产充值主 Key。提交按钮运行期间禁用，成功后清空全部字段并刷新候选列表；失败只显示稳定错误码和可操作提示，不回显 Key 或服务端路径。

候选列表继续显示名称、状态、最近检查和价格变化，并为启用记录提供“停用”命令。停用需要二次确认；它只停止后续候选采集，不删除审计和历史证据。

## 5. API 与数据流

浏览器通过现有管理员登录态、同源 HTTPS 和 CSRF/Origin 门禁向候选创建端点提交 JSON。请求新增 `probe_key`，不再要求管理员提供 `probe_key_file`。

```text
管理员表单
  -> 同源 HTTPS POST /relay-ops/api/candidates
  -> 限制请求体和字段
  -> 候选秘密存储原子安装 Key
  -> 既有候选服务读取一次并计算 SHA-256 指纹/末四位
  -> 数据库保存候选资料、file: 引用、指纹和审计摘要
  -> 响应仅返回候选 ID、名称、Base URL、启用状态
```

任何步骤失败都不得留下候选数据库记录。数据库创建失败时删除本次新建的秘密文件；删除失败只记录不含路径和 Key 的稳定运维错误，并阻止返回成功。

## 6. 秘密存储边界

- 新增专用目录 `/var/lib/relay-ops/candidate-keys`，宿主机来源位于生产 secrets 目录，权限 `0700`，所有者为容器 UID/GID `10002`。
- 仅该目录以读写挂载；容器根文件系统、既有飞书/路由/Admin API 秘密和 `/run/secrets/candidates` 保持只读。
- 服务端文件名来自规范化候选名称的 SHA-256，不使用用户输入路径，不允许路径穿越。
- 使用 `O_CREATE|O_EXCL` 和 `0600` 创建，限制 Key 为 4-8192 字节，去除首尾空白，不允许覆盖现有文件。
- Key 不进入数据库、审计摘要、日志、错误、飞书、Agent 输入、页面 HTML、响应 JSON、命令行参数或文档。
- 服务持有的可变 Key 字节在安装完成后尽力覆盖清零；不对 Go 运行时、TLS 栈或 JSON 解码器的短生命周期内部缓冲区作不可验证的确定擦除承诺。API 客户端成功或失败后清空密码框。
- 数据库只保存 `file:` 引用、SHA-256 指纹和末四位，用于冲突检测和管理员识别。

## 7. 运行模式与探测预算

创建候选记录不会自动批准付费 probe。`read_only` 下只执行既有公开页面采集和无费用发现；任何同步/SSE 付费探测继续受既有全局预算、每候选最多 2 请求、每请求最多 `$0.001` 和管理员单独批准约束。

页面和 API 不提供“直接切换生产”“改价格”“改倍率”或“复制为生产上游”动作。候选综合更优仍只产生观察标签和飞书提醒。

## 8. 错误处理

- 未登录：`401`。
- Origin、Content-Type 或 CSRF 不符合：`403 ORIGIN_REJECTED`。
- 无效字段、URL、Key 长度或秘密安装失败：`400 CANDIDATE_REJECTED`。
- 名称/Base URL/Key 指纹冲突：`409 CANDIDATE_CONFLICT`。
- 数据库失败：`500 CANDIDATE_CREATE_FAILED`。

面向浏览器的消息只解释下一步，不包含底层文件名、IP 解析结果、数据库错误、Key 片段或内部堆栈。

## 9. 测试与验收

测试先行覆盖：

1. `/ops` 渲染六个字段、密码输入、提交状态和候选停用按钮。
2. 前端提交 `probe_key`，成功后清空并刷新；失败不回显 Key。
3. API 拒绝未知字段、空/超长 Key、跨域和错误 Content-Type。
4. 秘密存储创建 `0600` 文件、拒绝覆盖/路径穿越、失败清理并清零输入缓冲区。
5. 数据库只保存指纹、末四位和 `file:` 引用。
6. 候选创建成功、冲突和数据库失败回滚。
7. 候选停用只改变候选启用状态，不触碰生产来源或 Sub2API。
8. Go 全量 race、vet、JavaScript 语法、Compose/Caddy/relay-ops 契约均通过。

生产部署只重建 relay-ops。验收必须确认：

- `/healthz`、`/readyz`、`/pricing`、`/ops`、`/monitor` 为 HTTP 200。
- relay-ops `healthy`、重启数为 0、模式仍为 `read_only + dry_run`。
- 新目录权限和挂载范围符合设计，其他秘密仍只读。
- `/ops` 表单真实可见，密码字段不会由浏览器恢复旧值。
- 使用故意无效的非秘密测试值验证失败路径，不在生产创建临时候选或残留秘密。
- 飞书路由配置哈希和 Sub2API canonical 路由快照与部署前一致。

首次真实成功录入由管理员后续使用新的候选站和独立低额度 Key 完成；该操作产生正常候选审计记录，不属于部署测试数据。

## 10. 完成标准

代码、本地测试、生产部署和无残留失败路径验收全部通过；管理员可以只通过 `/ops` 安全录入候选站及低额度 Key，候选进入既有只读采集流程，而生产路由、价格、余额和飞书 `dry_run` 状态保持不变。
