# 账号监控产品补完设计

**日期：** 2026-08-02（Asia/Shanghai）  
**状态：** 用户已通过历史方案及本轮截图纠正确认  
**继承规格：** `2026-08-01-account-monitor-group-operations-design.md`

## 目标

补完 `/admin/accounts/monitor` 的已确认产品结构。首屏必须先回答全站经营是否正常、全站账号服务是否正常；默认展示全站唯一账号全集。进入分组后，再回答该分组的经营、服务、评分规则和账号分区。评分只影响监控排名，`accounts.priority` 继续是唯一真实调度优先级。

## 已确认的信息架构

```text
账号监控
├── 全站经营数据
│   ├── 用户实际计费、上游真实扣费、纸面利润、利润率
│   └── 成本覆盖率、待对账数量、今日与历史累计
├── 全站账号数据
│   ├── 全部账号、监控中、可用、不可用、待确认、暂停
│   └── 成功率、首包时间 P50、总耗时 P95
├── Tab：全站、分组 A、分组 B……
└── 当前范围
    ├── 分组经营数据与分组服务数据（选择分组时）
    ├── 账号状态摘要 + 当前分组评分权重 + 配置入口
    └── 可用 / 不可用 / 成本不合格 / 待确认 / 暂停账号分区
```

## 数据口径

- 全部账号使用顶层账号投影按 `account_id` 去重；不能把分组成员数相加。
- 默认 Tab 是“全站”，默认没有隐式分组筛选；首次打开必须展示全站账号全集。
- 管理状态、服务状态和分组资格是三个独立维度，不能用一个状态互相覆盖。后端为顶层账号和分组账号分别投影 `management_state`、`service_state`、`group_eligibility`，并额外提供只用于页面分区的 `monitor_bucket`；页面只显示对应中文名称。
- `management_state` 为 `enabled` 或 `paused`；`service_state` 为 `available`、`unavailable`、`pending` 或暂停时的 `not_monitored`；`group_eligibility` 为 `eligible`、`cost_ineligible`、`multiplier_pending` 或全站/暂停时的 `not_applicable`。
- `status != active`、`schedulable == false`、临时不可调度或已按过期策略暂停的账号归为暂停，仍可见，但不计入可用、不可用、待确认或评分。
- 启用账号中，无新鲜证据、无探测结果或倍率未知归为待确认；有新鲜成功证据且满足当前分组成本资格归为可用；有新鲜失败证据归为不可用。
- 分组内账号倍率高于分组倍率时，分组资格为成本不合格；倍率缺失或状态未确认时，分组资格为倍率待确认。成本不合格账号的服务状态仍可为可用，不能因此计入服务不可用。
- 页面分区按“暂停 > 服务待确认或倍率待确认 > 成本不合格 > 服务可用/不可用”的固定优先级生成唯一 `monitor_bucket`。
- 全站/分组服务健康计数只使用管理状态和服务状态；满足 `可用 + 不可用 + 待确认 + 暂停 = 全部账号`，并额外返回“监控中 = 全部账号 - 暂停”。分组资格不改变这组服务计数。
- 页面整体过期只检查监控中的账号；暂停账号不会再被探测，其旧记录或无记录不能让整个页面永久显示过期。
- 已关闭分组继续显示账号，保留“已关闭”语义，但不把空账号持续作为故障告警。
- 分组质量评分只适用于管理启用、证据新鲜、成本合格的账号；其余账号没有质量排名。

## 页面结构

- 全站经营与全站账号数据使用两个明确命名的并列/上下区块，不把“服务健康”塞进经营指标卡末尾。
- Tab 首项固定为“全站”；其余分组按倍率降序，同倍率按原生稳定顺序。
- 分组经营与分组服务数据也使用两个明确区块，均位于账号卡片之前。
- “评分权重”与“可用 X 个 · 不可用 X 个 · 按质量分降序”位于同一账号区头部，直接展示四项当前值并提供清晰的配置按钮。
- 账号卡片复用现有监控卡视觉，不重做独立页面。宽屏保持双列，不允许单张卡片留下大面积无意义空白。
- 页面和面向人的状态、分区、按钮全部使用中文；API、TypeScript 和数据库字段可保留英文。

## 验收标准

1. API 返回的全部唯一账号均能在“全站”Tab 找到；无筛选时不再只显示第一个分组。
2. 暂停账号可见且只计入暂停；服务计数四类互斥，`可用 + 不可用 + 待确认 + 暂停 = 全部账号`。
3. 全站经营数据与全站账号数据视觉和语义分离，并包含上述全部指标。
4. 每个分组 Tab 同时展示分组经营、分组服务、权重摘要和五类账号分区。
5. 关闭分组仍可检查其账号；评分保存、恢复默认和账号调度优先级行为保持原生产合同。
6. 桌面与移动端无重叠、横向溢出或文字截断；生产 Chrome 无业务控制台错误。
