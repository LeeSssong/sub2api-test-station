# 账号监控调度排名与真实请求优先性能监控设计

日期：2026-09-02

## 目标

1. 账号监控未选择分组时，账号顺序直接按 T114 质量分字段降序重排；选择分组时，顺序与该分组当前原生调度排名一致。
2. 分组性能监控以用户真实请求为主；主动探测仅在对应五分钟桶没有真实请求时补足，并显式展示补足量。
3. 修复账号监控首页加载失败后显示英文 `internal error` 和误导性的“全站 0”。

## 排名事实源

后端复用现有原生调度投影，不再使用旧质量评分权重决定分组页主顺序。分组页直接使用 `scheduler_rank`；全站页使用账号的 T114 `quality_score` 字段降序，分数相同再按成功质量、P50 TTFT、账号 ID 稳定排序。

旧 `quality_rank` 和 `group_rank` 字段暂时保留兼容，但不参与前端主排序。

## 用户体感性能口径

每个分组、每个五分钟桶只选择一种主来源：

1. 有真实请求时仅采用真实请求；
2. 没有真实请求且存在有效主动探测时采用探测补足；
3. 两者均无时为无数据。

窗口主指标包括真实请求数、成功数、失败数、成功率、TTFT 和完整耗时。主动探测不得增加真实请求计数，补足桶和补足请求数单独返回。窗口始终满足成功数与失败数不超过请求数。

## 首页错误恢复

- 首次请求失败：显示中文可重试错误态；“全站”计数显示 `--`，不得显示 0。
- 已有成功快照后刷新失败：保留现有卡片和分组数据，只显示数据延迟提示。
- 后端日志记录失败阶段和原始错误；前端不直接展示英文 `internal error`。
- 分组真实请求查询不得引用不存在的 CTE 字段；增加 SQL 合同测试防止回归。

## 实施与发布边界

修改账号监控 repository/service contract、Monitor V4 真实请求优先 SQL、账号监控前端错误态与直接测试。无数据库迁移、无调度算法改写、无账务或生产数据写入。完成定向测试、后端构建、前端测试、类型检查和生产构建后停在可发布状态，不推送、不部署。
