## 4. 供应与售价策略

- 第一条真实闭环只使用现有上游，不等待新上游主动提供下游合作。
	- 我的回复：没有现有上游，我只是在别人的中转站充值了拿到key而已，对别人而言我是普通用户，不是下游
- 第二家中转 API 先录入非敏感价格/限额/条款并在私有测试组取样，用 ROUTE01 比较；付费公开流量要求商用/再分发状态确认。
	- 我的回复：我的中转站只做两种，一种是接别人，一种是自己买https://priceai.cc/网站里的号，都是不保质的，只要能快速消耗，我盈利的几率很高
- 账号池首样只买 1 个独立 Plus。K12 只视为卖家标签；组织托管、共享 Pro、Token/Cookie-only、卖家保留恢复权或要求绕过登录/验证码/地区风控的候选直接淘汰。
	- 我的回复：参考我上条回复，号池的标准。【组织托管、共享 Pro、Token/Cookie-only】这个我没懂什么意思，【卖家保留恢复权】这个也没懂，【要求绕过登录/验证码/地区风控的候选直接淘汰】这个倒是可以
- 真实售价必须等 UP01 成本和至少三笔调用数据到位后重算，完全成本毛利目标不低于 20%。不按卖家宣称的理论额度定价。

## 9. 主要剩余风险

- 消费订阅账号不等于可转售 API 合同，账号可能找回、限制、降级或封禁。
- 上游中转可调用不代表允许再分发；价格、模型和限额会变化。
- Sub2API v0.1.155 的 LICENSE 与 README 商业限制/免责声明需要在真实收费前单独处理。
- 活动服务器价格和库存会变化，续费通常恢复官网价。
- 离线和本地验证不能替代真实网络、计费、支付、备份恢复和用户流程验收。
