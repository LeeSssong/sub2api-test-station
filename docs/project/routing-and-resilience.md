# 路由、熔断与扩容基线

**更新日期：** 2026-07-15  
**当前状态：** 离线基线完成；真实上游指标、三网样本、线路和节点均不存在或未购买

## 当前推荐

1. MVP 保持一个 Sub2API 节点和原生调度，不增加 Envoy/Nginx 故障转移层。
2. 第一家上游先在邀请测试组跑通；第二家上游取得非敏感价格、模型、限额和条款信息后，用 ROUTE01 比较，不因价格更低直接切主。
3. 自动额外尝试最多 1 次。响应已开始、扣费已发生或扣费状态未知时不跨上游重试。
4. 429 使用短冷却，529 使用过载冷却，401/402/403 进入人工隔离；连接/TLS/超时和 5xx 才进入滚动熔断。
5. 当前不购买优化线路，不增加第二节点。D10/D11 只有真实数据达到门槛后才提交。

## 与 Sub2API 的边界

Sub2API v0.1.155 已有账号/分组优先级、粘性会话、负载感知、并发槽位、模型路由和临时不可调度。本项目不复制这些运行时功能：

- ROUTE01 用于接入前比较和运营决策。
- 通过评分的渠道再映射到 Sub2API 独立分组或账号优先级。
- 新渠道先处于测试分组，达到样本门槛后才加入用户流量。
- 人工禁用始终优先，不能被半开计时器自动恢复。

## 上游评分

| 项目 | 权重 | 越高越好 | 默认边界 |
|---|---:|---|---|
| 成功率 | 30% | 是 | 90% 计 0 分，99.5% 计 100 分 |
| 单位成本 | 25% | 否 | USD 1.5–4.0 / 百万 Token |
| TTFT P95 | 20% | 否 | 500–2500 ms |
| 并发余量 | 15% | 是 | 10%–80% |
| 客服响应 | 10% | 否 | 30–240 分钟 |

资格过滤先于评分：至少 20 个样本、余额至少 2 天、并发余量至少 10%、429 比例不高于 15%、模型匹配、熔断关闭。付费公开流量还要求再分发/商用条款状态为 `confirmed`；`unknown` 只允许私有测试。挑战者需高出当前渠道至少 8 分，并连续 3 个窗口领先，才建议切换。

示例命令：

```bash
ruby ops/evaluate-routing-baseline.rb score config/routing/ROUTE01.example.yaml gpt-test
```

示例中的 UP01–UP04 和 `gpt-test` 全是虚构数据，不代表任何真实供应商。

## 重试矩阵

| 场景 | 自动额外尝试 | 处理 |
|---|---|---|
| 连接/TLS 失败且请求体未发送 | 允许 1 次 | 切到另一合格渠道 |
| 408/429/5xx/529，明确未扣费 | 允许 1 次 | 遵守冷却和总尝试上限 |
| 上游支持幂等键且键覆盖计费 | 允许 1 次 | 复用同一业务幂等标识 |
| 已开始返回响应头或 SSE | 禁止 | 终止并保留原请求 ID |
| 扣费未知或已扣费 | 禁止 | 先对账，不赌重复成本 |
| 400/401/402/403/404/409/422 | 禁止 | 修请求、凭据、权益或余额 |

## 熔断基线

- `closed -> open`：连续 5 次失败，或至少 20 个滚动样本中失败率达到 50%。
- `open -> half_open`：首次冷却 60 秒；重复失败按 60/120/240 秒退避，最高 900 秒。
- `half_open -> closed`：连续 2 次受控探测成功；任何一次失败重新打开。
- 429 无可信 `Retry-After` 时冷却 30 秒；529 冷却 600 秒。
- 401/403、402 和人工禁用不自动恢复。

## 三网测量模板

模板见 `config/routing/network-measurement.example.yaml`。真实资产到位后复制为 `network-measurement.local.yaml`，该文件已 Git 忽略。

必须覆盖 3 家运营商 × 2 个时间段 × 2 个分段，共 12 个格子，每格至少 20 个样本：

- `client_to_entry`：用户到 Caddy，关注 RTT、丢包、DNS、TCP、TLS 和流中断。
- `entry_to_upstream`：服务器到上游，关注连接、TLS、TTFB、TTFT、429/5xx 和流中断。
- 白天和 20:00–23:00 分开统计，不能把模型排队时间当成入口线路问题。

只有入口段 P95 延迟超过 220 ms 或丢包超过 2%，且它是主要瓶颈时，才比较对应运营商的 CN2 GIA/CTGNet、CMI/CMIN2 或联通优化候选。先用测试 IP 重复同一网格，再看价格、流量包、DDoS 和超额费；当前不采购。

## 扩容阈值

先从 2 GiB 升到 4 GiB：24 小时内出现 OOM/非人为重启，或内存、swap、CPU、PostgreSQL 连接任一指标持续 15 分钟越线。阈值见 ROUTE01。

第二节点需要同时满足：

- 已完成 4 GiB 纵向扩容且仍受入口节点限制。
- 入口自身 7 日可用率低于 99.5%，或 SSE 并发至少 30 且压力持续 15 分钟。
- 预计月故障损失至少是新增节点月成本的 1.5 倍。
- 已接受共享 PostgreSQL/Redis、统一 JWT/TOTP 密钥、发布一致性和回滚的新增复杂度。

当前没有真实指标和收入损失数据，因此 LINE01 保持“不采购”。
