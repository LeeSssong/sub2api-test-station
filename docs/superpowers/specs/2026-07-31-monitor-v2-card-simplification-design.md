# Monitor V2 卡片信息精简设计

## 目标

简化 `/monitor` 的服务分组卡片：保留汇总性能指标、有效调用、P95 尾延迟和趋势；移除各指标下的样本数与整个模型列表，并让监控快照接口不再返回模型信息。

## 已确认的统计口径

卡片指标按服务分组内、所选时间窗口的全部调用样本汇总，不是按模型分别计算后取算术平均：

- TTFT 和总延迟是该分组成功调用的整体 P50/P95。
- TPS 是按 TPS 样本数量加权的整体结果。
- 可用率是该分组全部有效调用的成功率。

因此高流量模型会对分组数值影响更大；本次不新增任何模型级解释或明细入口。

## 界面

- 四项主指标继续显示其值或“样本不足／未提供”，但不显示“xxx 个样本”。
- 删除可展开的模型区块，不提供模型数量、查看／收起模型、模型状态或模型名称。
- P95 指标继续保留在卡片的紧凑详情区；本次不改变其计算口径。
- 可用率、趋势和状态徽章保持原样。

## 接口契约

- Monitor V2 快照契约从版本 `3` 升级至 `4`。
- 分组对象移除 `models` 字段。
- 后端不再读取可用渠道或探针模型信息，也不再进行模型状态聚合。
- 前端解析器拒绝仍包含 `models` 的旧载荷，以确保接口与视图同步升级，而不是静默保留不需要的模型信息。

## 验证

- 后端处理器响应测试：响应版本为 `4`，分组 JSON 不含 `models`。
- 前端契约测试：有效的版本 `4` 无模型载荷可解析；含模型字段的载荷被拒绝。
- 卡片视图测试：不显示样本数、模型列表、模型操作文案或模型状态，且仍显示指标、可用率、P95 和趋势。
- 运行目标化后端与前端测试，再运行前端构建。
