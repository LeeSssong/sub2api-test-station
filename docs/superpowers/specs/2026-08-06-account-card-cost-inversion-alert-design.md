## 四、倍率和成本证据

### 上游原生倍率

Sub2API 上游：

```text
GET /v1/sub2api/billing
→ effective_rate_multiplier
```

New API 上游：

```text
GET /api/pricing
→ group_ratio[账号映射的上游分组名]
```

系统保存「本站账号 → 上游分组名」映射；倍率数值每次从上游定价接口读取。该规则适用于所有 New API 账号，不针对任何具体供应商、账号或倍率做特例。无法取得映射或接口返回无对应分组时，倍率来源为「待确认」，不得猜测或沿用历史测算值。

### 成本折合本站倍率

有逐笔上游实际扣费时：

```text
成本折合本站倍率
  = 上游实际扣费 / 本站模型标准费用
```

没有逐笔账单，但同时有上游模型价格和上游原生倍率时：

```text
上游定价推算成本
  = Σ(上游各计费项单价 × 对应用量) × 上游原生倍率

成本折合本站倍率
  = 上游定价推算成本 / 本站模型标准费用
```

主动发探测请求前后读取上游额度的结果只能标注「额度测得」，不得覆盖上游原生倍率。

## 五、模型维度和轻量聚合

不同模型的上游价格可能不同，成本折合本站倍率必须在后端保留「账号 + 模型」维度，不在数据层平均成一个账号倍率。

有效样本必须先按「账号 + 模型」独立聚合，不能用跨模型平均值掩盖亏损模型。对每个模型，聚合成本折合本站倍率定义为：

```text
聚合成本折合本站倍率
  = SUM(上游实际扣费) / SUM(本站模型标准费用)
```

其中有效样本必须同时满足：本站请求与上游请求已成功逐笔匹配、上游实际扣费可确认、本站模型标准费用大于 0。样本数量以有效逐笔样本计数。

为保持卡片轻量，当前分组卡片只展示「当前分组范围内最高的可信成本折合本站倍率」，并在小字中显示对应模型和有效样本数。这里的“最高”只用于风险卡片和预警，不用于全站或分组利润计算。

示例：

```text
成本折合本站倍率  0.204x
成本模型                  gpt-5.4
```

某个模型已确认亏损时，不能被其他盈利模型的平均值掩盖。

## 六、当前分组判定规则

账号成本状态按当前分组 Tab 单独计算。同一账号在不同分组可以出现不同结果。

| 后端状态 | 中文文案 | 条件 |
|---|---|---|
| `loss_confirmed` | 确认亏损 | 任一模型有至少 6 笔有效逐笔上游实际扣费样本，且该模型聚合成本折合倍率 `>` 当前分组倍率 |
| `loss_observing` | 亏损观察中 | 任一模型有 1–5 笔有效逐笔样本，且当前聚合成本折合倍率 `>` 当前分组倍率；显示当前样本数/6 |
| `zero_margin` | 无利润空间 | 任一模型达到至少 6 笔有效样本，且最高可信聚合成本折合倍率与分组倍率在数值容差内相等 |
| `cost_covered` | 成本覆盖 | 所有已知模型均达到至少 6 笔有效样本且低于分组倍率，且没有已知倒挂模型 |
| `pricing_risk` | 可能亏损 | 只有上游定价推算或额度测得证据，推算成本高于分组倍率，尚无逐笔实际扣费确认 |
| `insufficient_samples` | 样本不足 | 存在 1–5 笔有效样本，但未达到确认门槛，且当前聚合值未高于分组倍率 |
| `unknown` | 成本待确认 | 无可用证据、证据过期、探测失败或上游不支持 |

状态按风险优先级从高到低确定：`loss_confirmed` → `loss_observing` → `pricing_risk` → `zero_margin` → `cost_covered` → `insufficient_samples` → `unknown`。例如，一个模型已有 1–5 笔样本且倒挂时，不能被另一个模型的“成本覆盖”结果覆盖。

`cost_covered` 只表示「当前已知成本没有发现倒挂」，不代表所有未发生请求的模型已获得逐笔真实账单。卡片通过成本来源和更新时间表达证据局限。

“超过 5 笔”严格解释为至少 6 笔有效样本。只有逐笔实际扣费证据可以进入 `loss_confirmed`；定价推算和额度测得最多进入 `pricing_risk`，不能直接确认亏损。

分组倍率变化不会清空或覆盖成本样本。`groups.rate_multiplier` 更新后，立即使账号监控的分组投影缓存失效，并使用已有样本重新计算；下一次账号监控 API 响应必须返回新分组倍率下的新状态，不要求重新产生 6 笔请求。

## 七、强提醒视觉

### 确认亏损

`loss_confirmed` 时：

- 整张卡片保留现有服务质量边色，另外增加明确的红色「成本倒挂」告警条；
- 不将账号服务状态伪装成失败，服务质量和成本风险保持两个独立状态；
- 告警条展示成本折合倍率、当前分组倍率、差额和触发模型。

示例：

```text
成本倒挂 · gpt-5.4
成本折合本站倍率 0.204x > 当前分组倍率 0.18x，高出 0.024x。
```

### 其他状态

- `zero_margin`：橙色「无利润空间」；
- `loss_risk`：橙红色「可能亏损·上游定价推算」；
- `unknown`：黄色或中性色「成本待确认」；
- `cost_covered`：低强度绿色或中性「成本覆盖」。

「立即标记」指新的成本证据被后端成功写入后，下一次账号监控投影/API 响应必须返回新状态。上游异步账单尚未生成时，不伪造「确认亏损」。

## 八、New API 通用验收口径

- 任意 New API 账号均通过「本站账号 → 上游分组名」映射定位 `/api/pricing` 中的 `group_ratio`；代码、配置和测试不得硬编码供应商名、账号名或倍率。
- `/api/pricing` 返回的 `group_ratio` 是该账号的「上游原生倍率」，实时值优先于历史缓存或主动额度测算值。
- 主动额度探测可以单独保存为「额度测得」证据，用于成本推算，但不得覆盖 New API 原生 `group_ratio`，也不得冒充上游原生倍率。
- 缺少分组映射、接口失败或找不到对应 `group_ratio` 时，返回 `null + 待确认`，不得回退到硬编码值。
- 只有本站请求和上游账单逐笔成功匹配后，才能将该笔计入有效样本并参与 `loss_confirmed` 判定。

## 九、后端投影合同

账号监控分组投影为每个账号返回一个轻量成本对象：

```json
{
  "cost_guard": {
    "upstream_multiplier": 0.20,
    "upstream_multiplier_source": "upstream_pricing",
    "equivalent_site_multiplier": 0.204,
    "cost_source": "reconciled_bill",
    "model": "gpt-5.4",
    "sample_count": 6,
    "required_sample_count": 6,
    "group_multiplier": 0.18,
    "gap": 0.024,
    "status": "loss_confirmed",
    "observed_at": "2026-08-06T12:00:00Z"
  }
}
```

合同规则：

- 金额、账单列表、用户账务数据和凭据不进入 `cost_guard`；
- 数值不可用时返回 `null` 和明确状态，不默认为 `1.0`、`0` 或账号配置值；
- `observed_at` 是生成判定的成本证据时间，不是页面刷新时间；
- 同一账号在不同分组投影中可返回不同的 `group_multiplier`、`gap` 和 `status`。

## 十一、测试与验收标准

1. Sub2API 上游有新鲜 `effective_rate_multiplier` 时，卡片正确显示数值和「上游声明」来源。
2. New API 账号映射到上游分组后，卡片从定价接口读取当前 `group_ratio`，不使用硬编码倍率。
3. 任意 New API 测试账号均显示其 `/api/pricing` 返回的 `group_ratio` 与「上游定价」来源；主动额度测得值不能覆盖该原生倍率。
4. 逐笔对账成本可用时，成本折合倍率等于「上游实际扣费 / 本站模型标准费用」。
5. 任一模型的新鲜账单实测成本折合倍率高于当前分组倍率时，显示红色「成本倒挂」告警条。
6. 只有上游定价推算时显示「可能亏损」，不显示「确认亏损」。
7. 证据失败、过期或缺失时显示「成本待确认」，不默认使用 `1.0x`。
8. 账号同时属于多个分组时，在每个分组 Tab 中分别使用该分组倍率判定。
9. 账号支持多个模型时，卡片展示当前分组内最高的可信成本折合倍率和触发模型。
10. 本次不新增金额型投入产出区，也不删除或迁移当前环境已有但可能因接口数据而不可见的金额区；本次只新增倍率字段、成本来源和成本状态。
11. 服务质量仍为正常时，成本倒挂以独立告警展示，不把账号伪装成请求失败。
12. 红色告警只展示倍率、差额、模型和证据时间，不增加营收、成本金额或对账明细。
13. 当有效逐笔样本为 1–5 笔且聚合值高于当前分组倍率时，显示「亏损观察中 n/6」；达到至少 6 笔后才可显示「确认亏损」。
14. 修改当前分组倍率后，不清空成本样本；下一次账号监控响应按新倍率即时重算状态。
