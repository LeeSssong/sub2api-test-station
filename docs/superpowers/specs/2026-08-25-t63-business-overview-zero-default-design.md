# T63 经营总览移除待确认并统一空值为 0

日期：2026-08-25  
基线：`main@fbe32c725`  
候选：`codex/t63-business-overview-zero-default`  
状态：设计中，等待书面规格审阅

## 1. 问题证据与当前行为

T57 新增的管理员经营总览 `GET /api/v1/admin/operations/business-overview` 当前同时依赖 `usage_logs` 与 T55 `user_quota_ledger_entries`。服务在 [business_overview.go](../../../upstream/sub2api/backend/internal/service/business_overview.go) 中按 `usage_logs.id` 查找额度账本记录，但扣费链路写入账本时使用的是 `request_id`/`logical_request_id` 作为 `reference_id`。历史充值又按 T55 设计不回填，因此多数历史或当前流水无法完成额度拆分。

当前服务一旦发现任意流水没有对应账本记录，就设置 `revenue_status=pending_split`，把收入、毛利和毛利率返回为 `null`；前端再将 `null` 渲染为“口径待确认”。充值/余额部分在账本缺失或查询结果为空时也会出现 `null` 或 `pending`。截图中上游成本 ¥95.31、实际消耗 ¥23.35 已经存在，但收入与毛利仍被全局门槛遮蔽，证明问题是经营总览选择了不必要的额度拆分依赖，而不是成本或用量不存在。

## 2. 目标

1. 经营总览彻底移除“待确认”“口径待确认”“pending_split”等用户可见语义。
2. 站内收入直接使用 Sub 原生 `usage_logs.actual_cost` 聚合，不再依赖历史充值或付费/赠送额度拆分。
3. 上游成本继续使用项目已批准的 Sub 原生有效账号成本表达式：
   `COALESCE(account_cost, COALESCE(account_stats_cost, total_cost) * COALESCE(account_rate_multiplier, 1))`。
4. 毛利始终为站内收入减上游成本；毛利率始终为毛利除以站内收入，收入为 0 时返回 `0.00%` 对应的数值 `0`。
5. 时间范围内没有充值、消费、成本或趋势记录时，所有金额字段返回数值 0，并在页面显示 `¥0.00`。
6. 历史充值不回填、不重算、不写入新账本，也不作为收入是否存在的判断条件。
7. 保持原生管理员入口、时间范围、分组归属、CNY/额度 1:1 展示约定和 T55 钱包写入链路不变。

## 3. 非目标

- 不修改 T55 充值、退款、消费扣款、幂等或钱包迁移。
- 不回填历史充值、历史额度拆分或历史 `usage_logs`。
- 不新增第二套计费事实源、外部账务源、汇率换算、采购成本分摊或人工估算。
- 不修改账号监控中的“待确认/成本待确认”健康或采购语义；本任务只处理经营总览。
- 不改变普通用户接口、调度、定价、上游成本写入和 `usage_logs` 记录行为。

## 4. 方案比较与选择

### 方案 A：只把前端 pending 文案替换为 0

改动最小，但会掩盖后端收入匹配错误，且分组、趋势和余额仍可能互相矛盾。否决。

### 方案 B：继续依赖额度账本，修复 reference ID 匹配

可以修复新流水，但历史充值不回填仍会导致历史窗口长期处于待确认，且经营页继续被非经营事实源阻塞。否决。

### 方案 C：经营结果统一复用 `usage_logs`，缺失数值按 0（推荐）

收入、成本和毛利直接来自已批准的原生用量事实；账本仅保留为充值/钱包明细来源。历史无账本不再阻断经营结果；真正数据库查询失败仍返回接口错误，不伪装成 0。选择此方案。

## 5. 端到端数据与控制流

1. 管理员请求经营总览，服务解析北京时间范围和可选 `group_id`。
2. 服务查询时间范围内的正常 `usage_logs`，保留不可变 `group_id` 归属；与现有正常用量统计一致，`usage_completeness='unknown'` 的失败尝试不计入经营请求、收入或成本。
3. 每行计算：
   - 收入行值：`COALESCE(actual_cost, 0)`；非有限值按 0 处理。
   - 成本行值：按批准的有效账号成本表达式；所有来源为空、非有限或缺失时按 0 处理。
4. 全站和分组分别累加收入、成本、请求数、模型数；派生毛利和毛利率。
5. 充值现金仅读取当前时间范围内已有的原生充值账本事件；无事件为 0，不读取历史充值推导收入。
6. 消耗趋势直接按 `usage_logs.actual_cost` 按北京时间自然日聚合；无记录的日期补 0。
7. 钱包当前快照仍复用 T55 `user_wallets`；缺少快照行时按 0 展示。账本事件没有历史补查或回填。
8. 只有 SQL/数据库连接/扫描等真实查询错误返回接口错误；“没有行”“没有账本记录”“字段为 NULL”均不进入 pending 状态。

## 6. 接口与字段契约

接口路径保持：`GET /api/v1/admin/operations/business-overview`。

### 6.1 结果字段

- `summary.revenue_cny`、`summary.upstream_cost_cny`、`summary.gross_profit_cny`、`summary.gross_margin` 始终为有限数值。
- `cash_and_balance` 中金额字段始终为有限数值；没有数据为 `0`。
- 趋势每一天都返回一行，充值、实际消耗、净充值均为有限数值。
- 分组 `revenue_cny`、`upstream_cost_cny`、`gross_profit_cny`、`gross_margin` 始终为有限数值；没有流水的分组不凭空创建。
- `preset_margin` 仍可为 `null`，因为它表示可选的调度预设配置，不是经营实际结果；页面显示 `—`，不显示“待配置”。

### 6.2 兼容字段

为避免已部署客户端解析失败，`revenue_status`、`pending_split_count`、`pending_cost_count` 暂时保留在管理员 JSON 中，但固定返回：

- `revenue_status: "confirmed"`
- `pending_split_count: 0`
- `pending_cost_count: 0`

前端类型和页面删除 pending 分支与相关文案；后续可在独立兼容任务中移除这些废弃字段。接口不再发出 `pending`、`pending_split` 或 `unavailable` 作为经营结果状态。

### 6.3 余额核对

`balance_reconciliation.status` 不再返回 `pending`：

- 差额为 0：`balanced`，没有事件时附加说明“本期无变动”。
- 差额非 0：`unbalanced`，保留数值差额和原生调整说明。

## 7. 页面展示契约

- 删除顶部“当前账本或历史额度拆分尚未完整……”提示。
- 删除 `isPending`、`formatMoneyOrPending` 和“口径待确认”文案。
- 金额统一格式化为 `¥0.00` 或实际金额；负毛利保留红色。
- 毛利率为数值 0 时显示 `0.00%`，不显示 `—`。
- 预设倍率缺失显示 `—`，不影响实际毛利和毛利率。
- 充值/余额无数据显示 `¥0.00`；余额核对显示“本期无变动”或“已平衡”。
- 页面不再出现 `待确认`、`口径待确认`、`pending_split`、`pending_cost` 文本。

以截图数据为例，修复后经营结果应显示：站内收入 ¥23.35、上游成本 ¥95.31、毛利 -¥71.96、毛利率 -308.18%；该结果不需要历史充值记录或额度拆分记录。

## 8. 失败、安全与兼容语义

- 数据库查询失败、权限失败、字段扫描失败仍返回现有管理员接口错误，不返回 0，避免把系统故障伪装成经营数据。
- `NULL`、空集合、缺少历史账本记录属于数据缺失，按 0 计算；不得触发 SQL 重试、历史回填或账务写入。
- 继续复用原生管理员鉴权和 `usage_logs` 查询权限；普通用户不能访问该接口。
- 不读取、记录或返回凭据、API Key、请求体或上游敏感响应。

## 9. 兼容性、迁移与回滚

- 无数据库迁移、无配置变更、无生产数据写入、无历史回填。
- T55 表和钱包写入行为保持不变；仅改变经营总览读取和投影。
- 旧客户端仍可解析固定的兼容字段；新前端不依赖这些字段。
- 回滚为恢复上一已验证镜像/蓝绿槽；不需要数据回滚。
- 预期发布预检 `downtime_required=false`；若预检实际返回 `true`，在任何停机、迁移或切换前暂停。

## 10. 场景化验收矩阵

| 场景 | 后端结果 | 页面结果 |
|---|---|---|
| 有消费、有成本、无充值 | 收入/成本/毛利/毛利率均为数值 | 显示真实金额，不出现待确认 |
| 无 usage_logs | 收入、成本、毛利、趋势消费均为 0 | 金额显示 ¥0.00，毛利率 0.00% |
| 有 usage_logs，`actual_cost=0` | 收入 0，成本按有效成本表达式 | 毛利为负成本，毛利率 0.00% |
| 成本字段全部为空 | 该行成本按 0 | 不出现待确认；毛利按收入计算 |
| 无当前充值账本事件 | 现金充值 0，净充值按消费计算 | 显示 ¥0.00，不提示历史缺失 |
| 历史充值未回填 | 不影响收入、毛利或趋势 | 页面无历史拆分提示 |
| 分组无预设倍率 | 实际收入/成本照算，`preset_margin=null` | 预设倍率显示 `—` |
| `usage_completeness=unknown` 失败尝试 | 不计入请求、收入、成本 | 不污染经营统计 |
| 数据库真实查询失败 | HTTP 错误，保留现有错误处理 | 显示“经营总览加载失败” |
