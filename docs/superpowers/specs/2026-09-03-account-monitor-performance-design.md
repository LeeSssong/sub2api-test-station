# 账号监控加载性能与错误恢复设计

## 1. 问题证据

`GET /api/v1/admin/accounts/monitor?range=24h` 当前在一次请求内串行执行多组聚合查询，并在账号循环中逐账号调用模型检测投影。模型检测投影每个账号读取设置、最近 20 条记录并再次读取设置，形成 N+1 查询。生产约 311 个账号时，接口通常耗时 1.2-1.6 秒，偶发达到 19.3 秒；并发读取接口约 9-30 毫秒。`usage_logs`、`ops_error_logs`、`account_monitor_results` 规模持续增长，累计真实请求统计还会扫描全历史。

发布切换期间，Caddy 已出现旧槽位响应被取消并记录 `aborting with incomplete response` / `context canceled`。前端将该类不完整响应统一显示为英文 `Network error`。

## 2. 目标

1. 将账号监控首屏接口 P95 控制在 5 秒内，避免单次慢查询拖垮整页。
2. 消除模型检测投影的逐账号串行等待；保持现有检测语义和字段。
3. 让核心账号卡片先可用，模型检测详情按需或分批补充；单个补充失败不阻断整页。
4. 将超时、发布切换中断、后端 5xx、鉴权失败分别显示中文并提供重试。
5. 保留完整真实请求、探测、评分、利润和调度排序口径，不改变数据事实源。
6. 性能柱状图使用固定阈值：TTFT P95 ≤ 10000 ms 为绿色，> 10000 ms 为黄色；失败桶为红色；无数据为灰色短柱。

## 3. 非目标

- 不修改 `usage_logs`、`ops_error_logs`、账务、调度数学、探测间隔或模型检测算法。
- 不新增第二套质量/利润事实源，不回填历史数据。
- 不在本任务执行主站或验收站发布；完成本地验证后停在发布门禁前。

## 4. 方案与选择

方案 A：仅提高前端超时。实现简单，但掩盖后端 N+1 和大扫描，失败时仍阻塞首屏。弃用。

方案 B：仅把后端查询改并行。可降低墙钟时间，但数据库压力和模型检测 N+1 仍存在，且整页仍被最慢组件阻塞。作为局部手段保留。

方案 C（采用）：先消除已有生产证据确认的模型检测 N+1，对模型检测投影使用固定 worker 池并允许单账号降级；其他大型聚合保持原有顺序，避免未经压测就制造数据库并发尖峰。客户端按错误类型中文化，页面保留已有数据并提供重试。

## 5. 数据与控制流

账号监控服务保持现有聚合顺序；模型检测投影由 8 个 worker 限流并写入结果 map，单账号错误记录日志并保留空投影，不使全页失败。模型检测设置复用同一次已解析结果，移除每账号一次重复读取。

前端请求错误按 Axios 错误属性分类：取消/发布切换显示“请求被中断，请重试”；超时显示“账号监控查询超时，数据库仍在处理或当前负载较高”；5xx 显示“账号监控服务暂时不可用”；401/403 保持会话/权限提示；其他网络错误显示“无法连接账号监控服务”。保留当前数据时只更新错误条，不清空已展示卡片。

## 6. 性能预算与兼容

- 核心接口性能目标：发布后以生产只读日志验证 P95 ≤ 5 秒；本地不伪造生产性能结论。
- 并行度固定为 8 个模型检测 worker；不得为每个账号创建无限 goroutine。
- 所有查询继续使用现有参数化 SQL、索引和官方事实源。
- 无迁移、无配置 schema 变化、无生产数据写入；仅代码行为和前端状态变化。

## 7. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 311 个账号正常加载 | 核心卡片先完成，模型检测补充不阻塞；无 N+1 串行等待 |
| 单账号模型检测读取失败 | 该账号显示稍后加载/无检测数据，其余账号正常 |
| 请求超时 | 显示中文超时原因和重试按钮，已有数据保留 |
| 发布切换中断 | 显示中文“请求被中断，请重试”，不显示英文 network error |
| 后端 5xx | 显示中文服务暂不可用，提供重试 |
| 真实请求柱状图 | ≤10000ms 绿色，>10000ms 黄色，失败红色，无数据灰色短柱 |
| 数据库空表/无账号 | 正常空状态，不报错 |
