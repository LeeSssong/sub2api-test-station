# T98-R3 飞书余额通知确认与静默设计
## 用户批准

2026-09-01，用户批准在 `main` 新建工作区实施“点击后按 BaseURL 静默一段时间”方案。

## 目标

- 飞书余额告警卡片提供 1 小时、6 小时、24 小时静默按钮。
- 静默作用域为现有余额事件的规范化 BaseURL。
- 静默状态持久化在现有 `ops_alert_events` 账本，不新增平行事实源。
- 回调校验飞书回调令牌、接收人身份和卡片作用域令牌。
- 静默期间不创建或发送新的该 BaseURL 余额告警；重复点击幂等。

## 非目标

- 不修改余额快照选择、阈值和排名逻辑。
- 不保存 API Key、登录密码或完整卡片内容。
- 不发送真实飞书消息或调用生产回调。

## 数据流

发送卡片时为每个 BaseURL 生成随机作用域令牌，令牌只进入卡片按钮 value，不落库明文；服务端保存令牌摘要。回调接口校验令牌摘要、配置的回调令牌及接收人 OpenID，再按按钮时长原子更新余额事件的 `silenced_until`，清除投递租约并将下次尝试时间推迟到静默结束。余额恢复时现有 Resolve 流程结束 firing 事件，静默自然失效。

## 兼容与安全

- `silenced_until` 为可空新增字段，旧事件默认未静默。
- 回调令牌从本机 0600 保护文件读取，不写入仓库。
- 数据库只保存令牌摘要和时间，不保存凭据或卡片 payload。

## 验收

- 卡片包含三个静默按钮和作用域令牌值。
- 无效令牌、非接收人和错误时长均拒绝。
- 有效回调更新 `silenced_until`，重复回调保持同一或更晚截止时间。
- claim 在截止前跳过，截止后可重新 claim。
- 直接相关 service/repository/notify/handler 测试及 server build 通过。
