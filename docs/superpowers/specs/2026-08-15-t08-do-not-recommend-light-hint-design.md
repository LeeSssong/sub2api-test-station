## 3. 目标与非目标

### 3.1 目标

1. 保留同行紧凑标签“暂不建议入组”。
2. 默认卡片内容不显示原因正文。
3. 桌面端支持鼠标悬浮、点击和键盘聚焦查看原因。
4. 移动端支持点击查看原因。
5. 原因文案最多一到两行，内容只表达最主要原因。
6. 复用现有 `reason_codes[0]`、推荐对象和本地化兜底。
7. 浮层不被卡片 `overflow-hidden` 裁剪，不遮挡账号名、状态或操作按钮。
8. 缺少推荐对象或原因码异常时保持安全、稳定的旧行为。

### 3.2 非目标

- 不改变推荐算法、评分权重、质量门槛、成本门槛或 7d 证据窗口。
- 不增加、删除或重命名后端 API 字段。
- 不增加推荐历史、详情页、抽屉、模态框或常驻说明区。
- 不自动迁移分组，不修改账号分组、优先级或调度状态。
- 不改变 `recommended`、`observe`、`blocked` 或正式组迁移提示的业务语义。
- 不重构账号卡片其他区域、指标、排序、尺寸或操作按钮。
- 不引入数据库迁移、配置变化、外部控制面、第三方依赖或 GitHub Actions。

## 5. 方案比较与选择

### 方案 A：复用 `HelpTooltip`，增加悬浮/点击触发语义（推荐）

为现有 `HelpTooltip` 增加一个仅用于本功能的组合触发模式，允许：

- 桌面鼠标进入时打开；
- 桌面点击时打开或切换；
- 键盘聚焦时打开；
- 移动端点击时打开；
- 外部点击或 `Escape` 关闭。

`AccountMonitorCard` 只在 `not_recommended` 分支使用该模式，触发器仍显示原标签文本，并附轻量信息图标。

优点：

- 复用项目现有 Teleport、定位、关闭和可访问性基础设施；
- 只改变局部渲染分支和共享 Tooltip 的触发合同；
- 不复制桌面/移动两套 DOM；
- 能严格保持卡片同行布局。

代价：

- 需要为 `HelpTooltip` 增加组合触发单元测试；
- 需要确认 hover 与 click 状态在触屏环境下不会互相抖动。

### 方案 B：新增 T08 专用 Teleport 浮层

在账号卡片内手动维护可见状态、触发事件、定位、边界翻转和关闭逻辑。

优点：

- 可完全控制 T08 的文案尺寸和响应式定位。

代价：

- 重复已有 Tooltip 能力；
- 增加滚动、resize、触屏、焦点和层级的实现风险；
- 变化面超过“轻提示”任务的必要范围。

### 方案 C：只使用原生 `title` 和 `aria-label`

保留紧凑标签，在标签上补充浏览器原生 title。

优点：

- 改动最少。

代价：

- 移动端没有稳定的点击查看体验；
- 无法统一控制一到两行的原因展示；
- 无法保证浮层不被卡片容器裁剪。

### 选择

选择方案 A。它与既有项目组件最一致，能够覆盖桌面悬浮/点击、移动点击和键盘访问，同时把 T08 的实现边界限制在提示交互，不触碰推荐决策和卡片布局。

## 6. 端到端数据与控制流

1. 后端按现有推荐逻辑生成可选 `group_recommendation`。
2. 账号监控页面将账号对象传给 `AccountMonitorCard`。
3. 卡片判断推荐对象是否存在且 `status === "not_recommended"`。
4. 卡片从 `reason_codes[0]` 读取首要原因码，并使用现有本地化原因映射。
5. 卡片默认只渲染紧凑标签，不渲染原因正文。
6. 用户在桌面悬浮、桌面点击、键盘聚焦或移动端点击触发器。
7. `HelpTooltip` 将短原因 Teleport 到 `body` 并定位到触发器附近。
8. 用户离开 hover 区域、点击外部或按 `Escape` 后浮层关闭。
9. 账号刷新或推荐对象变化时，卡片按新对象重新决定是否显示 T08 提示；不持久化任何客户端状态。

## 7. 接口与字段契约

T08 不改变现有接口。继续使用：

```ts
interface AccountMonitorGroupRecommendation {
  status: 'recommended' | 'observe' | 'blocked' | 'not_recommended' | string
  target: string
  target_name: string
  action: 'keep' | 'migrate' | 'hold' | 'none' | string
  reason_codes: string[]
  sample_count: number
  observed_at: string
  source: 'monitor_probe' | string
}
```

T08 的前端解释契约：

- 首要原因只取 `reason_codes[0]`；
- 已知原因码复用当前中文短语；
- 未知、缺失或空原因码统一回退到“主动探测质量不满足目标”；
- `not_recommended` 原因提示不显示推荐目标、样本数、观测时间或长段证据；
- 原因提示内容必须在视觉上最多占一到两行；
- 其他状态继续使用既有标签和 Tooltip 文案契约。

建议的 T08 触发器语义名为 `hover-click`，具体实现可通过扩展 `HelpTooltip` 的 `trigger` 联合类型完成。该名称是组件内部实现合同，不是后端 API 字段，也不改变现有 `hover`/`click` 调用方语义。

## 8. 视觉与交互规格

### 8.1 卡片默认状态

- 继续显示“暂不建议入组”紧凑标签；
- 标签仍位于“平台 / 当前分组 / 调度状态”同行；
- 不显示“原因：……”常驻文本；
- 不新增行、区块、卡片或说明面板；
- 标签颜色可继续使用现有 `not_recommended` 红色语义，不把 T08 误解为新的业务状态。

### 8.2 触发器

- 使用原标签文本作为按钮可见名称；
- 附现有图标组件的信息提示图标；
- 保留 `title` 和 `aria-label`，其中可包含完整短原因；
- 保留 `focus-visible` 可见焦点环；
- 触发器尺寸不改变 header 的现有 flex 约束。

### 8.3 浮层

- 通过 `Teleport` 渲染到 `body`；
- 使用现有 Tooltip 层级与主题；
- 宽度使用视口安全上限，例如 `min(16rem, calc(100vw - 1.5rem))`；
- 文案使用短句和正常换行，最多一到两行；
- 不在 T08 浮层中放置按钮、迁移动作、指标表格或长证据；
- 超出视口时应限制在视口内，不允许横向滚动。

## 9. 失败、安全与可访问性语义

- 推荐对象为空时不创建触发器，不影响整张卡片。
- 原因码映射失败时使用固定兜底，不把原始错误、凭据、请求体或上游响应暴露到 UI。
- Tooltip 事件异常不得阻塞账号监控列表渲染。
- 触发器必须可通过键盘 Tab 到达，并通过 `aria-label` 说明“暂不建议入组”和主要原因。
- `Escape` 关闭后焦点仍留在触发器或返回触发器，不跳转到页面其他位置。
- 外部点击关闭不能误触发账号卡片的编辑、删除、更多等操作。
- 浮层使用 `role="tooltip"`；若实现需要额外关联，应通过稳定 ID 建立 `aria-describedby`，不得依赖不可见长文本。
- 不引入新的用户权限、管理权限或服务端数据读取。

## 10. 兼容性与迁移

- 无数据库迁移。
- 无后端 schema 版本变更。
- 无配置、依赖、权限、路由或部署拓扑变化。
- 老接口缺少 `group_recommendation` 时保持兼容。
- 旧客户端忽略推荐对象时不受影响。
- 现有 `HelpTooltip` 的 `hover` 和 `click` 调用方行为必须保持不变；新增组合触发只供 T08 使用。
- 不需要历史数据回填、缓存清理或客户端存储迁移。
