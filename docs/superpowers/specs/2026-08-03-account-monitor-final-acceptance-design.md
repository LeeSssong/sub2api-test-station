# 账号监控最终验收设计

## 目标

以 `/admin/accounts/monitor` 作为账号服务、经营、账务和后续飞书联动的唯一运营入口，修复当前生产验收发现的分组、评分、卡片、渠道监控和账务交互问题。

## 已确认口径

- 分组 Tab 只来自 `/admin/groups` 的未删除正式分组，顺序与名称保持一致。
- 桌面账号卡片每行最多两张，移动端一张。
- 今日调用默认收起，以按钮点击展开；不能只依赖鼠标悬停。
- 页面评分显示整数，排序保留后端原始精度。
- 倍率上限是硬门槛；通过门槛后按分组权重计算质量分。
- 成功率直接按比例计分；TTFT P50 与总耗时 P95 按分组目标值到分组上限线性衰减，不能共用固定 1000ms 截止值。
- 最近五分钟真实请求优先；样本不足时参考近期主动探测。页面使用“本组数据不足，参考近期探测”等普通中文。
- “纸面利润”统一显示为“账号利润”。
- 组内评分、排名和调度优先级是辅助信息，不能压过服务指标、探测证据和经营数据。
- 账号卡片与渠道监控使用一致的探测柱语义：成功绿色、失败红色、无数据灰色；柱高表示响应速度差异。
- 各指标显示自己的样本数，不用总样本数冒充 TTFT 或总耗时样本数。
- 渠道监控的时间柱改用真实探测结果；探测成功始终是绿色。
- 账务 API 只开放 `/relay-ops/api/reconciliation/*`，不得重新暴露 relay-ops 自建页面。

## 卡片层级

1. 账号名称、平台、管理状态和服务状态。
2. 成功率、TTFT P50、总耗时 P95、倍率；每项显示对应样本数。
3. 全宽近期探测柱状图。
4. 弱化辅助行：组内评分、排名、数据来源。
5. 经营区：上游真实扣费、用户实际计费、账号利润、对账状态。
6. 今日调用摘要，点击展开完整请求、Token 和金额明细。
7. 底部调度优先级，点击编辑图标后才出现输入控件。

## 交互验收矩阵

- 全部刷新：账号监控刷新与账务刷新分别返回结果，部分成功必须明确提示。
- 历史按日、本组历史：返回 JSON 并可打开、关闭、切换日期。
- 异常明细：返回 JSON，空状态与异常列表均不崩溃。
- 补登记：可从异常记录进入，提交后刷新经营数据。
- 监控设置、评分权重、恢复默认、账号刷新、账号历史、优先级编辑逐项执行。
- API 返回 HTML 或结构错误时显式显示中文错误，不能静默展示 0、破折号或待对账。

## 验收门禁

- 后端公式精确值、分组软删除、各指标样本数、批量时间线和独立错误口径测试。
- 前端两列响应式、整数评分、折叠交互、柱状图、中文文案和全部按钮测试。
- Caddy 精确路由正向测试与 relay-ops 自建页面不可达的负向测试。
- 生产管理员会话逐项点击；桌面与移动端截图；页面无业务 console/runtime error。
