# 管理员隔离测试站规格说明书

**任务编号：** T53  
**日期：** 2026-08-22  
**状态：** APPROVED，进入实施计划阶段；尚未开发或部署
**范围：** 在当前域名下挂载一个仅管理员可见、完全隔离生产数据与外部副作用的 Sub2API 测试站，用于后续额度账本与经营分析功能验证。

## 1. 问题与背景

当前生产站已经承载真实用户、真实余额、真实支付、真实上游账号和生产运维链。额度账本与经营分析会涉及充值、付费额度、赠送额度、流式预占、技术透支、退款清除赠送额度和经营聚合，直接在生产站开发或验证会带来余额误扣、账务污染、支付回调误处理和上游请求外泄风险。

本任务先建设一个测试站：

- 复用当前网站的代码、页面结构和管理员体验；
- 使用当前域名的独立路径挂载；
- 使用独立测试服务栈和独立认证会话；
- 不迁移任何生产业务数据；
- 不连接生产支付、生产上游、生产通知或生产对象存储；
- 仅允许测试管理员访问；
- 通过脱敏、人工构造的种子数据验证后续功能。

## 2. 目标

### 2.1 必须实现

1. 当前域名下提供独立测试路径，建议为 `/admin/lab/`。
2. 测试路径路由到独立测试前端/API，不与生产 API 路由混用。
3. 测试站使用独立 PostgreSQL、Redis、Cookie、管理员账号和配置。
4. 测试站禁止访问生产数据库、生产 Redis、生产支付渠道、生产上游账号、生产通知和生产文件存储。
5. 普通用户不能发现、访问或调用测试站页面和 API。
6. 测试站可运行完整管理员功能，并为后续额度账本功能提供可重复的种子数据和 Mock 依赖。
7. 测试站可以一键重置到干净状态，重置只影响测试资源。
8. 测试站具备明确的停用和回滚方式，停用不得影响生产站。

### 2.2 非目标

- 不迁移、复制或回填任何生产用户、生产订单、生产余额、生产 usage logs、生产账号或生产密钥。
- 不复用生产管理员 Cookie，不共享生产 session secret。
- 不连接真实支付网关，不接收真实支付回调。
- 不调用生产上游，不使用生产 API Key、OAuth 凭据、Base URL 或代理凭据。
- 不在本任务实现额度账本、充值包、经营分析或流式预占业务；这些属于后续独立规格。
- 不把测试站作为生产灰度、线上影子流量或真实用户入口。
- 不创建 GitHub Actions 发布链；继续使用项目现有本地/宿主发布链（若未来批准部署）。

## 3. 方案比较与选择

### 方案 A：当前域名独立路径 + 独立服务栈（推荐）

```text
https://<current-domain>/admin/lab/
```

该路径由反向代理转发到测试前端/测试 API；测试服务使用独立数据库、Redis、Cookie 和管理员账号。生产路径保持原样。

**优点：** 满足当前域名要求；生产与测试边界清晰；可复用页面和管理员工作流；停用只需移除测试路径路由。  
**缺点：** 需要处理同域名 Cookie、静态资源 base path、SSE/WebSocket、API 前缀和缓存键隔离。

### 方案 B：测试子域名

```text
https://lab.<current-domain>/
```

**优点：** Cookie、静态资源和路由天然隔离。  
**缺点：** 需要 DNS/TLS 和额外域名配置，不符合“使用现在的域名挂载”的首选体验。

### 方案 C：生产服务内增加 lab mode

生产服务通过配置切换测试数据库或测试页面。

**不采用原因：** 一旦配置、连接串或环境变量错误，可能让生产进程连接测试库或让测试写入生产；无法形成足够强的运行时隔离。

**选择：** 方案 A。

## 4. 目标架构

```text
当前域名
├── /api/...             -> 生产 API
├── /admin/...           -> 生产前端/管理员页面
└── /admin/lab/...       -> 测试前端（独立构建，base=/admin/lab/）
                           ↓
                         测试 API（独立进程/容器）
                           ├── 测试 PostgreSQL
                           ├── 测试 Redis
                           ├── 测试文件存储（本地临时卷或 MinIO test bucket）
                           ├── Mock 支付适配器
                           └── Mock 上游适配器
```

### 4.1 服务身份

测试 API、测试 worker、测试前端和测试依赖必须具有独立服务身份。测试服务不得使用生产 Compose service name、生产容器网络别名或生产持久化卷。

### 4.2 测试数据库

- 单独的 PostgreSQL 数据库和 schema，名称建议 `sub2api_lab`。
- 连接串只允许来自测试 API/worker。
- 测试迁移从当前代码的迁移集合初始化，不从生产数据库导出。
- 每次 reset 只能删除并重建测试数据库，禁止出现生产连接串。
- 数据库账号必须与生产账号不同。

### 4.3 测试 Redis

- 单独 Redis 实例或独立 database/index，优先使用独立实例。
- 测试 Cookie/session、缓存、队列和锁不得进入生产 Redis。
- reset 时清理测试 Redis，不得执行无前缀全库清理。

### 4.4 测试文件与密钥

- 测试站使用独立临时文件卷或测试 bucket。
- 种子数据不得包含生产 API Key、OAuth refresh token、支付密钥、Webhook secret、SMTP 凭据或代理凭据。
- 测试环境使用固定标记为 `LAB_ONLY` 的假凭据；Mock 依赖必须拒绝真实外部地址。

## 5. 路由与前端契约

### 5.1 路径

首选路径：

```text
/admin/lab/
/admin/lab/api/...
/admin/lab/assets/...
```

测试 API 不得占用生产 `/api/v1/...` 路由。若内部 API 仍使用 `/api/v1/...` 形式，反向代理必须在外层增加不可混淆的 `/admin/lab/api/` 前缀，并在测试 API 内剥离前缀。

### 5.2 Cookie

生产和测试必须使用不同 Cookie 名称，例如：

```text
生产：sub2api_prod_session
测试：sub2api_lab_session
```

测试 session secret、CSRF secret 和刷新令牌签名密钥必须独立。测试 Cookie 的 `Path` 限定为 `/admin/lab`，不得设置为 `/`。

### 5.3 前端构建

- 测试前端的 Vite base path 固定为 `/admin/lab/`。
- 所有静态资源、路由、API 请求和 WebSocket/SSE URL 必须通过 base path 生成。
- 生产前端不得渲染测试入口；测试入口不写入生产导航配置。
- 测试站页面可以完整显示管理员功能，但所有写操作只写测试 API。

## 6. 认证与访问控制

### 6.1 测试管理员

测试站使用独立测试管理员账号，不复用生产管理员账号或生产登录会话。测试管理员凭据只能通过本地/宿主安全变量注入，不提交到仓库。

### 6.2 双层访问控制

**反向代理层：**

- 只允许 `/admin/lab/` 路径进入测试服务；
- 可配置额外 Basic Auth、IP allowlist 或宿主内网入口；
- 非允许请求不应转发到测试 API。

**应用层：**

- 所有测试 API 强制要求有效 `sub2api_lab_session`；
- 角色必须为 `admin`；
- 普通用户、未登录用户和生产 session 均返回 401/403；
- 测试 API 不接受生产 JWT、生产 Cookie 或生产刷新令牌。

### 6.3 防止“只隐藏菜单”假隔离

验收必须直接请求页面、API、SSE 和 WebSocket 路径，确认普通用户不能通过猜路径、复用生产会话或修改请求头访问测试站。

## 7. 外部副作用隔离

测试服务默认采用 fail-closed：

- 支付 provider 只允许 `mock`；真实 provider 配置缺失时启动失败或请求拒绝；
- 上游请求只允许 `mock-upstream` 或本地录制响应；真实 HTTP 出站默认阻断；
- 邮件、飞书、Webhook、短信等通知只写测试 outbox 或日志，不发送外部消息；
- 文件上传只写测试临时卷；
- DNS/HTTP 出站 allowlist 不包含生产上游、支付和通知域名。

## 8. 测试数据种子

“不迁移生产数据”不等于空站。测试站必须通过版本化种子脚本创建脱敏、可重复的数据。

### 8.1 最小种子集合

1. 测试管理员账号。
2. 测试用户 A：付费额度 100Q、赠送额度 20Q。
3. 测试用户 B：仅赠送额度 10Q。
4. 测试用户 C：待补缴额度 0.40Q。
5. 测试用户 D：模拟上线时旧余额转为付费额度 50Q。
6. 至少两个测试分组和三个测试模型。
7. 正常、失败、流式中断、跨付费/赠送额度的测试 usage log。
8. 成功、失败、退款预留状态的测试支付订单。
9. 测试充值包和手工充值记录。
10. 测试账号有效成本样本和无成本/待确认样本。

### 8.2 种子要求

- 种子脚本幂等，可重复运行；
- 每条记录带 `LAB_ONLY` 标识或等价测试来源标识；
- 不使用生产 ID、生产邮箱、真实域名凭据或生产请求 ID；
- reset 后可以从零重建同一场景；
- 种子数据覆盖后续额度账本验收矩阵，而不是只做页面占位。

## 9. 测试站生命周期

### 9.1 启动

启动顺序：

1. 校验所有连接串和外部 endpoint 都是测试值；
2. 启动测试 PostgreSQL/Redis；
3. 应用测试迁移；
4. 启动测试 API/worker；
5. 执行种子脚本；
6. 启动测试前端；
7. 注册 `/admin/lab/` 路由；
8. 执行健康、认证和副作用阻断检查。

### 9.2 重置

reset 只能作用于测试资源，必须输出：

- 测试数据库标识；
- 测试 Redis 标识；
- 种子版本；
- reset 时间；
- 执行结果。

reset 不得访问生产数据库，不得清理共享 Redis，不得修改生产配置。

### 9.3 停用与回滚

停用顺序：

1. 移除 `/admin/lab/` 反向代理路由；
2. 停止测试前端/API/worker；
3. 保留或销毁测试数据库按明确操作执行；
4. 验证生产 `/admin/`、`/api/`、SSE/WebSocket 路由不受影响。

回滚不需要恢复生产数据；恢复生产路由配置即可。

## 10. 安全与故障语义

- 测试站任何生产连接串、生产 token、Authorization、Cookie 和真实上游 URL 进入日志都视为阻断问题。
- 测试站无法确认当前连接是否为测试资源时，必须 fail-closed，不允许继续启动。
- 测试站 API 错误不得被生产错误监控或生产通知链发送出去；测试错误写入隔离日志。
- 测试数据删除、reset 和 mock 账务动作必须留有测试审计记录。
- 测试站不承诺生产可用性，不承接真实用户流量，不作为生产灰度入口。

## 11. 兼容性与迁移

- 不迁移生产数据库数据。
- 不修改生产 schema、生产配置或生产数据。
- 测试数据库使用当前代码迁移集合初始化；后续额度账本迁移先在测试站执行。
- 测试站的数据库和 Redis 命名、网络、卷、凭据与生产保持可审计区分。

## 12. 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 管理员访问 `/admin/lab/` | 进入测试站，使用测试 Cookie |
| 普通用户访问 `/admin/lab/` | 401/403/404，不显示测试页面 |
| 生产 Cookie 访问测试 API | 被拒绝，不创建测试 session |
| 测试管理员执行写操作 | 只影响测试数据库和测试 Redis |
| 测试站 reset | 只删除/重建测试资源，种子可重复恢复 |
| 支付操作 | 仅命中 mock provider，不产生真实支付请求 |
| 上游调用 | 仅命中 mock/录制响应，真实出站为 0 |
| 通知触发 | 只写测试 outbox/日志，不发外部消息 |
| 测试站关闭 | 生产页面、API、SSE/WebSocket 继续正常 |
| 搜索生产数据 | 测试站无生产用户、订单、余额和 usage log |
| 生产数据写入检查 | 测试站全流程不产生生产写入 |
| 日志敏感信息扫描 | 无生产凭据、生产 Cookie、真实 API Key 或生产 URL |

## 13. 测试策略

### 直接相关自动化验证

- 反向代理路径和 upstream 路由合同测试；
- 前端 base path、资源 URL 和 API 前缀测试；
- Cookie Path/Name/secret 隔离测试；
- 测试 API 角色鉴权和生产 session 拒绝测试；
- Compose/env 合同测试，阻断生产连接串和真实外部 endpoint；
- 种子脚本幂等和 reset 隔离测试；
- mock 支付、mock 上游、通知 outbox 的出站阻断测试；
- 测试站登录、管理员页面和关键写操作 smoke；
- 生产路由回归检查。

### 不在本任务执行

- 额度账本业务正确性测试；
- 经营分析数学和毛利口径测试；
- 真实支付、真实上游或生产数据验收；
- 压力、长时间 soak 和跨平台穷举。

## 14. 发布、停机与回滚条件

- 本规格阶段不部署、不修改生产。
- 后续若部署到宿主，必须由根发布总控从验证后的 `main` 执行。
- 预检明确 `downtime_required=false` 时，可按现有规则继续无停机路径；若为 `true`，必须在任何停服、迁移、重启或切换前暂停并取得授权。
- 测试站首次挂载当前域名可能涉及 Caddy/反向代理路由变化；若宿主判断需要停机，必须停止在门禁前。
- 回滚优先移除测试路径路由并停止测试栈，不回滚或覆盖生产数据。

## 15. 未决事项与默认决策

| 事项 | 默认决策 | 是否阻塞本规格 |
|---|---|---:|
| 测试路径 | `/admin/lab/` | 否 |
| 测试管理员 | 独立测试管理员账号 | 否 |
| 生产管理员复用 | 不复用生产 session | 否 |
| 数据来源 | 版本化脱敏种子，不迁移生产数据 | 否 |
| 外部支付/上游 | Mock/录制响应，真实出站阻断 | 否 |
| 测试站是否长期保留 | 先支持可启动、可 reset、可停用；保留周期后续决定 | 否 |
| 是否显示生产站入口 | 不显示；测试站提供显式“测试环境”标识 | 否 |
| 测试域名证书 | 继续使用当前域名现有 TLS 入口 | 否，需发布预检确认宿主能力 |

## 16. Done-when

本规格对应的测试站任务只有同时满足以下条件才算完成：

1. `/admin/lab/` 能访问测试站；
2. 仅测试管理员可以进入；
3. 测试 API、数据库、Redis、Cookie 和密钥均与生产隔离；
4. 种子脚本可重复生成测试场景；
5. 支付、上游、通知真实出站均被阻断；
6. 测试写操作不产生生产写入；
7. reset、停用、回滚和生产路由回归验证通过；
8. 直接相关测试、必要构建/类型检查、发布预检和线上（或宿主测试环境）专项验证完成。
