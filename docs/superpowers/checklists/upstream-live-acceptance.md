# UP01 真实环境验收清单

**执行时机：** 用户审阅完整报告、完成必要资产操作并明确开始真实联调之后。  
**当前状态：** 延后，尚未执行。  
**凭据规则：** 证据只记录时间、请求 ID、状态码、模型、Token/费用和结论，不记录完整 Key、Cookie、OAuth Token、Prompt 或支付密钥。

## A. 前置门禁

- [ ] `UP01.local.yaml` 普通校验和 `--live-ready` 校验均通过。
- [ ] 上游余额、价格、最低充值和退款规则已重新核对；本清单不执行充值。
- [ ] 再分发状态不是 `prohibited`；若为 `unknown`，风险已经登记且渠道可快速停用。
- [ ] Base URL 符合当前 URL 策略，没有 URL 用户信息、查询串或片段；若启用 allowlist，host 已加入 `SECURITY_URL_ALLOWLIST_UPSTREAM_HOSTS`。
- [ ] 真实 Key 已直接进入 Sub2API 管理界面或受控密钥存储，未进入文件或聊天。
- [ ] 账号使用独立名称和分组，初始并发不超过 2，模型只开放已核对白名单。

## B. 协议与模型

- [ ] 管理员账号测试成功，记录延迟和上游请求 ID（如有）。
- [ ] `/models` 或供应商等价能力只返回预期模型；不同则更新白名单，不自动全量放开。
- [ ] 最小非流式请求成功，模型名和响应格式正确。
- [ ] 最小流式请求持续返回数据，首字时间和结束事件正常，无代理缓冲。
- [ ] 主客户端需要 Responses API 时，单独验证 `/responses`；需要 tools 时，至少完成一次工具调用回合。
- [ ] 外部模型名与上游模型名不同时，日志能看到预期映射且没有误改其他请求字段。

## C. 错误与重试

- [ ] 使用临时无效凭据验证 401/403，不覆盖或泄露真实 Key。
- [ ] 请求一个明确不存在的模型，错误可定位且不被伪装成成功响应。
- [ ] 在供应商沙箱、测试开关或自然发生时验证 429；不通过高并发消耗余额强行制造。
- [ ] 记录 `Retry-After`、恢复时间和一次请求实际重试次数。
- [ ] 只有在确认重试不会重复计费后才开启 pool mode；最大重试保持 1。
- [ ] 上游 5xx 无安全复现方式时标记“未验证”，不得为完成清单故意攻击上游。

## D. 中断、日志和密钥

- [ ] 客户端主动中断流式请求后，上游连接在合理时间内取消或结束。
- [ ] 中断请求的本站扣费与上游扣费结果已记录，差异可解释。
- [ ] 站内请求 ID 可关联用户、Key 摘要、模型、账号和上游请求 ID。
- [ ] 日志包含状态码、首字时间、总时间、Token、重试和错误类型。
- [ ] 日志、错误页、导出和截图中没有完整用户 Key、上游 Key或默认完整 Prompt。
- [ ] Key 轮换后旧 Key 失效，账号可单独停用且不影响其他渠道。

## E. 用量与计费

- [ ] 至少三笔小额请求逐笔比较本站 usage、本站扣费和上游用量/余额变化。
- [ ] 输入、输出、缓存读取/写入和推理 Token 的处理与价格表一致。
- [ ] `rate_multiplier` 只按账号成本统计用途配置，未当作用户售价。
- [ ] 单用户、单 Key 和上游日成本上限已有实际执行位置；只有台账记录时不得勾选。
- [ ] 余额告警在低于设定阈值时能通知到唯一负责人。
- [ ] 未发生真实客户收款；人工账本和支付仍只处于模拟状态，除非后续另行授权。

## F. 通过标准与证据

以下条件全部成立才将 UP01 标记为“已验证”：

- [ ] 非流式和流式请求成功，主客户端必需能力通过。
- [ ] 白名单、并发和错误处理符合预期，没有无法解释的重复请求。
- [ ] 至少三笔用量和成本差异可解释。
- [ ] 密钥和 Prompt 未进入日志或报告。
- [ ] 已知限制和未验证项已写入资产台账，渠道可以一键停用。
