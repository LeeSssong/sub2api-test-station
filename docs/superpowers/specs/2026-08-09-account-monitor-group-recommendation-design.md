# 账号监控卡片“推荐分组”设计

## 目标

为账号监控卡片增加一个低侵入的只读“推荐分组”字段，建立新 GPT 文本上游从测试组观察到人工迁入正式组的持续运营闭环：

1. 新账号先进入 `GPT-测试分组`。
2. 既有账号监控原生定时探测持续产生质量证据。
3. 后端基于最新主动探测、成本与账号状态派生推荐结果。
4. 管理员在账号卡片看到推荐后，继续使用现有分组编辑能力人工迁移。

系统不得自动修改账号分组、优先级或调度状态。

## 范围

### 纳入

- `GPT-测试分组` 内的 GPT/OpenAI 文本账号。
- `GPT-Pro`、`【专属】GPT-Pro`、`GPT-Plus`、`GPT-特惠` 内能够正常调度的 GPT/OpenAI 文本账号。
- 分类为 `Codex Auth` 的自购账号。

### 排除

- 生图账号和生图分组。
- Claude 账号和 Claude 分组。
- 自测分组作为推荐目标。
- 正式组内暂停、禁用或不可调度账号的迁移分析。
- 自动迁移、自动修改优先级、调度器改造和推荐历史页面。

## 核心原则

1. **主动探测是唯一质量来源。** 推荐成功率、TTFT 和完整响应延迟不得被真实请求数据覆盖。
2. **实时派生，不持久化第二份状态。** 原生监控定时任务只负责刷新探测结果；账号监控投影按最新证据确定性计算推荐结果。
3. **利润和硬故障先于质量分。** 成本不满足目标组利润下限，或存在认证、余额、配额、模型不可用等硬故障时，不得给出可立即迁入的建议。
4. **人工迁移。** 推荐结果仅供管理员判断，不增加自动迁移按钮或后台写分组任务。
5. **最小视觉侵入。** 不新增卡片区块，不移动现有评分、指标、成本、探测和调用区域。

## 推荐目标

推荐档位只有：

- `GPT-Pro`
- `GPT-Plus`
- `GPT-特惠`
- 无正式组推荐

`GPT-Pro` 与 `【专属】GPT-Pro` 是同一质量池。推荐为 `GPT-Pro` 时，运营含义是公开 Pro 与专属 Pro 应保持相同账号池；不得把专属 Pro 作为独立质量档位。

目标组通过稳定的规范名称映射识别，不硬编码生产数据库 ID。

## 推荐计算

### 证据窗口

- 推荐结果固定使用滚动 `7d` 主动探测窗口，与账号监控页当前选择的 `24h`、`7d` 或 `30d` 展示筛选解耦，避免管理员切换页面窗口时推荐结论跳变。
- 卡片 Tooltip 必须明确标注推荐基于 `7d` 主动探测；当前页面选择的其他窗口仍只影响原有指标展示。
- 返回主动探测样本数、最后观测时间和固定证据源 `monitor_probe`。

### 通用判定顺序

1. 判断是否属于 GPT/OpenAI 文本账号及受支持分组范围。
2. 判断账号管理状态、调度状态及最新硬故障。
3. 判断主动探测样本是否达到最低门槛。
4. 判断账号成本是否满足目标分组利润下限。
5. 根据各分组现有成功率要求、TTFT/完整响应目标与上限判断可承载档位；超过目标值只影响现有加权分，超过配置上限才阻断该档位。
6. 对普通 GPT 文本账号按 `GPT-Pro > GPT-Plus > GPT-特惠` 选择满足条件的最高档位。
7. 使用目标分组现有评分权重生成解释和组内质量依据，但不修改原有组内评分结果或排序。

利润下限沿用已确认运营政策：

| 目标组 | 最低利润 |
| --- | ---: |
| GPT-Pro | `0.05x` |
| GPT-Plus | `0.05x` |
| GPT-特惠 | `0.02x` |
| 【专属】GPT-Pro | `0.02x` |

首期质量门槛沿用已形成的 GPT 分组基线：最低有效主动探测样本数为 20；成功率基线为 Pro 98%、Plus 95%、特惠 70%；TTFT 和完整响应使用各目标组当前评分配置中的目标值和上限。推荐逻辑不得改变现有评分权重配置。

### Codex Auth 自购账号

- 正常且具备可用探测证据时，默认推荐 `GPT-Pro`，运营上同时进入公开 Pro 与专属 Pro。
- 位于测试组且存在认证、余额、配额、模型或持续探测异常时，仍保留 Pro 目标语义，但状态为暂缓迁入并展示原因。
- 已位于正式 Pro/专属 Pro 时，异常继续由现有账号状态展示；推荐字段不额外输出“继续观察”或“暂缓”提示。

## 正式组与测试组的不同语义

### GPT-测试分组

测试组始终允许展示推荐字段：

- 达到正式组要求：`推荐：GPT-Pro/Plus/特惠`
- 样本不足：`继续观察`
- 存在硬故障：`暂缓迁入`
- 有充分证据但没有正式组满足：`暂不建议入组`

提示必须包含一个最主要原因；Tooltip 可补充样本数、观测时间和其他原因。

### 正式分组

正式组只对能够正常调度的账号分析，并采用保守提示规则：

- 只有明确识别出另一个正式推荐档位时，才返回迁移提示并显示叹号。
- 未识别出其他正式推荐档位时，一律视为仍符合当前分组，不显示“继续观察”“暂不建议”“暂缓迁入”等推荐状态。
- 当前属于公开 Pro 或专属 Pro、且推荐档位为 Pro 时视为匹配。
- 正式组迁移提示不自动修改当前分组。

## 接口设计

在现有 `AccountMonitorAccount` 投影增加一个可选的嵌套对象，避免散落多个顶层字段：

```json
{
  "group_recommendation": {
    "status": "recommended",
    "target": "gpt_plus",
    "target_name": "GPT-Plus",
    "action": "migrate",
    "reason_codes": ["success_rate_below_pro"],
    "sample_count": 132,
    "observed_at": "2026-08-09T10:15:42Z",
    "source": "monitor_probe"
  }
}
```

字段约束：

- `status`：`recommended`、`observe`、`blocked`、`not_recommended`。
- `target`：`gpt_pro`、`gpt_plus`、`gpt_special` 或空。
- `action`：`keep`、`migrate`、`hold` 或 `none`。
- `reason_codes`：稳定的机器可读原因码，第一项是主要原因；前端只负责把原因码和既有数值字段映射为本地化简短文案，不在前端重算推荐规则。
- `sample_count`、`observed_at`、`source`：推荐证据元数据。
- 正式组没有明确迁移目标时，整个 `group_recommendation` 为空。
- 字段必须可选；旧数据或异常响应缺少该对象时，前端完全保持原卡片行为。

首期原因码至少覆盖：

- `sample_insufficient`
- `profit_below_minimum`
- `success_rate_below_pro`
- `success_rate_below_plus`
- `success_rate_below_special`
- `ttft_exceeds_target`
- `latency_exceeds_limit`
- `auth_failed`
- `balance_unavailable`
- `quota_unavailable`
- `model_unavailable`
- `codex_auth_default_pro`

## 卡片交互

推荐字段直接追加到现有“平台 / 当前分组 / 调度状态”同行信息中：

```text
OpenAI / 当前分组：GPT-测试分组 / 可调度 / 推荐：GPT-Pro
```

交互规则：

- 不增加新的上下区块或指标单元，不移动现有卡片内容。
- 桌面端尽量保持同行；窄屏沿用现有换行能力。
- 测试组显示推荐值或观察/阻断状态。
- 正式组只有明确推荐迁移到另一档位时追加 `推荐：目标组` 和叹号。
- 叹号复用现有 `HelpTooltip` 组件，鼠标悬停和键盘聚焦均可读取。
- Tooltip 文案格式为：`推荐迁移至 ×× 分组：简短原因`，并附 `7d` 主动探测样本数和观测时间。
- 不增加自动迁移按钮。

## 错误与降级

- 推荐计算失败不得导致账号监控列表失败；单个账号推荐对象为空并记录可观测错误。
- 分组评分配置缺失时使用现有标准化默认值，但不得猜测成本或利润。
- 主动探测证据缺失或过期时，测试组显示继续观察；正式组保持无推荐提示。
- 目标分组不存在、被删除或停用时，不返回迁移建议。
- 成本证据不可用时，测试组显示暂缓迁入；正式组不产生迁移提示。

## 测试要求

### 后端

- 普通 GPT 测试组账号能按 Pro、Plus、特惠顺序选择最高合格档位。
- 利润、样本、成功率、TTFT、完整响应和硬故障门槛分别有边界测试。
- Codex Auth 正常时默认 Pro，异常测试组账号返回暂缓迁入。
- Pro 与专属 Pro 被视为同一档位。
- 正式组不可调度账号不计算推荐。
- 正式组无明确其他目标时推荐对象为空。
- 生图、Claude 和不支持的分组不返回推荐。
- 单账号推荐计算失败不破坏整个监控投影。

### 前端

- 推荐字段与现有状态同行，不新增卡片区块。
- 测试组的推荐、继续观察、暂缓迁入和暂不建议状态正确显示。
- 正式组仅在明确迁移时显示推荐字段和叹号。
- Tooltip 支持悬停和键盘聚焦，并显示由原因码生成的本地化简短文案。
- 缺少推荐对象时卡片 DOM 与现有行为保持兼容。
- 窄屏可自然换行且不遮挡状态、名称或操作按钮。

## 验收标准

1. 新 GPT 文本账号放入 `GPT-测试分组` 后，积累主动探测样本即可在卡片同行位置看到推荐结果。
2. 推荐结果只使用主动探测作为质量证据。
3. 正式组可调度账号只有在明确应迁移到其他正式档位时出现叹号。
4. Codex Auth 正常账号默认推荐公开 Pro 与专属 Pro；异常测试组账号不会被提示立即迁入。
5. 生图、Claude、正式组不可调度账号不受影响。
6. 推荐结果不自动修改分组、优先级或调度状态。
7. 现有账号卡片布局、指标顺序和高度结构没有新增区块。

## 非目标

- 推荐主力、次级、备用或自动修改全局优先级。
- 保存推荐历史或提供推荐趋势页面。
- 把真实请求混入推荐质量证据。
- 建立第二套外部探测脚本。
- 自动执行 Sub2API 分组迁移。
