# GPT 分组配置基线分析设计

## 目标

使用生产现有历史数据，一次性建立 `GPT-Pro`、`【专属】GPT-Pro`、`GPT-Plus`、`GPT-特惠` 的账号归属和主力/次级/备用基线。基线同时用于评估账号监控页是否能持续发现分组或调度优先级偏离。

## 范围

- 纳入生产 Sub2API 已登记的 GPT/OpenAI 文本账号，包括未分组、暂停或异常账号。
- 排除仅生图账号、Claude 平台/分组账号。
- `自测` 不作为推荐分组；其中的 GPT 文本账号仍作为账号分析对象。
- 仅使用已有真实请求、主动探测、成本/倍率、分组权重与调度配置。不产生新请求，不修改生产数据。

## 证据选择

1. `7d` 是当前配置基线，`30d` 只用于检查长期漂移或七天异常。
2. 成功率、TTFT 和总耗时分别选择数据源。
3. 真实请求对应指标样本数至少为 `20`，且不少于对应探测样本数时，使用真实请求。
4. 真实样本不足或少于探测样本时，使用探测数据。
5. 两类证据均缺失时记录为“待人工处理”，不伪造分数，不在本轮补跑。
6. 每个账号的每项指标必须保留数据源、时间窗口、样本数和最后观测时间。

## 评分与归属

- 使用生产当前每个分组的成本、成功率、TTFT、总耗时权重及目标/上限。
- 使用现有线性评分公式重算，但质量证据改为上述真实优先选择结果；成本数据仍以生产 API 当前投影的成本模式和有效倍率为准。
- 认证、余额/配额、计费、模型不可用、连续失败或证据过期等硬故障先于总分。
- 不直接比较不同分组的总分。先根据 Pro/Plus/特惠的产品定位判断最高可承载档位，再用该分组权重排序。
- `【专属】GPT-Pro` 必须完整镜像 `GPT-Pro` 账号池和优先级，仅用户倍率不同。

## 调度基线

每个分组输出三个稳定层级：主力、次级和备用。优先级数值遵循现有调度器“数值越小越优先”的语义，但具体数值根据生产当前配置与分数分布给出，不在诊断阶段写入生产。

当前 OpenAI 调度使用账号全局 `accounts.priority`。如同一账号跨质量档分组，报告必须显式记录无法为各分组设置不同有效优先级的冲突。

## 交付物

- 生产证据摘要：账号、分组、成本、真实请求、探测、错误、权重与调度配置，不含凭据或请求内容。
- 分组基线报告：每个账号的当前配置、推荐分组、建议调度层级/优先级、证据源、置信度与待人工处理项。
- 评分体系审计：明确哪些部分可保留，哪些数据源、阈值、页面提示或调度语义需调整。

## 安全边界

- 只读 SSH/SQL/API，禁止 `INSERT`、`UPDATE`、`DELETE`、迁移、服务重启、容器重建或调度配置更改。
- 不读取或输出 `.env`、API Key、Cookie、密码、TOTP、请求正文或模型输出。
- 可在生产主机内部使用受保护的 Admin Key 文件调用本地管理 API，但凭据值不得离开主机或进入日志/报告。
