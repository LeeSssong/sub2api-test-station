## 用户最终确认清单

以下是本轮讨论已逐项确认的最终方案。恢复任务时必须整体读取，不得只实现其中一部分，也不得以旧生产页面为准重新设计：

1. 页面视觉沿用已确认 V3 原型并 1:1 还原；当前布局与 UI 方向不再重做，后续重点是数据计算和真实字段接线。
2. 卡片左上只显示账号名称和账号 ID，右上显示账号状态；其下一层独立展示账号分组评分、组内排名和可直接修改的全局优先级。
3. 分组倍率属于分组，只能放在分组汇总，账号卡片不得重复展示。
4. 分组汇总只能显示分组状态、平台、分组倍率、RPM 上限、原生账号数、原生活跃账号数、原生限流账号数七项。
5. 账号卡片按所选真实请求窗口计算评分和排名，默认 24 小时，并可切换 7 天、30 天；探测只在真实请求少于 3 次时补充服务质量证据，不能冒充真实请求。
6. 缺少倍率或有效采购成本只把成本项计为 0 分，账号仍继续参与评分和排名；组内唯一正常可用账号必须排名第 1。
7. 自有真实账号录入一次性人民币采购金额；生效时间由服务端记录，结束时间复用 Sub2API 原生 `expires_at`。上游账号使用原生倍率；人民币与站内美元额度数值 1:1，不做汇率换算。
8. 上游未返回原生倍率时（包括常见的 newapi 账号），账号卡片允许录入并修改倍率；保存为账号的手工倍率覆盖并参与成本评分/排名。未录入时成本项为 0 分但账号仍可排名；有采购成本时仍以采购成本模式为准。
9. 卡片展示 Sub2API 原生当前并发，并以 `current / configured maximum` 形式实时更新；页面可见时每 5 秒批量读取，失败保留最近成功值并提示延迟。
10. 具体分组内桌面一行两卡、移动端一行一卡，并按组内排名升序排列。
11. 账号监控移除所有营收和运营相关内容；未来由独立“营收”页面承接，本轮只记录边界、不实现该页面。

## 页面结构

从上到下固定为：

1. 页面标题、说明和右上角“立即刷新全部”。
2. `全站 + 原生分组` Tab；具体分组来自 Sub2API 原生 `/admin/groups` 数据，不允许用状态桶伪造分组。
3. 一行筛选：账号名称/ID 搜索、一个状态下拉、`24 小时 / 7 天 / 30 天` 分段控件；不得额外展示平台下拉。
4. 具体分组下展示七项原生汇总；全站 Tab 隐藏该分组汇总。
5. 排名卡片网格：桌面每行正好两张，移动端每行一张；按组内排名升序，同排名按账号 ID 升序，未排名置后。

页面内容使用约 1240px 的受限宽度和参考图相同的留白、边框、8px 以内圆角、字阶与浅灰背景，不得铺满整个可用宽度。

## 分组汇总

只能展示以下七项 Sub2API 原生字段：

1. 分组状态 `status`
2. 平台 `platform`
3. 分组倍率 `rate_multiplier`
4. RPM 上限 `rpm_limit`
5. 原生账号数 `account_count`
6. 原生活跃账号数 `active_account_count`
7. 原生限流账号数 `rate_limited_account_count`

分组倍率只出现在这里，不得出现在账号卡片。

## 账号卡片完整结构

每张卡片从上到下固定为：

1. 正常账号使用绿色左边框和浅绿色卡头；左侧账号名称和 ID，右侧状态徽标。
2. 三格评分带：账号分组评分、组内排名、全局优先级。评分取整数；排名明确展示“第 N / 组内可排名数”或“未排名”；优先级可原位编辑。
3. 五个独立浅色指标块：成功率、TTFT P50、总耗时 P95、账号成本、当前并发。成功率、TTFT、总耗时、成本分别使用参考图的绿、蓝、黄、紫弱色底；并发使用中性灰。
4. 近期探测：最近 24 个 `timeline` 点的柱状图、总数/成功/失败、较早/最近标签。探测不可用但完成可达性检查时仍按绿色矮柱展示；真实探测失败使用红柱。
5. 当前窗口调用折叠：标题随范围显示 `24 小时调用`、`7 天调用` 或 `30 天调用`；请求数和失败数只来自同一真实请求窗口，绝不混入探测数。
6. 页脚：检查时间、统计截止时间和单卡刷新图标按钮。不得恢复设置或历史按钮。

卡片不得出现营收、利润、经营、账务、对账、历史流水、异常处理、调整或分组倍率。

## 数据与交互合同

- 窗口只允许 `24h`、`7d`、`30d`，默认 `24h`；评分、排名、请求数、失败数、成功率、TTFT、总耗时和基础成本必须来自同一窗口。
- 全站 Tab 不得留空评分或排名：使用所选窗口的真实请求证据、`DefaultAccountMonitorScoreWeights` 和账号自身成本证据计算账号服务评分，并在全站正常可排名账号中稳定排序；卡片标签固定为“账号服务评分”“全站排名”。具体分组 Tab 才使用该分组权重和组内排名。不得拿任意一个分组的评分或排名冒充全站结果。
- 真实请求少于 3 次时才允许同窗口探测补充服务质量证据；探测不得增加真实请求数、失败数或基础成本。
- 同一卡片的请求数与失败数必须来自同一账号、同一筛选条件、同一真实请求窗口；恒有 `0 <= error_count <= request_count`，不得再出现“0 次请求、212 次失败”一类混窗结果。
- 唯一正常可用账号必须排名 1；倍率或采购成本信息缺失只让成本项为 0 分，账号仍参与评分与排名。
- `accounts.priority` 是唯一可编辑的真实全局优先级，只允许整数 `>= 1`；服务端成功后才替换显示，失败保留草稿、焦点和局部错误。
- 采购成本只录入一次性人民币金额，使用原生 `expires_at`；人民币金额与站内美元额度数值 1:1，不做汇率换算。
- 采购成本非空为采购模式；为空为原生账号倍率模式。上游托管倍率只读，清空采购成本后恢复倍率模式。
- 当原生倍率缺失或不可用时，倍率模式提供手工倍率录入/修改；请求必须同时写入 `rate_multiplier` 与 `rate_multiplier_policy=manual_override`，清除手工倍率只能恢复上游托管策略，不得伪造原生探测结果。
- 当前并发显示 `current / configured maximum`，来自 Sub2API 原生 Redis 槽位；页面可见时每 5 秒批量刷新，隐藏时停止，恢复时立即刷新；失败保留上次值并标记数据延迟。
- 所有可见业务文案使用中文。
