# T98-R2 飞书余额新鲜度、凭据版本与恢复调度设计

## 根因

当前余额快照只记录金额、来源和时间，不记录生成快照时使用的 API Key 身份。账号换 Key 后，旧 Key 的 `USD 0` 快照仍可能被新账号配置消费。通知只要求快照格式有效，不限制最大年龄。活动零余额事件的每分钟复核只读取现有投影；账号若因余额或临时状态退出普通探测池，充值后不会主动刷新余额。

## 设计

- 成功余额快照保存当前 API Key 的 SHA-256 指纹，不保存或记录明文 Key。
- 通知只接受与账号当前 Key 指纹一致、状态为 `ok`、采集时间不超过 10 分钟的余额快照；旧版无指纹快照仅供界面历史展示，不参与告警。
- `RunDue` 遇到活动 `zero` 事件时，先让余额 reader 对该 BaseURL 下全部 active OpenAI API Key 账号执行 declaration + balance 刷新。该路径读取全部监控账号，不受 schedulable、临时隔离或真实流量跳探测影响。
- 刷新失败会把快照状态写为 `failed`，通知因此 fail-closed，不继续使用保留的旧金额发送。
- 成功刷新沿用 `UpdateAccountMonitorBalance` 的 CAS、scheduler outbox 和单账号 cache 同步。余额恢复到 `>=5` 后，同一轮投影解析会 Resolve 活动事件，调度缓存也收到最新账号 extra。
- 发送前保留现有二次读取和 lease 指纹比较；二次投影同样执行 Key 指纹与 10 分钟新鲜度校验。

## 边界

- 保持 BaseURL 聚合、5 美元阈值、30/5 分钟节奏和原生 SchedulerRank 不变。
- 不增加数据库迁移、配置项或新的余额事实源。
- 不依赖未合入的 T98-R3 静默按钮候选。
- 不发送真实飞书消息，不修改生产数据，不合并、推送或部署。
