# 充值页与支付配置修复设计

## 目标

- 充值页加载 checkout 信息失败时显示明确错误和重试入口，不再误报“充值功能暂未开放”。
- 将充值主界面移植到 Figma `4091:422` 的信息结构和桌面尺寸基准，同时保留现有支付订单、恢复和回调链路。
- 让 `payment_visible_method_<method>_enabled` 同时约束 checkout 展示与订单路由。

## 前端设计

- 页面内容宽度使用 1180px 基准；桌面支付区分为 848px 主操作区和 330px 支付摘要区，移动端折叠为单列。
- 账户权益区同时展示余额和并发上限。
- 快捷金额为 10、30、50、100、200 美元，并保留自定义金额、限额校验和现有支付方式能力。
- checkout 请求失败与“成功加载但无可用支付方式”是两个独立状态。失败状态提供重试按钮；空状态才显示支付未开放。

## 后端设计

- 可见支付方式 enabled 设置仅在值明确为 `false` 时关闭，缺失或空值继续沿用旧行为，避免升级后意外关闭既有支付方式。
- 同一判断同时用于 checkout 方法聚合和订单 provider 解析，防止隐藏后仍可直接调用下单接口。

## 验证边界

- 自动测试覆盖错误重试、关键页面结构、金额档位及后端开关兼容语义。
- 本地和测试站仅验证 checkout 与页面，不点击“确认支付”，因此不验证真实支付宝订单创建和资金链路。
