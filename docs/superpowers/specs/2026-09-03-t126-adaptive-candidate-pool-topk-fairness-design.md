# T126 自适应候选池、Top-K 与公平性设计

## 目标

在 Sub 原生 OpenAI 调度器中，根据运行时健康候选规模、质量分差距、负载和故障域集中度，自适应调整候选池模式、有效 Top-K 与探索强度，同时保留统一质量评分、原生利润控制 fail-open、并发/cooldown/能力等硬门禁。

## 非目标

- 不恢复管理员分组 `weight_overrides` 或调度配置页。
- 不改变统一质量评分公式、评分权重或利润进入评分的语义。
- 不重构 Sub 原生利润控制；配置读取失败继续 fail-open。
- 不新增数据库表、外部控制面、独立账务源或 continuity 重构。

## 当前行为与问题

现有实现已支持按分数差距收窄 Top-K，并在 hybrid 模式下追加饥饿账号；候选池模式、探索比例、饥饿阈值和公平权重主要来自固定运行时设置。固定值在候选稀缺、分数接近、负载突增或故障域集中时不能及时改变覆盖范围，可能造成质量过度集中或公平探索不足。

## 方案选择

1. 每请求直接用当前候选统计计算参数：响应快但容易振荡，且会放大单次异常。
2. 后台独立控制面持续优化参数：稳定但引入新事实源、状态和运维面，违反原生优先边界。
3. **采用：原生调度器内的有界、窗口化自适应策略**。复用已有候选和决策投影，在进程内按固定时间窗口更新 EWMA，单次只移动一个档位，并以绝对上下限保护行为。无样本时回退现有默认值。

## 控制流

硬门禁过滤协议能力、账号状态、原生利润门、cooldown、并发、失败域和安全排除后，形成质量候选集合。自适应策略只读取该集合及其质量分、负载、失败率、最近使用时间和故障域分布，计算 effective candidate pool mode、Top-K 和 exploration ratio；随后继续走现有质量排序、sticky、fairness 与账号获取路径。

规则：候选数量低于低水位时扩大到 `all_eligible` 或提高 Top-K；分数差距明显且失败率/负载稳定时收窄 Top-K；分数接近、候选池耗尽率高、故障域集中或账号饥饿时扩大 Top-K 并提高探索；任何结果不得超过配置的最小/最大边界，也不得把硬排除账号重新加入。

## 接口与观测

新增内部策略输入/输出结构，包含候选数、分数差、失败率、负载、故障域集中度、饥饿比例和窗口时间戳；输出 effective mode、Top-K、exploration ratio 与触发原因。复用现有 scheduler decision details/log sink 记录原始候选数、有效 Top-K、最终候选数和原因，不记录请求体、凭据或完整候选敏感信息。

## 失败与兼容

统计缺失、NaN/Inf、缓存不可用或策略计算异常时，回退既有静态配置并继续调度；自适应层不得阻断请求。配置关闭时保持现有行为。部署无迁移、无配置 schema 变化，可通过关闭开关或回滚上一已验证镜像恢复。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 候选不足 | 候选池扩大或 Top-K 提高但不超过上限 |
| 分数差距大且稳定 | Top-K 可逐档收窄但不低于下限 |
| 分数接近 | Top-K 扩大，必要时使用 all-eligible |
| 故障域集中/饥饿 | exploration 增强，优先引入合格且长期未用账号 |
| 统计异常 | 回退静态配置，继续请求 |
| 硬排除账号 | 永不被自适应重新加入 |
| 统一质量分 | 自适应参数变化不改变分数公式或权重 |
| 原生利润配置异常 | 继续 fail-open，且不由自适应层改写 |

## 测试与发布

覆盖策略纯函数边界、窗口滞后/单档位变化、调度集成、硬门禁排除、现有 Top-K 回归和 fail-open 回归。无迁移；发布前只需直接相关 Go 测试、必要构建和 diff-check。部署必须从推送后的干净 `main`，本规格本身不授权部署。
