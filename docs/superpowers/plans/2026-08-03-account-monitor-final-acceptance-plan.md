# 账号监控最终验收实施计划

1. 后端数据契约：过滤软删除分组；补充分组评分阈值；修正评分公式；分别统计成功率、TTFT、总耗时和实测倍率样本；批量返回每账号近期探测时间线；统一账号与分组错误口径。
2. 账号卡片：固定最多两列；指标样本数；近期探测柱；整数评分；通俗数据来源；账号利润；折叠今日调用；弱化评分、排名和调度优先级。
3. 渠道监控：时间柱改用真实探测结果；成功统一绿色；恢复六项指标样本数；总耗时使用真实样本数。
4. 账务链路：增加 `/relay-ops/api/reconciliation/*` 精确反代；前端校验 JSON 结构；修复经营汇总、历史、异常、刷新和补登记。
5. 每个实施任务完成后由独立审查任务核对需求、数据口径和测试；修复审查发现后再进入下一门禁。
6. 执行后端测试、前端测试、类型检查、构建、Caddy 契约和差异检查。
7. 提交并推送当前发布分支，构建不可变镜像，部署非活动槽并切换；只重载必要的 Caddy 配置，不重建 PostgreSQL、Redis。
8. 使用合法管理员会话完成 API、全部按钮、响应式布局、控制台和生产数据逐项验收。
9. 只有推送、部署和线上验证全部完成后，更新项目总账为已完成并提交生产报告。
