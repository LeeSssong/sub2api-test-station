# L1-8 真实路由、线路与扩容验收清单

**当前状态：** 延后；只有真实服务器、域名、上游和样本存在后执行  
**安全规则：** 不在本清单、Git、聊天或测量输出中记录 API Key、Cookie、OAuth Token 或鉴权头

## A. 上游接入

- [ ] 为每家上游建立独立代号、测试分组和可单独禁用的 Sub2API 账号/渠道。
- [ ] 确认支持模型、单位成本、余额、RPM/TPM、并发、429 规则和退款规则。
- [ ] 付费公开流量前确认再分发/商用状态；状态未知时只留在私有测试。
- [ ] 每家每个主模型至少取得 20 个同口径样本，记录成功率、TTFT P95、429 比例和单位成本。
- [ ] 用真实非敏感值生成本地 ROUTE01 并运行 `validate` 和 `score`。
- [ ] 挑战者连续 3 个窗口高出当前渠道至少 8 分后，才提交权重/优先级变更。

## B. 重试与熔断

- [ ] 验证响应开始前的连接失败最多只切换 1 次，并保留同一请求关联 ID。
- [ ] 验证已开始 SSE 后不会跨渠道继续或拼接响应。
- [ ] 对 429 验证 `Retry-After` 和无该头时的 30 秒回退冷却。
- [ ] 对 529 验证 600 秒过载冷却；对 401/402/403 验证不会自动恢复。
- [ ] 用不产生真实扣费的受控故障验证 5 连败打开、60 秒半开、2 次成功关闭。
- [ ] 验证人工禁用跨重启仍保持，且不会被半开探测恢复。
- [ ] 核对失败请求是否计费；无法确认时保持“不自动重试”。

## C. 三网基线

- [ ] 复制 `config/routing/network-measurement.example.yaml` 为 Git 忽略的本地文件。
- [ ] 填满电信、联通、移动 × 白天、20:00–23:00 × 两个网络分段的 12 格样本。
- [ ] 每格至少 20 个样本，记录 RTT、丢包、DNS、TCP、TLS、TTFB、TTFT 和流中断。
- [ ] 分离入口网络、上游网络和模型排队，不用单一 ping 结论代替 SSE 实测。
- [ ] 只有入口段越过阈值时才收集优化线路测试 IP 和正式报价。
- [ ] 使用相同测量网格比较普通线路和候选线路，不接受只在白天或单运营商的结果。

## D. 纵向扩容

- [ ] 连续采集 CPU、`MemAvailable`、swap、容器重启、PostgreSQL 连接、Redis 和 SSE 并发。
- [ ] 任一阈值触发后先排除泄漏、错误连接池和异常请求，再确认升级 4 GiB。
- [ ] 升级前完成数据库备份和恢复抽查，记录停机和回滚方式。
- [ ] 升级后使用相同负载和时间窗复测，确认瓶颈确实改善。

## E. 第二节点

- [ ] 4 GiB 纵向扩容已经完成且数据证明仍是入口节点瓶颈。
- [ ] 满足可用率或持续 SSE 并发门槛。
- [ ] 月故障损失估算至少为新增节点月成本的 1.5 倍。
- [ ] PostgreSQL/Redis 不使用节点本地单机数据，备份和回滚已验证。
- [ ] JWT、TOTP、版本、配置和时间同步在节点间一致。
- [ ] 用户确认 D11 后才购买和部署第二节点。

## F. 关闭条件

- [ ] D10/D11 的数据、候选、成本和风险已写入决策记录。
- [ ] 任何购买均由用户在最终报告审阅后自行完成。
- [ ] 变更前后使用相同测试集，改善和新增成本均可解释。
