# 星桥新手教程与生产链接修复设计

**日期：** 2026-07-25

**生产站点：** `https://api.xingqiaolab.top`

**参考页面：** `https://tkapi.fun/api-beginner-guide/`（已获得页面设计与内容复刻许可）

## 目标

在星桥生产域名下提供一份面向新用户的完整教程，并修复当前生产环境中错误、过时或含义不清的跳转。用户从官网或 Sub2API 控制台点击“文档”后，必须进入星桥自己的 `https://api.xingqiaolab.top/docs/`，不得再跳转到其他中转站。

本任务只修改生产部署所使用的仓库文件和生产配置。不得启动、停止、重建或修改本机 Sub2API、Colima、本地数据库或本地容器。

## 已确认的生产问题

- Sub2API 公开设置中的 `doc_url` 当前为 `https://api3.xmhbao.cn`，导致顶部“文档”打开其他中转站。
- `balance_low_notify_recharge_url` 当前为旧地址 `https://api.43-133-75-82.sslip.io`。
- `/docs/` 当前由 Sub2API 单页应用兜底处理，返回控制台外壳而不是独立教程。
- 官网“文档”链接当前定位到首页的接入说明区块，不能替代完整教程。
- `充值/订阅` 使用 CatFK 作为现有业务收银台；这是经批准的必要第三方服务，不应被误判为错误链接。
- 管理员菜单中的 Sub2API 上游 GitHub 链接是管理员专用的合法外链。

## 方案

采用独立静态教程并由现有 Caddy 在同域 `/docs/` 下提供服务。

- 教程文件和图片进入 `homepage/public/docs/`，随现有 homepage 构建产物发布。
- Caddy 在 Sub2API 反向代理之前显式处理 `/docs`、`/docs/` 和 `/docs/*`。
- `/docs` 规范化重定向到 `/docs/`；`/docs/` 返回教程首页；图片等资源使用同域路径。
- Sub2API 的 `doc_url` 更新为 `https://api.xingqiaolab.top/docs/`。
- 官网桌面和移动导航中的“文档”更新为 `/docs/`。
- 余额不足通知的充值地址更新为 `https://api.xingqiaolab.top/custom/xingqiao-storefront`。

不把教程做成 Sub2API Markdown 自定义页。Markdown 页无法忠实复刻固定顶部栏、桌面目录、移动端响应式版式和大幅截图排版。也不把教程加入 React SPA 路由，避免让文档可用性依赖 JavaScript 启动和首页运行状态。

## 教程内容

保留并按星桥生产能力改写以下内容：

1. 开始前先了解：密钥安全、小额测试、价格和分组以生产页面为准。
2. 充值并确认余额：从 `充值/订阅` 进入现有收银台，说明刷新、订单号和客服处理方式。
3. 创建 API 密钥：名称、分组、自定义密钥、IP、额度、速率和有效期。
4. 导入 CC Switch：使用生产控制台当前提供的导入和“使用密钥”能力。
5. 启动 Codex 并完成首次测试。
6. 查看 Token 和扣费：解释输入、输出、缓存、倍率和最终扣费。
7. 常见错误：401、余额不足、429、模型不可用和超时。
8. 密钥安全建议。
9. 完成检查与联系客服。

删除以下不符合当前生产状态的内容：

- 注册和邮箱验证码。生产公开设置当前 `registration_enabled=false`。
- 邀请好友和返利。生产公开设置当前 `affiliate_enabled=false`。
- TK API 专属优惠、退款、群号、域名和品牌描述。
- 未由星桥维护的临时安装包和网盘链接。教程保留 Codex/CC Switch 配置步骤，但不发布未经验证的下载地址。

## 链接规则

用户常规流程允许以下同域目标：

- `/`
- `/docs/`
- `/dashboard`
- `/keys`
- `/usage`
- `/custom/xingqiao-storefront`
- `/support`

允许的第三方服务只有：

- CatFK 收银台：通过现有 `xingqiao-storefront` 自定义页面承载。
- Sub2API 上游 GitHub：仅管理员菜单可见。

教程正文不得链接其他中转站、旧 `sslip.io` 域名、TK API 页面或空 `href`。确需新增外链时，必须有明确用途、可访问性验证，并使用新窗口与 `noopener noreferrer`。

## 生产配置

新增一个幂等配置脚本，使用现有受控 Compose/PostgreSQL 访问方式更新：

- `doc_url`
- `balance_low_notify_recharge_url`

更新必须在串行化事务中完成，使用 advisory lock，失败时回滚，不打印秘密或完整设置响应。脚本不得覆盖 `custom_menu_items`、支付配置或其他无关设置。

教程静态文件、Caddy 路由和数据库设置必须分开验证。数据库设置失败不得导致错误链接被当成成功上线。

## 测试与验收

- 静态内容测试：品牌、域名、QQ、章节清单正确，不含 TK API、其他中转站、旧域名、邮箱注册或返利内容。
- 路由测试：`/docs` 重定向到 `/docs/`，`/docs/` 返回教程，所有图片返回 200，未知 `/docs/*` 返回 404 而不是 Sub2API SPA。
- 配置脚本测试：初次写入、覆盖旧值、幂等执行、事务重试、并发更新保护和秘密扫描。
- 官网测试：桌面和移动“文档”均指向 `/docs/`。
- 链接审计：抓取官网、教程、登录后主要用户导航，记录所有 `href`、路由目标、HTTP 状态和最终域名。
- 浏览器验证：桌面 1440x1000、移动 390x844；检查顶部栏、目录、正文、图片、跳转、控制台错误和无重叠。
- 生产验证：公开设置返回新的同域地址；从真实顶部“文档”入口点击后最终停留在 `api.xingqiaolab.top/docs/`。

## 部署与回滚

按现有生产发布流程构建并发布 homepage/Caddy 变更，之后执行幂等配置脚本。上线前保存当前 `doc_url` 和 `balance_low_notify_recharge_url` 的脱敏快照。

回滚顺序：

1. 恢复上一版 homepage/Caddy 部署。
2. 将两个设置恢复为上线前记录的值；若旧值属于已确认错误地址，则将 `doc_url` 临时置空以隐藏入口，不恢复错误中转站链接。
3. 验证生产首页、控制台和 API 健康状态，确认没有改动用户、密钥、余额、订单、渠道或账本数据。
