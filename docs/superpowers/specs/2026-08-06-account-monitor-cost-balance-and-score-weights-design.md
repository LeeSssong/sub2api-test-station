# 账号监控成本、余额与评分权重修复设计

## 状态

- 产品方案已于 2026-08-06 确认。
- 本文只定义账号监控的展示、评分与辅助探测，不改变生产请求调度算法。

## 背景与问题

账号监控 V3 重做页面时移除了分组评分权重入口，但既有评分权重弹窗、前端 API、后端接口和持久化仍然存在。当前账号成本编辑又被塞进窄指标栏，输入框与操作按钮互相挤压，无法稳定使用。

现有采购成本评分还有一个更根本的问题：它按账号有效期把人民币采购成本摊入所选统计窗口，再直接除以美元基础成本。这个算法既把账号成本错误地与时间绑定，也直接混用了 CNY 与 USD，不能用于不同类型账号的公平比较。

同时，OpenAI API Key 上游账号缺少余额展示；Sub2API 声明倍率、New API 付费测量倍率和余额刷新目前又共用一个 `force` 布尔值，无法分别表达“跟随健康探测”“六小时付费测量”和“单卡强制刷新”。

## 目标

1. 恢复当前分组的评分权重查看、编辑和重置入口。
2. 用轻量弹窗替换账号卡片内拥挤的成本输入。
3. 为采购账号增加“预计可用额度（USD）”，用采购成本与预计额度计算统一成本倍率。
4. 让采购账号与 API Key 上游账号在同一分组中使用同一套成本评分公式。
5. 为 OpenAI API Key 上游展示标准化 USD 余额及其新鲜度。
6. 余额和官方 billing probe 跟随账号健康探测；单卡手动刷新强制执行健康、余额与官方 billing probe，但不维护独立的 New API 付费倍率测量周期。
7. 辅助刷新失败时保留最后一次有效数据，不让健康探测被辅助接口拖成失败。

## 非目标

- 不根据账号监控评分改写账号 `priority`、路由权重或生产调度顺序。
- 余额不参与评分和排名。
- 不把营收、利润、账务或对账功能放回账号监控页。
- 不自动推断采购账号最终能使用多少额度，也不把默认值 60 USD 批量写入历史账号。
- 不在本次工作中重新定义非 OpenAI 平台的账号成本分类；已有数据继续兼容展示。

## 统一经济口径

### 收入口径

已确认充值关系为：用户支付 `1 CNY`，获得 `1 USD` 站内额度。因此分组倍率可视为每消耗 `1 USD` 官方基础成本时产生的人民币收入系数。

### 账号成本倍率

OpenAI 账号按接入类型自动选择成本来源，不提供人工类型选择器：

- `account_type=apikey`：这是上游 API Key 账号，成本倍率取声明倍率、New API 测量倍率或管理员手工覆盖倍率。
- 其他 OpenAI 账号类型：这是采购账号，成本倍率为：

```text
estimated_cost_multiplier = procurement_cost_cny / estimated_usable_quota_usd
```

示例：

```text
4 CNY / 60 USD  = 0.0667x
4 CNY / 120 USD = 0.0333x
```

采购成本代表已经支付的人民币，预计可用额度代表管理员对该账号整个生命周期可消耗官方美元额度的估计。该口径不再按账号有效期或当前统计窗口摊销。

接入类型是 OpenAI 账号成本来源的唯一判据。API Key 账号即使历史上残留采购成本字段也只使用倍率；非 API Key 账号即使存在 `rate_multiplier` 也只使用采购成本与预计额度。残留字段不自动删除，但不得参与错误的评分路径。

### 混合分组评分

同一分组可以同时包含采购账号和 API Key 上游账号。两类账号先各自得到同单位的 `effective_cost_multiplier`，再进入同一个成本得分公式：

```text
cost_score = cost_weight * clamp(
  (group_rate_multiplier - effective_cost_multiplier) / group_rate_multiplier,
  0,
  1
)
```

总分仍由成本、成功率、TTFT 和总耗时四部分相加，现有目标值、上限值和取整规则不变。一个账号属于多个分组时，账号成本倍率保持不变，但分别与各分组自己的 `group_rate_multiplier` 和评分权重比较。

采购账号缺少预计可用额度时显示“成本待确认”，`effective_cost_multiplier=null`、成本项得 0 分；成功率、TTFT 和总耗时仍正常计分，该账号只要服务证据合格就继续参与排名。不得因为成本待确认而把它移入不可排名账号。

## 数据模型与接口

### 账号字段

在 `accounts` 增加可空字段：

- `estimated_usable_quota_usd NUMERIC(14,2)`，必须为有限正数。

现有 `procurement_cost_cny` 继续允许 0，两个字段作为一组由管理员账号更新接口原子保存。任何触及采购配置的新保存请求都必须同时提交采购成本和正数预计额度；清空操作则同时把两者设为 `NULL`。迁移后已有采购成本保持原值，新增预计额度为 `NULL`，因此在管理员明确确认前只显示“成本待确认”。

前端对没有持久化预计额度的采购账号可在弹窗草稿中预填 `60`，但只有管理员点击保存、后端成功持久化后才能参与成本评分。

### 余额快照

账号监控投影为 OpenAI API Key 账号增加只读 `balance` 对象：

- `value_usd`：最后一次有效 USD 余额。
- `source`：`sub2api` 或 `newapi`。
- `status`：`ok`、`stale`、`failed`、`unsupported` 或 `unavailable`。
- `observed_at`、`last_attempt_at` 和 `failure_code`：用于判断新鲜度和解释失败。

余额快照保存在账号 `extra` 的独立版本化键中。失败尝试只更新尝试时间和错误状态，保留最后一次有效 `value_usd` 与 `observed_at`。非 OpenAI API Key 账号不返回可展示余额。

余额来源：

- Sub2API：读取 `/v1/usage` 的 `balance` 或 `remaining`，单位 USD。
- New API：读取 `/api/usage/token/` 的 `total_available`，除以 `/api/status` 的 `quota_per_unit`，结果单位 USD。

来源识别复用现有声明探测结果：`/v1/sub2api/billing` 已支持的账号按 Sub2API 处理；声明接口明确返回不支持后才按 New API 端点处理。不得在每个探测周期同时请求两套余额接口。

### 监控投影版本

账号监控投影 `schema_version` 从 3 升为 4，并新增：

- 账号级 `estimated_usable_quota_usd`。
- 账号级 `balance`。
- 更新后的 `cost_mode`、`effective_multiplier` 和成本状态语义。

分组评分权重继续复用现有 GET、PUT、DELETE 接口，不创建重复接口。

## 倍率单一事实源与刷新模型

官方 Sub2API `v0.1.171` 已原生支持通过 `accounts.rate_multiplier` 保存账号倍率，并以
`extra.upstream_billing_rate_sync_enabled` 表达倍率归管理员手工维护还是归上游探测写回。
本功能必须直接复用这两个原生字段和官方更新能力，不再维护
`upstream_billing_rate_multiplier_policy`，也不再把
`account_monitor_multiplier_measurement.value` 作为第二套倍率值。

- 账号监控展示、成本评分、真实请求计费统一读取 `accounts.rate_multiplier`。
- `upstream_billing_rate_sync_enabled=false` 表示当前倍率由管理员手工填写。
- `upstream_billing_rate_sync_enabled=true` 表示当前倍率由官方 billing probe 管理；来源标签只描述所有权，不参与数值选择。
- 余额快照继续独立刷新；New API 余额解析保留，但删除账号监控自建的付费倍率测量、6 小时倍率 TTL 和强制倍率测量分支。

### 全量与定时探测

每次账号健康探测周期都执行健康探测，并为符合条件的 OpenAI API Key 账号刷新余额。Sub2API 声明倍率也跟随同一探测周期刷新。

倍率写回频率完全跟随官方 `upstream_billing_rate_sync_enabled` 与 billing probe 调度，不再由账号监控维护独立 TTL。

### 单卡手动刷新

单卡刷新始终重新执行健康探测、余额刷新和官方 billing probe。手工倍率保存必须在同一次官方账号更新请求中写入 `rate_multiplier` 并关闭 `upstream_billing_rate_sync_enabled`。管理员点击“恢复自动获取”时开启官方 probe 与 rate sync，随后触发单账号刷新，使 `accounts.rate_multiplier` 尽快得到官方探测值。

### 失败隔离

健康探测结果先独立持久化。随后执行的余额、声明倍率或付费测量任何一项失败时：

- 本次健康探测仍按真实健康结果成功落库并返回。
- 保留该辅助字段最后一次有效值。
- 将对应辅助字段标记为失败或过期，记录失败码和最后尝试时间。
- 其他辅助字段继续执行，不因为一个来源失败而短路。

## 前端交互

### 分组评分权重

选中具体分组时，分组摘要由七项扩展为八项。第八项显示当前权重，例如“成本 15 · 成功 45 · TTFT 20 · 延迟 20”，并提供编辑图标按钮。

点击后复用现有 `AccountMonitorGroupScoreDialog`。保存或重置成功后重新加载当前统计范围，使摘要、账号得分和排名使用同一份最新权重；失败时保留弹窗输入并展示错误。全站 Tab 不显示分组权重入口。

### 账号成本弹窗

点击账号卡片“账号成本”的编辑按钮打开轻量弹窗，移除当前卡片内的窄行内输入。

OpenAI API Key 账号弹窗显示：

- 当前倍率、来源、新鲜度和自动/手工策略。
- 倍率输入，单位 `x`；保存时原子写入 `rate_multiplier` 并关闭官方倍率同步。
- “恢复自动获取”操作，开启官方 probe 与倍率同步并刷新当前账号。

OpenAI 非 API Key 账号弹窗显示：

- 采购成本，单位 CNY。
- 预计可用额度，单位 USD。
- 根据草稿实时计算的预计成本倍率。
- 保存和清空成本信息操作。

弹窗没有“倍率/采购成本”人工切换器，账号平台和接入类型决定字段。保存期间禁用重复提交；校验或接口失败时弹窗保持打开并聚焦错误字段。

非 OpenAI 账号不引入新的自动分类。它们同样使用轻量弹窗替代行内输入，但由既有成本数据决定兼容模式：已有采购成本时编辑采购配置，否则编辑既有倍率；本次不改变其评分来源。

### 余额展示

OpenAI API Key 账号卡片显示“上游余额”指标：

- 有有效值时显示美元金额和数据来源。
- 刷新失败但存在历史有效值时继续显示该值，并标记“数据延迟”。
- 无有效值时显示“暂不可用”，不得显示为 0。
- 非 API Key 账号不渲染空余额指标。

单卡刷新按钮继续作为健康与辅助数据的统一手动入口，刷新中保持卡片级 loading，完成后重新加载当前统计范围。

## 兼容与迁移

- 数据库迁移只增加可空正数约束字段，不回填 60 USD，不重写现有采购成本。
- 新增清理迁移把旧 `upstream_billing_rate_multiplier_policy=manual_override` 转为原生 `upstream_billing_rate_sync_enabled=false`，把 `upstream_managed` 转为 `true`，保留现有 `accounts.rate_multiplier` 数值，然后删除旧策略键。
- 同一迁移删除 `account_monitor_multiplier_measurement`，不保留运行时兼容读取；迁移后唯一倍率配置值为 `accounts.rate_multiplier`。
- 现有分组评分权重数据和默认权重保持不变。
- 旧采购成本账号升级后进入“成本待确认”，质量分继续排名；管理员保存预计额度后自动获得成本分。
- 所有新快照字段使用版本化 JSON，无法解析的旧值按 `unavailable` 处理，不影响健康探测。

## 验证

### 后端

- 迁移、Ent schema、DTO 和管理员更新接口正确读写 `estimated_usable_quota_usd`，拒绝 0、负数、NaN 和 Inf。
- `4/60=0.0667x`、`4/120=0.0333x`，不再依赖账号有效期或统计窗口。
- 混合分组中两类账号进入同一成本公式；不同分组倍率分别计算。
- 缺预计额度的采购账号成本项为 0，但质量项仍计分并参与排名。
- Sub2API 和 New API 余额解析、USD 归一化、最后有效值保留与失败状态均有测试。
- 手工保存原子关闭官方 rate sync 并写入原生倍率；恢复自动原子开启官方 probe/rate sync，并在探测后更新同一原生倍率字段。
- 监控投影、成本评分、真实请求计费和 usage log 倍率快照均以 `accounts.rate_multiplier` 为源，不存在声明值、测量值与计费值分叉。
- 清理迁移正确转换旧策略并删除两个旧 JSON 键，应用代码中不再暴露或写入 `rate_multiplier_policy`。
- 任一辅助刷新失败不改变已落库的健康探测结果。

### 前端

- 分组摘要显示第八项权重入口；全站不显示；保存和重置后得分、排名与摘要同步刷新。
- API Key 与采购账号打开不同弹窗，页面不存在人工模式选择器或旧窄行内输入。
- 采购弹窗默认草稿 60 USD 未保存前不改变投影，保存后显示推导倍率。
- 手工倍率保存、恢复自动获取、错误保留、重复提交保护均有组件与页面集成测试。
- API Key 卡片正确展示正常、延迟、失败和无数据余额状态；其他账号不出现空占位。
- 桌面和移动视口验证弹窗、八项分组摘要和卡片指标无挤压、溢出或遮挡。

### 发布与线上验收

实现完成后必须通过受控不可变镜像和既有蓝绿/维护发布路径部署。线上至少验证一个 Sub2API API Key、一个 New API API Key、一个 60 USD 采购账号和一个 120 USD 采购账号；确认分组权重保存/重置、单卡强刷、官方倍率同步开关、余额来源、混合排名和失败保留行为。只有代码已推送、生产已部署且上述行为已验证生效，总账状态才可改为“已完成”。
