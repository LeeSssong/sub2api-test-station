# T25 自建渠道监控最终视觉与主动探测重试设计

## 背景与证据

当前自建渠道监控继续复用原生 Monitor V2 API 和主动探测链，但页面在后续精简中偏离了用户确认的旧版卡片层级：调用证据仍显示成功数/总数，趋势柱体仍按失败与耗时改变颜色和高度，倍率视觉权重偏低。`ChannelMonitorService.runChecksConcurrent` 对每个模型只执行一次 `runCheckForModel`，首次临时失败会直接写入本轮历史。

历史基线 `aabae0397` 已通过真实页面预览确认包含所需的 TTFT/总延迟 P50 与 P95、TPS、缓存率和样本数；其模型列表合同已经被后续 API 正式移除，因此不能整文件回退。

## 目标

- 保留现有 Monitor V2 数据合同与旧版卡片信息层级。
- 删除用户圈选的模型相关行、P95 解释和页面底部说明。
- 将调用证据统一显示为“基于 N 次真实请求。”，不展示成功/失败拆分。
- 强化基础倍率视觉权重。
- 趋势柱体统一青绿色、固定高度和宽度；结果与耗时仅留在无障碍标签/悬浮详情，不改变柱体视觉。
- 每个模型的本轮主动探测首次失败后最多重试 5 次；任一次成功即停止，六次均失败才写入失败结果。

## 非目标

- 不恢复 `models` 字段、模型列表或展开/收起交互。
- 不改变 T19 已上线的 Monitor V2 真实请求统计口径：`actual_cost > 0` 的有效服务响应继续作为相关统计分母。
- 不改变分组状态、可用率、TTFT/TPS/缓存计算、账号调度、隔离、计费或错误分类。
- 不新增数据库迁移、历史回填、生产样本或平行监控事实源。

## 方案比较

1. 整体回退到历史组件：视觉最接近，但会重新引入已经删除的 `models` API 和旧统计语义，风险高。
2. 在当前合同上恢复旧版视觉层级并最小扩展主动探测：保留现有 API 与 T19 口径，只修改展示和单模型执行策略，范围最小。
3. 新建第三套渠道监控页面和探测器：重复现有事实源，维护成本高。

采用方案 2。

## 前端合同

- `MonitorV2GroupCard` 继续显示：TTFT P50、输出 TPS、总延迟 P50、缓存命中率、TTFT P95、总延迟 P95，以及各自样本数。
- 可用率右侧百分比保留；左侧证据为 `基于 {eligible_count} 次真实请求。`。零样本时沿用现有状态文案。
- 倍率使用独立高对比背景、边框和更大字重字号，保留 `×` 与无障碍“基础倍率”。
- `MonitorV2Timeline` 每个已有数据点使用相同青绿色和固定高度；空桶也使用同一乐观柱体形态，不再用灰/红/高低表达探测结果。title 与 aria-label 仍保留真实探测结果和延迟。
- `MonitorV2View` 删除页尾两条说明。

## 后端控制流

1. 每个主模型/附加模型仍由现有 errgroup 并发执行。
2. 单模型内部最多调用 `runCheckForModel` 6 次。
3. `operational` 与 `degraded` 均代表已获得有效上游服务响应，立即返回，不再重试。
4. `failed` 或 `error` 继续下一次；第 6 次结果作为本轮最终结果。
5. context 被取消或超时时立即停止，并返回当时最后一个结果，不额外制造请求。
6. 共享 ping 仍只执行一次。runner 单轮 context 上限调整为 `6 * monitorRequestTimeout + monitorPingTimeout + buffer`，确保重试预算真实可达。
7. 历史表仍每模型每轮只写一条最终结果，不记录中间失败，避免改变聚合分母。

## 失败语义与兼容性

- 临时错误在后续尝试成功时，本轮只记录成功结果。
- 六次均失败时只记录最后一次失败，状态与消息沿用现有 checker。
- 调度 interval 小于最坏重试时长时，现有 in-flight 去重会跳过重叠任务，不并发执行同一 monitor。
- 无 API、DTO、配置 schema 或数据库变化。

## 验收矩阵

- 前端：页面含 P50/P95/TPS/缓存和样本；不含模型区、P95 解释、底部说明；调用证据精确为“基于 N 次真实请求。”；倍率有强化类；所有点柱体同色同高。
- 后端：首次成功调用 1 次；第 2 至第 6 次任一次成功时按对应次数停止；六次全失败调用 6 次并返回最后结果；context 取消后停止。
- 视觉：桌面双列、移动端单列无整页横向溢出，文本不遮挡。
- 发布：无迁移、无生产数据写入；预检 `downtime_required=false` 时继续蓝绿发布，`true` 时停在维护授权门禁。

## 测试与回滚

- Vitest 覆盖卡片文案、删项、倍率类和统一柱体。
- Go unit test 覆盖重试次数、成功停止与全失败。
- 执行前端 focused tests、typecheck/build，后端 service focused tests、受影响包 compile-only/server build、gofmt 和 diff-check。
- 回滚为上一生产槽/镜像；如仅需关闭主动探测，可使用现有 `channel_monitor_mode=v2` 配置切回官方页。
