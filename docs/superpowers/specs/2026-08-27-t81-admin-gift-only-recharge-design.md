# T81 管理员仅赠送额度充值设计

**状态：** 已获用户确认实施；仅本地候选，不推送、不部署。

**问题证据：** `UserBalanceModal` 将 `amount` 设为必填，并以 `!form.amount` 禁用确认按钮；提交函数也要求现金金额大于零。因此管理员输入 `¥0` 与 `$5` 赠送额度时不能提交。原生 `QuotaWalletService.Recharge` 已接受 `AmountCNY=0` 且 `GiftQuotaUSD>0`，仅拒绝两个值同时为零或任一为负。

**目标：** 管理员在“充值”模式可只赠送额度：现金金额或赠送额度任一大于零即可提交。账本仍写入既有 `quota-ledger`，并沿用原生幂等、缓存失效与审计。

**非目标：** 不修改后端服务、API、数据库、迁移、支付订单、退款语义、账务事实源、生产配置或部署链。

**选择：** 只改 `UserBalanceModal` 的本地有效性判断，而不在前端复制账本规则或改写后端。派生 `isValidMutation`：充值为 `amount > 0 || giftQuota > 0`；退款为 `amount > 0`。这与原生服务契约相同：充值双零仍被服务端拒绝，退款仍不可为零。

**数据流：** 管理员输入 -> 弹窗计算有效性 -> `POST /admin/users/:id/quota-ledger`（带现有幂等键）-> 原生钱包服务写入一条 `recharge` 流水，其中现金和付费额度变化为零、赠送额度为正 -> 前端刷新父视图。

**失败与兼容：** 输入负值继续受 input 最小值和后端非负校验保护；双零在按钮、前端提交校验和服务端均被拒绝；退款不接受赠送额度单独操作。既有“现金充值”与“现金+赠送”行为不变。

**验收与测试：** 新增组件测试验证仅赠送会调用请求，双零充值显示金额必填错误且不请求，退款零金额仍不可请求；运行该组件测试及其现有回归。无迁移，预期 `downtime_required=false`；本轮按用户指令不推送或部署。
