# T108 OpenAI 错误生命周期、分组模型准入与 404 处理规格

**日期：** 2026-09-01  
**任务包：** T108  
**状态：** 设计已确认，待实施计划  
**范围：** OpenAI HTTP 请求链路，重点覆盖 Responses、Chat Completions、Messages 兼容入口及其共享账号选择/错误处理链路

## 1. 问题证据与当前行为

当前 Sub 原生能力分成三层：

1. 账号能力层由 `Account.IsModelSupported()`、`model_mapping`、账号平台和端点能力决定候选账号。
2. 模型发现层由分组 `ModelsListConfig` 过滤 `GET /v1/models` 返回值。
3. 错误恢复层由账号级限流、临时不可调度、上游错误处理和请求级 failover 决定是否重试或切换账号。

这三层并未形成统一的分组请求准入链路。当前 `Group.ModelsListConfig` 只在 `GatewayHandler.Models` 生成列表时使用；OpenAI 请求调度主要调用 `Account.IsModelSupported()`，因此客户端可以手工请求一个未出现在分组模型列表中的模型。OpenAI OAuth 空映射/透传账号还可能按原生兼容策略放行未知模型，导致 `gpt-5.6-luna` 在列表已移除时仍进入上游。

当前 404 处理也存在语义分裂：

- 上游明确返回模型不存在时，已有账号-模型冷却和 failover 逻辑，应继续保留。
- 通用 failover 状态集合没有统一覆盖所有 404。
- 部分路径对裸 404 采用宽泛的模型不存在判断，可能把端点、Base URL 或路径问题错误写成模型级状态。
- 流已经输出语义内容后，不能重放请求并拼接第二段响应。

这些行为对通用 Sub 的兼容目标是合理的，但不满足本项目的产品语义：分组列表代表用户可调用模型集合；单个账号的通道问题不应直接暴露给用户；监控应接近用户最终体感，而不是统计内部 attempt。

## 2. 目标与非目标

### 2.1 目标

- 将启用的分组模型列表作为 OpenAI 请求的产品级准入清单。
- 保留 Sub 现有 `model_not_found` 的账号-模型隔离和切号行为。
- 对非模型类 404 执行请求级、有界的账号跳过/切号，不写持久化账号故障状态。
- 将中间 attempt 与逻辑请求最终终态分离：最终完整有效响应才算成功，用户最终看到错误或流终止才算失败。
- 保证已开始语义输出或已产生副作用/计费不确定时不进行不安全重放。
- 复用原生 usage、错误流水、账号状态和调度事实源，不新建第二套账务或监控事实源。

### 2.2 非目标

- 不替换 Sub 原生调度器、账号槽位、账号级模型映射或原生计费。
- 不恢复或新增 `external-primary`、平行控制面或平行错误事实源。
- 不改变已确认的 `model_not_found` 现有定制行为。
- 不在本任务中重做 T87 逻辑请求终态实现；本任务只定义其与 404/模型准入的接口契约。
- 不扩展到非 OpenAI 平台、生图专用语义、Responses WebSocket 专用协议或管理 API 的资源型 404，除非它们明确复用本任务定义的共享请求错误契约。

## 3. 原生能力复用与最小扩展

### 3.1 直接复用

- 账号候选过滤继续使用原生 `IsModelSupported`、平台/端点能力、账号状态、额度自动暂停和账号槽位。
- 明确模型不存在继续使用原生 `HandleUpstreamModelNotFound` 与账号-模型冷却键。
- 账号错误和管理员诊断继续写入现有错误/运维日志结构。
- usage 与成本/扣费继续使用 Sub 原生 usage 记录和结算流程。

### 3.2 最小扩展

- 在 OpenAI 请求进入账号选择前增加分组模型准入判断；它只读取当前 API Key 所属分组的有效 `ModelsListConfig`。
- 将上游 404 分类为 `model_not_found`、`route_or_channel_not_found`、`unknown_not_found` 三类，并把“是否可切号”和“是否写持久化状态”分开表达。
- 将非模型类 404 纳入请求级 failover 决策，但不让它落入账号-模型冷却或账号永久错误状态。
- 使最终请求状态、用户可见结果和内部 attempt 归因使用同一逻辑请求标识，供 T87/Monitor V4 消费。

## 4. 端到端控制流

1. 认证和分组解析完成后，读取分组模型准入配置。
2. 若分组模型列表已启用且请求模型不在列表中：在选号前返回现有模型不可用/`model_not_found` 兼容响应；不选择账号、不访问上游、不切号、不写账号故障状态。
3. 若模型通过分组准入，进入原生账号调度；账号级 `IsModelSupported` 仍决定具体账号是否可承接及如何映射。
4. 上游返回错误或流读取失败时，先生成一次 attempt 诊断，再根据输出状态、副作用状态和错误分类决定：同账号重试、跨账号切换或终止。
5. 若允许重试，当前账号加入本次请求排除集；请求级切换次数受既有 T87/原生预算约束，不新增无界循环。
6. 若最终得到完整有效响应，逻辑请求终态为成功，内部中间失败不进入分组失败分母。
7. 若所有安全候选耗尽，逻辑请求终态为失败；用户收到最终脱敏错误，管理员仍可查看完整诊断摘要。

## 5. 404 分类与处理契约

### 5.1 明确模型不存在

证据包括结构化错误码 `model_not_found`、明确的“model not found/unknown model/does not exist”等模型语义，且请求上下文包含模型。

- 当前请求：允许有界切号。
- 状态写入：复用 Sub 原生账号-模型临时冷却。
- 用户可见：若其他账号成功则隐藏；候选耗尽后保持现有 `model_not_found` 定制响应。
- 监控：中间 attempt 不计最终失败；最终失败只计一次逻辑请求失败。

### 5.2 明确端点、Base URL 或路径问题

证据包括响应体或上游诊断明确指向 endpoint/route/path/base URL/resource route，而非模型能力。

- 当前请求：跳过当前账号并允许有界切号。
- 状态写入：只记录管理员诊断和本次 attempt；不写账号临时不可调度、不写账号-模型冷却、不永久禁用账号。
- 用户可见：若其他账号成功则隐藏；全部候选耗尽后返回脱敏 502 `api_error`/上游不可用语义。
- 监控：最终失败只计一次；账号视图保留该账号的通道诊断，分组视图只反映用户最终结果。

### 5.3 无法判断的裸 404

无结构化错误码且响应体不足以确认模型或路由含义时：

- 当前请求：最多执行一次请求级有界切号，不进行无界重试。
- 状态写入：只记录管理员诊断，不写持久化账号状态。
- 用户可见：任一候选成功则隐藏；候选耗尽后统一返回脱敏 502。
- 监控：按最终逻辑请求终态计失败，不把裸 404 单独扩大为模型池故障。

### 5.4 安全重放边界

- 在 HTTP 状态尚未提交且没有语义输出、副作用或计费不确定时，允许切号。
- 已输出语义内容、已创建上游副作用、已确认 usage/扣费，或状态无法确认时，禁止重放和拼接第二段响应。
- 流终止后的用户响应必须遵循现有流错误契约，不伪装为成功。

## 6. 分组模型准入契约

- `ModelsListConfig.Enabled == true` 且模型列表非空时，列表是该分组的用户请求允许集合，而不仅是展示集合。
- 比较使用规范化后的模型 ID；不得因为大小写、空白或现有合法别名处理造成绕过。
- 列表外模型在账号选择前被拒绝，不进入上游，不消耗账号重试预算，不切换账号，不生成上游错误流水。
- 该准入只约束分组用户入口，不修改账号级模型映射；管理员账号详情仍可看到账号支持模型。
- 分组列表未启用时，保持当前原生账号能力语义，不新增隐式白名单。
- `gpt-5.6-luna` 若被 GPT-Plus 分组列表移除，直接在入口被拒绝；该行为与上游随后返回的 `model_not_found` 账号隔离逻辑分开。

## 7. 逻辑请求终态与监控

逻辑请求以稳定的请求标识聚合所有 attempt：

- `success`：用户收到完整、有效、协议闭合的响应。
- `failed`：用户最终收到错误、流在完成前断开，或响应状态不明且无法安全恢复。
- `in_progress/unknown`：仅用于内部处理中，不得被最终监控当作成功。

中间 404、403、429、502、503、网络断流和 `malformed_stream` 只作为 attempt 诊断；如果后续安全切号并成功完成，分组最终失败数不增加。账号视图可以保留账号级 attempt 失败和冷却原因，但分组视图只按用户最终逻辑请求统计。

## 8. 错误可见性与审计

- 用户只获得脱敏错误类型、状态码和可执行建议，不返回 API Key、完整 Base URL、内部账号 ID、原始请求体或上游敏感头。
- 管理员诊断至少保留逻辑请求 ID、attempt 序号、账号名称、账号 ID、分组、请求模型、上游状态、分类、是否切号、切号原因、输出是否开始、usage 是否已知和最终终态。
- 非模型类 404 的管理员诊断必须能区分“端点/通道”与“未知裸 404”，防止后续误把它们统计为模型不可用。
- 诊断写入失败不能阻断已确定的用户响应，也不能把中间错误升级为账号持久化禁用。

## 9. 场景化验收矩阵

| 场景 | 预期行为 |
|---|---|
| 分组列表包含模型，首账号成功 | 单次成功，无切号 |
| 分组列表移除 Luna，用户手工请求 Luna | 选号前拒绝，不访问上游，不切号 |
| 账号 A 返回明确 model_not_found，账号 B 成功 | A 写账号-模型冷却，B 成功，用户无感 |
| 所有账号均明确 model_not_found | 保持现有 `model_not_found` 定制响应，失败计一次 |
| 账号 A 返回 endpoint 404，账号 B 成功 | A 仅记录诊断，B 成功，A 不持久化下线 |
| 所有账号返回 endpoint 404 | 用户收到脱敏 502，失败计一次，保留每个 attempt 诊断 |
| 裸 404 后第二账号成功 | 最多一次有界切号，用户成功，裸 404 不扩大为模型故障 |
| 裸 404 后无其他候选 | 返回脱敏 502，不写账号状态 |
| 404 发生在已有语义输出之后 | 禁止重放/拼接，按流错误终态结束 |
| 中间 503/429/断流后最终完整成功 | 分组成功率记成功，中间错误只在账号/attempt 诊断可见 |
| 流缺少 `response.completed` 且无法恢复 | 用户失败，逻辑请求失败计一次 |
| 分组模型列表未启用 | 保持原生账号模型支持和调度语义 |

## 10. 测试策略

- 入口准入测试：启用列表拦截 Luna/任意列表外模型；禁用列表保持原生路径；空白、大小写和别名规范化。
- 调度测试：模型准入失败不调用账号选择；通过准入后仍遵循账号 `IsModelSupported`。
- 404 分类测试：结构化模型 404、明确路由 404、裸 404、错误体缺失、不同账号连续结果。
- 状态写入测试：模型 404 写账号-模型冷却；路由/裸 404 不写账号临时不可调度或账号-模型冷却。
- failover 测试：未输出时可切号；输出后不可重放；候选耗尽只返回一次最终错误。
- 逻辑终态测试：中间失败最终成功、中间失败最终失败、断流、缺少完成事件、usage 已知/未知。
- 直接相关 OpenAI handler/service 测试、必要的 server build、gofmt、`git diff --check`；不执行无关全仓扩展验证。

## 11. 兼容性、迁移与发布

- 无数据库迁移、无新配置字段、无新依赖。
- 保持现有错误响应协议和 `model_not_found` 定制文案；新增 502 仅用于非模型类 404 候选耗尽场景。
- 运行时仅复用现有账号、分组、错误日志和 usage 数据；不回填历史 attempt，不修改历史计费。
- 实施候选必须独立 worktree 完成，先通过直接相关测试和构建，再交由根发布总控合并、推送、从干净 `main` 发布并线上验收。
- 本规格不授权任何部署；发布仍受验收站全局约束和用户明确主站授权限制。

## 12. 方案比较与选择

### 方案 A：保持原生完全不改

优点是兼容面最大、改动最少；缺点是分组模型列表仍只是展示，Luna 等列表外模型可被手工请求，非模型 404 可能直接暴露，监控也无法稳定按用户最终结果统计。**不满足本项目目标。**

### 方案 B：所有 404 统一切号并统一标记账号故障

优点是恢复积极；缺点是把模型不存在、端点错误和裸 404 混在一起，容易错误冷却模型或误伤账号，且会扩大无效重放。**风险过高。**

### 方案 C：分组准入 + 404 分类 + 请求级有界切号（推荐）

分组列表负责产品准入，账号映射负责账号能力，原生模型 404 冷却继续复用，非模型 404 只做请求级切号并记录诊断，最终结果交给逻辑请求终态。该方案改动集中、保留 Sub 原生事实源和状态机，同时解决用户可见错误、模型越权和监控失真的实际问题。
