# 商用 AI API 中转站实施计划

> **执行方式：** 每个 L1 阶段方案经用户确认后，由 AI 自主拆解并连续完成 L2-L4 的调研、实施、验证和记录；用户只处理已编号的关键决策和不可避免的账户操作。根据 D13，完整报告审阅前不执行任何真实付款、充值、购买、收款或商户开通。

**更新日期：** 2026-07-15  
**目标：** 先用现有上游 API 跑通可售卖闭环，再接入 K12、Plus、Pro 等订阅账号池和其他上游中转 API，逐步优化成本、线路、稳定性与自动化收款。  
**默认架构：** 境外单节点（首选东京，其次新加坡）+ Ubuntu 24.04 LTS + Docker Compose + Sub2API + PostgreSQL + Redis + Caddy + 现有上游 API；内测期优先腾讯云国际站 Lighthouse 2 vCPU / 2 GiB 年付活动机，配置 swap 和内存约束，达到扩容阈值后再升 4 GiB。  
**首个可验收目标：** 服务器、域名和上游凭据就绪后 1 个工作日内，用测试 API Key 完成一次真实流式请求，并在后台看到模型、Token、上游、扣费和请求日志。

### 全局约束

- 第一优先级是尽快跑通可售卖的纵向闭环；多节点、高可用、自动支付和昂贵优化线路不前置。
- 技术选择优先可逆、低成本和可验证；每次只推进一条当前关键路径。
- USD 20/月是服务器硬上限，不是默认支出目标；内测期先争取百元以内或两百元左右的境外年付活动机。
- 所有服务器、域名、上游充值、订阅账号、收款和商户渠道只做选型与记录；完整报告审阅前不执行真实交易，后续配置按“未购买/假定资产”继续准备。
- 用户不参与 L2-L4 日常技术选择；只有 Dxx、Axx、Rxx 或明显偏离已确认阶段方案时才暂停。
- 上游密钥、OAuth 凭据、Cookie、2FA 恢复码和支付密钥不进入 Git、普通聊天或实施文档。
- 不提供凭据提取、登录绕过、验证码绕过、地区/风控规避或未经授权访问；订阅账号通道只使用项目支持的正常授权入口，并受当时适用条款约束。
- 供应商结账页、库存和当时条款优先于本计划中的公开报价；购买前由 AI 再核对一次。

## 1. 工作树与当前状态

### 1.1 分层方式

```text
L0 项目目标
└── L1 大阶段
    └── L2 子系统
        └── L3 工作包
            └── L4 可执行任务
```

状态统一使用：`未讨论 → 讨论中 → 方案已定 → 可执行 → 执行中 → 已验收`。

### 1.2 L1 总工作树

```text
L0 建成可运营的商用 AI API 中转站
├── L1-0 确定项目基线与现有资产
├── L1-1 准备服务器、域名和网络入口
├── L1-2 部署 Sub2API 核心网关
├── L1-3 接入现有上游 API
├── L1-4 跑通调用、日志和计费闭环
├── L1-5 建立用户、Key、人工充值和小范围运营
├── L1-6 接入 K12、Plus、Pro 等订阅账号池
├── L1-7 接入自动支付并开始正式售卖
├── L1-8 优化线路、调度、成本与稳定性
└── L1-9 建立日常运营、对账和扩容机制     ← 离线准备已完成
```

### 1.3 第一条纵向闭环

```text
境外服务器
→ Docker / Sub2API / PostgreSQL / Redis / Caddy
→ 现有上游 API
→ 测试用户和 API Key
→ 流式请求
→ 用量日志
→ 余额扣费
→ 人工充值
```

只有这条闭环通过后，才扩展订阅账号池、多上游、支付和高可用。

## 2. AI 主导的项目机制

| 标记 | 含义 | 是否暂停 |
|---|---|---|
| `[AI 自主]` | 可逆、低成本、无账户风险的技术和执行选择 | 不暂停 |
| `[需你决策 Dxx]` | 预算、供应商、商业规则或不可逆选择 | 暂停等答复 |
| `[需你操作 Axx]` | 只有资产到位或真实环境验收时才能由账户所有人完成的登录、实名、支付、授权或凭据录入 | 根据 D13 集中延后；不阻塞离线准备 |
| `[需你知悉 Rxx]` | 需显式记录的商业、账户或合规风险 | 默认不暂停 |

执行规则：

1. 用户只确认 L1 阶段目标、成本边界、主要风险和完成条件，不逐层确认 L2-L4。
2. L1 确认后，AI 每次只选择一条当前关键路径，自行拆到 L4 并连续执行；可逆、低成本、无账户风险的技术选择不暂停。
3. 只有遇到尚未确定且会显著改变方案的 Dxx、不可逆操作、显著商业/合规风险或需要明显偏离已确认方案时暂停；Axx 按 D13 进入最终外部操作清单，不逐项阻塞离线准备。
4. 遇到 Dxx 时，只提供推荐、备选、成本、影响和最小回复格式；同一阶段多个决策合并成不超过 3 项的决策包。
5. 完成里程碑后，只汇报结果、验证证据、剩余风险和下一决策，不向用户倾倒过程日志。
6. 工作树、实际配置、决策与验收结果回写项目文件，不依赖聊天记忆；恢复工作时先读项目状态，再继续当前关键路径。

## 3. 现有资产、假设与 MVP 边界

### 3.1 已知资产

- 已有至少一家上游中转 API，可提供 Base URL 和 API Key。
- 首版接受人工充值和小范围测试，优先换取上线速度。
- 后续供给包含卡网购买的 K12、Plus、Pro 等消费订阅账号，并继续接入其他中转 API 赚取价差。
- 项目交由 AI 主导，用户仅保留关键决策和必须由账户所有人完成的操作。

### 3.2 MVP 包含

- 用户建立、API Key 生成/吊销、额度和并发限制。
- 至少一个文本模型的流式与非流式调用。
- 用量日志、余额扣费、价格倍率和人工充值。
- 一家现有上游 API 和一个可被禁用的调度渠道。
- HTTPS、基础防火墙、密钥保护、日志和数据库备份。

### 3.3 MVP 不包含

- 多节点高可用、自动故障转移和专用优化线路。
- 全自动支付、发票、代理分销和复杂优惠券。
- 图片、视频、音频、Realtime、文件托管和 WebSocket 全协议覆盖。
- 提取他人凭据、绕过登录、绕过地区/风控或规避 CAPTCHA 的技术方案。

## 4. 调研结论与首版选型

### 4.1 服务器与线路

| 选项 | 2026-07-15 公开信息 | 判断 |
|---|---|---|
| 腾讯云国际站 Lighthouse 新用户年付 | 产品页展示 Linux 2 vCPU / 2 GiB / 40 GB / 20 Mbit/s / 0.5 TB 为 USD 10.08/年，原价 USD 50.4/年；活动页的 1 年卡可选新加坡、东京、首尔等境外地区，不含香港。另有 2 vCPU / 4 GiB / 60 GB / 30 Mbit/s 为 USD 28.8/年，原价 USD 72/年 | 2 GiB 套餐是当前最低成本首选；活动要求 Lighthouse 产品新用户且每类限购 1 次，续费恢复官网价，最终以登录后的结账页为准 |
| 阿里云中国站 SWAS 活动 | 官方产品页宣传“支持海外地域，低至 68 元 1 年”；活动页明确新用户国内/海外均可选、可选 1 个月/1 年，但公开实时询价未返回 68 元对应的确切配置、地域和续费价 | 作为第二个低价候选；只有结账页确认境外、至少 2 vCPU / 2 GiB 且首年不高于 CNY 150 时才选 |
| 腾讯云中国站活动 | 活动页展示国内低价机，并另列境外 Linux 2 vCPU / 4 GiB / 60 GB / 30 Mbit/s / 1.5 TB 月流量、首尔/雅加达/曼谷、1 年套餐；未登录时活动价显示为待查询 | 作为年付兜底；国内机虽然更便宜，但正式绑定域名可能涉及备案，且不适合后续依赖境外上游和消费订阅账号通道 |
| 香港月付轻量机 | 腾讯国际站公开月付 2 vCPU / 2 GiB 约 USD 4.2/月、2 vCPU / 4 GiB 约 USD 8.5/月；阿里国际站香港 2 vCPU / 2 GiB 约 USD 8/月、2 vCPU / 4 GiB 约 USD 16/月 | 仅在低价境外年付活动不可买、或东京/新加坡实测无法满足上游可达性时启用 |
| AWS Lightsail | 公网 IPv4 Linux 套餐 2 vCPU / 2 GiB / 60 GB / 3 TB 为 USD 12/月，2 vCPU / 4 GiB / 80 GB / 4 TB 为 USD 24/月；有新加坡、东京、首尔，无香港区 | 账单清晰、全球生态成熟，但首版成本明显高于年付活动，作为低价活动和香港月付均不可用时的备选 |
| Vultr Cloud Compute | Regular Performance 2 vCPU / 4 GiB / 80 GB / 3 TB 为 USD 20/月，按小时计费 | 部署和迁移灵活，但没有针对中国大陆的线路承诺，首版性价比不如前两项 |
| 普通香港 BGP/国际线路 | 价格低，不保证中国大陆晚高峰质量 | 适合 MVP，先实测再升级 |
| CN2 GIA / CTGNet | 面向中国电信通常更稳，但价格高、容量有限，香港/日本比洛杉矶更贵 | 不在 MVP 阶段购买 |
| CMI/CMIN2、联通 AS10099 等高端线路 | 不同运营商回程表现差异很大；部分高端套餐同时接 CN2 GIA、CMIN2 和联通 Premium | 不仅依赖线路名称，购买前测试 IP、去回程路由和晚高峰三网数据 |

阿里云官方文档明确说明：从中国大陆访问香港或其他境外轻量服务器可能出现高延迟和丢包；带宽不保证，高峰期资源竞争可能降低带宽。因此“香港 + 200M”不等于“大陆三网 200M 稳定直连”。

API 中转首版主要承载文本、JSON 和 SSE 长连接，20 Mbit/s 已有充足吞吐余量；比带宽数字更重要的是上游可达性、连接稳定性、月流量、续费价和退出成本。2 GiB 是本项目单机部署 Sub2API、PostgreSQL、Redis 和 Caddy 的最低起点，1 GiB 套餐不进入候选。

**首版推荐采用条件式择优：**

1. 先核对腾讯云国际站东京区 2 vCPU / 2 GiB / 40 GB / 20 Mbit/s / 0.5 TB 套餐；若结账仍为 USD 10.08/年且账户有活动资格，选择该套餐。
2. 若腾讯活动不可买，再核对阿里云 68 元/年活动；只有结账页证明是境外、至少 2 vCPU / 2 GiB 且首年不高于 CNY 150 时选择。
3. 若上述最低价套餐都不可买，选择腾讯云国际站境外 2 vCPU / 4 GiB / 60 GB / 30 Mbit/s 的 USD 28.8/年活动套餐。
4. 只有所有年付候选失败、或境外活动地区无法访问现有上游时，才回到香港 2 GiB 月付；任何折算超过 CNY 250/年的新选择都重新提交确认，不因 USD 20/月上限而自动花满。
5. 2 GiB 主机默认建立 2 GiB swap、限制 PostgreSQL 连接数，并监控内存；出现 OOM/容器重启，或 `MemAvailable < 300 MiB`、swap 使用量超过 512 MiB 持续 15 分钟时，升级到 4 GiB。

### 4.2 核心网关对比

| 项目 | 优势 | 结论 |
|---|---|---|
| **Sub2API v0.1.155** | 账号/API 渠道、Token 计费、智能调度、粘性会话、并发、限流、支付和后台；与订阅账号池路线直接匹配 | 首版选用 |
| New API v1.0.0-rc.21 | 多模型聚合、协议转换和渠道路由更广，支持 Responses、Realtime、Claude、Gemini | 作为协议聚合对照，不是首版底座 |
| One API v0.6.10 | 令牌、兑换码、倍率、负载均衡和重试成熟，MIT 许可证 | 发布节奏相对慢，老式默认部署不适合直接作商用基线 |

Sub2API 当前官方 Compose 使用 PostgreSQL 18 Alpine 和 Redis 8 Alpine。生产部署锁定已验收的 Sub2API 版本或镜像 digest，不长期追随漂移的 `latest`。

### 4.3 商业站公开做法

对 SHUAI API、AICodeMirror、PatewayAI、API 快连等公开页面进行了观察。以下只记录可见产品做法，不把营销自述当作内部架构证明。

| 样本 | 公开可见做法 | 本项目吸收方式 |
|---|---|---|
| SHUAI API | 明示基础兑换比例、模型分组倍率、渠道来源和售后边界；页面声明基于 New API | 首版把价格、倍率、渠道质量和支持边界写清楚 |
| AICodeMirror | 首页直接提供定价、分平台教程、独立状态页；同时有 PAYGO、月度折扣包和企业席位 | 首版先做教程和状态入口；套餐、企业席位和发票后置 |
| PatewayAI | “注册 → 充值 → 替换 Base URL”三步流程；强调逐请求 Token/费用明细和多协议兼容 | 用户交付必须在 10 分钟内完成首次调用，并能逐笔查费用 |
| API 快连 | “创建 Key → 替换 Base URL → 按量付费”；公开展示模型分组、用量监控、文档和客服入口 | 首版提供 Key、模型白名单、用量页、文档和单一客服入口 |

**立即借鉴：** 短 onboarding、透明价格/倍率、单请求用量、一个已实测客户端教程、服务状态和客服入口。

**闭环后再做：** 充值优惠、月度套餐、邀请奖励、企业席位、合同/发票、40+ 模型展示和多节点 SLA。

**不照搬：** 未经证实的“官方渠道”“满血”“零风险”和 99.9% SLA；不隐藏渠道质量差异，不在未实测前宣称兼容所有模型与客户端。

**入口取舍：** 首版域名直达 Caddy，暂不打开 CDN 代理，减少 SSE 缓冲和超时变量；闭环稳定后再对比 Cloudflare 或 DCDN，不能从公开响应头推断样本站的源站和内部组件。

## 16. 里程碑、验收与目标节奏

| 里程碑 | 验收信号 | 资产就绪后的目标节奏 |
|---|---|---|
| M0 基础设施就绪 | SSH Key、域名、HTTPS 入口和上游网络可用 | 0.5–1 天 |

| M2 首条请求闭环 | 测试 Key 完成流式请求，用量与扣费正确 | 0.5–1 天 |
| M3 首批人工运营 | 3–10 人真实调用，至少一笔小额充值可对账 | 2–5 天 |

## 17. 方案自检

### 17.1 与已确认目标的一致性

- 现有上游 API 是第一供给，不等待新上游合作。
- K12、Plus、Pro 等订阅账号是正式后续供给通道，没有从方案中排除。

- 服务器、开源项目和商业站公开做法已纳入选型。

- 公开站点的 CDN/WAF 响应头不证明其内部使用任何特定组件。
- 商业站自述的上游来源、折扣、并发和供应规模未被当作已验证事实。
- “200M 峰值带宽”未被当作中国大陆用户的保证带宽。
- 技术上可导入消费订阅账号，未被表述为获得官方 API 转售权。
