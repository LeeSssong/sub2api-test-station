# T110 账号监控真实请求与调度排名统一设计

日期：2026-09-01（Asia/Shanghai）
状态：用户已批准，进入实施

## 1. 问题与当前证据

账号监控卡片存在三处口径冲突：

1. `real_request_timeline` 只读取持久化真实请求，空桶不读取原生主动探测，因此账号只有一笔真实请求时只有一根有效柱；这与“无真实请求时使用主动探测兜底”的最新要求冲突。
2. 卡片只显示当前 24h/7d/30d 窗口内的真实请求数，没有显示账号历史累计真实请求数。底层流水已持久化，但页面无法区分窗口量和累计量。
3. T96 已将普通文本账号实际调度固定为 `成功率 DESC -> P95 TTFT ASC -> 有效成本 U ASC -> 账号 ID ASC`，旧评分权重不参与调度；账号监控仍暴露评分权重、质量排名和调度排名多套概念。

## 2. 目标

1. 卡片同时展示当前窗口真实请求数与历史累计真实请求数。
2. 时间线按 5 分钟源桶执行“真实请求优先、无真实请求才用一次主动探测”，再聚合为固定 24 根卡片柱。
3. 主动探测不得增加窗口或累计真实请求数，Tooltip 必须明确来源。
4. 分组视图的列表顺序和卡片主排名只使用调度器投影的 `scheduler_rank`。
5. 全站视图不再把旧质量权重排名冒充调度排名；按各账号在所属分组中的最佳原生调度名次排序，并明确展示“最佳组内调度排名”。
6. 评分权重 API 与持久化数据保留兼容，但账号监控移除编辑入口和误导性摘要，明确其不参与当前调度。

## 3. 非目标

- 不改变 T96 调度器、资格过滤、健康隔离、利润门、重试预算或账号槽位。
- 不改变账务、价格、成本公式、`usage_logs`/`ops_error_logs` 写入。
- 不新增迁移、事实表、历史回填或生产数据写入。
- 不把主动探测写入真实请求计数。
- 不改变 Monitor V4 分组级终态与持久化快照。
- 生图和非普通文本路径继续使用既有原生调度语义。

## 4. 数据契约

### 4.1 真实请求计数

- `real_request_evidence.request_count`：当前选择窗口内的去重真实请求数。
- 新增 `lifetime_real_request_count`：同一持久化事实与去重规则下，账号历史累计真实请求数。
- 两者均使用 `usage_logs + ops_error_logs`，优先 `logical_request_id`、其次 `request_id`、最后使用单行稳定键；排除 `usage_completeness='unknown'`。
- 主动探测不进入任一计数。

### 4.2 混合时间线

后端先生成 5 分钟源桶：

```text
源桶有真实请求 -> 只选真实请求终态
源桶无真实请求且有主动探测 -> 只选该账号最新一次探测终态
二者都没有 -> no_data
```

随后将源桶按时间均匀聚合成固定 24 个展示桶。每个展示桶返回：

- `request_count/success_count/failure_count`：真实请求计数；
- `probe_count/probe_success_count/probe_failure_count`：兜底探测计数；
- `source`：`real | probe | mixed | no_data`；`mixed` 仅表示展示桶包含不同 5 分钟源桶，单个源桶仍不混用；
- `ttft_p95_ms`：优先真实成功样本；展示桶完全无真实样本时使用成功探测样本。

## 5. 排名与评分权重

- 分组视图继续直接消费调度器生成的 `scheduler_rank`，列表排序与卡片数字使用同一字段。
- 全站视图对账号所有所属分组的 `scheduler_rank` 取最小值，生成只读 `best_scheduler_rank`、`best_scheduler_rank_total` 与 `best_scheduler_group_name`；不存在任何分组调度排名时显示“未排名”。
- 全站排序为最佳组内调度名次 ASC、账号 ID ASC。
- `quality_rank/group_rank` 保留响应兼容，但不再决定账号监控 DOM 顺序或主排名。
- 评分权重接口与表保留，账号监控页面删除编辑按钮、弹窗挂载和分组摘要字段，改为静态说明“当前调度使用固定质量顺序，评分权重不参与调度”。

## 6. 失败与安全语义

- 累计查询失败时账号监控整体请求失败，不以 0 冒充累计值。
- 探测查询失败时账号监控整体请求失败，不用空桶掩盖数据源异常。
- 探测 `unknown` 状态作为无结果，不投影为失败。
- 不返回凭据、API Key、Authorization、完整请求体或完整上游响应。

## 7. 验收矩阵

1. 窗口内一笔真实请求时，卡片显示窗口 `1`；历史有更多流水时累计值大于 `1`。
2. 无真实请求但有成功探测的 5 分钟源桶显示绿色探测兜底柱，真实请求数保持 `0`。
3. 同一 5 分钟源桶同时有真实请求和探测时只使用真实请求。
4. 探测失败显示红色探测柱；探测 `unknown` 或完全缺失显示灰色无数据。
5. 24h/7d/30d 均固定返回 24 根展示柱。
6. 分组页面 DOM 顺序、卡片排名与调度器候选排名一致。
7. 全站页面显示每个账号最佳组内调度排名，不再使用质量权重排名。
8. 修改或保留旧评分权重不会改变页面主排名和调度排名。
