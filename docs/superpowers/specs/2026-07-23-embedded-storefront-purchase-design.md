# 站内嵌入店铺购买页设计

## 目标

将 Sub2API 用户侧的原生 `/purchase` 页面替换为同域的星桥购买页。购买页在站内嵌入星桥在 `catfk.com` 的店铺 `https://catfk.com/shop/DLK8SNUJ`，让用户浏览和购买兑换卡时不离开 `api.xingqiaolab.top`。

本次只交付购买页嵌入。卡密生成、卡密导入、兑换、自动增加额度、订单回调和退款不在本次范围内。

## 架构

1. Caddy 在通用 `sub2api:8080` 反向代理之前匹配 `/purchase` 与 `/purchase/`。
2. 匹配到的请求由首页构建产物中的静态 `purchase.html` 响应；不会改动 Sub2API 镜像或数据库。
3. 静态页面在一个无 sandbox 的跨域 iframe 中加载 `https://catfk.com/shop/DLK8SNUJ`。不加 sandbox 是为了不破坏外部店铺的支付表单、跳转和弹窗能力；星桥页面不读取 iframe 内容、Cookie 或订单状态。
4. 页面始终提供“在新窗口打开店铺”链接。当第三方站点未来拒绝 iframe、支付流程要求顶层窗口，或用户需要在独立窗口完成操作时，可以继续购买。

## 用户流程

1. 已登录用户在 Sub2API 点击“充值/订阅”。
2. 浏览器访问同域 `/purchase`，显示“充值与订阅”标题和内嵌店铺。
3. 用户在店铺内购买星桥兑换卡，并由店铺完成交付。
4. 用户后续到星桥兑换页输入卡密。本次不实现该页面和额度变更。

## 安全与边界

- 页面只允许 iframe 指向明确的 `https://catfk.com` 店铺 URL；不接受用户提供的 URL 参数。
- 为壳页设置最小 CSP：禁止脚本、对象和外部资源，仅允许内联样式、同域链接和 `catfk.com` iframe。
- 不把订单完成事件、页面跳转、iframe `load` 事件或前端参数当作“已支付”或“已到账”依据。
- 不在 iframe 内传递 Sub2API Token、管理员密钥、用户余额或卡密。
- Caddy 只在精确购买路径覆盖原生页面，其他 Sub2API 路由保持原样。

## 失败处理

- 第三方站点拒绝被嵌入、付款在 iframe 中无法继续，或网络失败时，用户可使用可见的新窗口链接完成购买。
- 静态页面不尝试绕过第三方的 `X-Frame-Options`、CSP、登录或支付限制。
- 若将来需要自动到账，必须以本站签发且已预登记的卡密为唯一凭据，使用服务端幂等核销和 Sub2API 管理端余额接口；该设计另行评审。

## 验证标准

- `npm run test:run`、`npm run typecheck` 与 `npm run build` 通过。
- Caddy 配置格式和适配的路径顺序可验证，`/purchase` 在通用代理之前处理。
- 在桌面与移动视口中，购买页框架有稳定尺寸且店铺内容非空。
- 页面 CSP 不允许任意第三方 iframe、脚本或对象资源。
