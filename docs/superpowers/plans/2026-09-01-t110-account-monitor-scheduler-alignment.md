# T110 Account Monitor Scheduler Alignment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show window and lifetime real-request counts, fill empty 5-minute source buckets with native active probes, and make account-monitor ranking use the scheduler projection.

**Architecture:** Extend the native account-monitor repository with a lifetime counter and a hybrid account timeline. Keep the card payload at 24 display buckets while preserving 5-minute source-selection semantics. Derive global display order from the best group-scoped scheduler rank and remove score-weight editing from the account-monitor UI.

**Tech Stack:** Go 1.27, PostgreSQL SQL, Vue 3, TypeScript, Vitest, sqlmock.

**Spec:** `docs/superpowers/specs/2026-09-01-t110-account-monitor-scheduler-alignment-design.md`

## Global Constraints

- Do not change scheduler selection, retries, billing, account eligibility, migrations, configuration, or production data.
- Active probes never increment real-request counts.
- Each 5-minute source bucket selects real requests before probes; the API returns exactly 24 display buckets.
- Keep legacy score-weight storage/API compatible but remove it from account-monitor ranking and editing UI.
- Stop after implementation and direct tests; do not merge, push, or deploy.
