# PostgreSQL 备份与恢复真实验收清单

**当前状态：** 2026-07-22 已完成首次服务器本地备份和隔离恢复；连续 7 天与加密异地备份尚未完成  
**禁止事项：** 恢复目标不得是生产数据库；不在普通归档保存明文秘密

## A. 备份前置

- [x] SRV01、生产 Compose、PostgreSQL 版本和数据目录已登记。
- [x] 本地备份目录权限为仅管理员可读写，剩余空间足够。
- [ ] Cloudflare R2 Standard Bucket、最小权限 S3 凭据、restic 仓库密码托管、保留期和删除流程已确认；R2 不可用时才回退 B2。
- [x] 备份命令从运行容器环境读取数据库用户名/库名，不打印密码。
- [ ] 已定义成功、失败和超时的通知负责人。

## B. 每日备份

- [x] `sub2api` 与 `relay_ops` 的 `pg_dump -Fc` 均返回成功，文件非空。
- [x] 记录开始/完成时间、PostgreSQL 版本、文件大小和 SHA-256。
- [x] `pg_restore --list` 可以读取两个归档目录。
- [ ] 本地 7 天和加密异地 30 天保留规则生效。
- [ ] restic `check` 通过，R2/B2 端只保存客户端加密仓库数据。
- [ ] Compose、Caddyfile、脱敏配置和版本清单已包含。
- [ ] 明文 `infra/.env`、SSH 私钥、上游/支付密钥未进入普通备份。

## C. 月度恢复演练

- [x] 使用独立临时 PostgreSQL 18 容器、内部网络、卷和不同数据库名。
- [x] SHA-256 与备份时一致。
- [x] `pg_restore --exit-on-error` 完成且没有忽略错误。
- [x] 逐表精确行数哈希、迁移、管理员、设置和 relay-ops 表数符合预期。
- [ ] 隔离 Sub2API 实例 `/health` 通过，只读后台可访问。
- [x] 恢复时长、人工步骤和结果已记录。
- [x] 临时实例、数据库、网络和卷在验收后销毁。

## D. 恢复生产前的额外门槛

- [ ] 事故负责人确认恢复点和可能丢失的数据窗口。
- [ ] 当前生产数据库先做只读快照或额外备份。
- [ ] 已通知用户停机/只读窗口，并关闭注册、充值和写入通道。
- [ ] 至少两人复核目标实例、数据库名、备份文件和回滚方案。
- [ ] 恢复后先做账务/余额一致性检查，再开放用户写入。

## E. 验收关闭

- [ ] 连续 7 天每日备份成功。
- [x] 至少一次独立恢复演练完整通过。
- [ ] 备份未包含明文秘密，恢复未接触错误目标。
- [ ] OPS01 中备份年龄和恢复演练年龄使用真实数据。

首次恢复证据见 `docs/superpowers/reports/2026-07-22-production-backup-restore-verification.md`。服务器本地归档不能替代 restic 加密异地副本；未建立 R2/B2 前不得声称主机级灾难恢复已完成。
