## 已确认产品决定

### 唯一管理入口

- 管理员账号监控唯一入口是 `/admin/accounts/monitor`。
- 不恢复 relay-ops 自建监控页面、运维页面或浏览器控制面。
- 评分、服务健康、真实账务、对账、定价采集状态和飞书投递状态均在 `/admin/accounts/monitor` 展示或操作。
- 公共 `/pricing` 是面向访问者的价格页面，不是第二个管理员监控入口。

### relay-ops 边界

- 本轮保留 relay-ops 作为不可见的内部后台服务，负责定时采集、逐笔对账、每日结账、价格采集和飞书出站。
- 浏览器关闭后仍必须持续运行的任务不能由 Vue 页面承担。
- relay-ops 不再拥有独立 UI；受保护后台接口仅服务 `/admin/accounts/monitor` 和内部调度。
- 本轮不把 relay-ops 全量迁入 Sub2API worker；待三轮生产闭环稳定后再单独评估服务合并。

### 账号质量评分

- 每个分组独立保存四项评分权重，默认和恢复默认均为：成本优势 15、成功率 45、首包时间 20、总耗时 20。
- 四项必须为非负整数且合计 100；只提供直接配置、保存和恢复默认，不提供预设模板。
- 评分只影响 `/admin/accounts/monitor` 的状态和组内排名，不写入调度器。
- `accounts.priority` 是唯一可编辑的实际调度优先级；卡片修改后立即刷新。
- 成本优势是账号倍率相对当前分组倍率的安全余量，不等于真实利润率。
- 同一账号在不同分组可以有不同成本优势、评分和排名。
- 分组 Tab 按原生分组倍率从高到低；同倍率保持原生稳定顺序，不写排序字段。

### 监控与分组语义

- 服务健康和经营结果都必须支持全站、分组、账号三个层级。
- 分组未向任何有效用户开放时显示“已关闭”，只提示一次，不持续报告“无可用账号”。
- 已开放分组没有可用账号，或存在真实用户请求失败时，仍按故障处理。
- 组内质量样本优先使用请求发生时的不可变 `group_id`；样本不足才回退账号全局样本并明确标识。

### 全站记账与对账

- 范围是全站所有启用且具备账单能力的账号，不按 Wawazz、Neko 或任何供应商名称限定。
- 定时扫描和日结使用全量账号范围；每个可计费账号必须具备合法只读账单授权和明确的账单账号映射。
- 上游真实扣费只来自真实上游交易/快照；不得用倍率、旧 `today_stats` 或前端估算冒充。
- 用户实际计费使用本站真实请求扣费；全站按唯一对账请求计算一次。
- 分组按请求发生时的 `group_id` 归属；未归属请求只进入全站并解释差额。
- 页面展示：用户实际计费、上游真实扣费、纸面利润、利润率、成本覆盖率、待对账数量和历史累计。
- 对账未闭合时显示“待对账”或“对账异常”，不得展示伪造的确定利润。

### 飞书联动

- 飞书只保留主动告警、恢复通知和日报，不恢复入站命令或写控制。
- 最新成功结果不能被历史失败覆盖；最新成功后不能继承历史 `balance_exhausted` 等错误码。
- 所有飞书管理链接统一指向 `/admin/accounts/monitor`。
- 原生 P0/P1 Bridge 本轮不扩大；现有链路满足告警和恢复后即停止。

### 中文展示

- 所有页面、面向人的报告和任务汇报使用中文业务名称。
- 数据库、API 和代码字段可以保留英文，但只能出现在代码、SQL 或技术附录。
- 五类核心数据统一称为：账单授权会话、上游成本快照、对账请求明细、对账执行记录、每日账务快照。
