# T15 规格书自审

## 结论

规格覆盖批准合同，允许进入计划与实现。未发现需要再次请求产品决策的范围变化。

## 覆盖检查

- 原生连接测试复用、按账号模型选择与回退：第 1、2、6、7 节。
- 原生账号模型登记与检测器基线交集：第 1、6、7 节。
- sidecar 仅执行、Sub worker 唯一事实、固定时隙、去重、迟到补触发：第 5、6、8 节。
- 卡片收缩状态行、详情字段、立即检测与模型编辑：第 2、5、6、9 节。
- 八种状态及不参与评分/调度：第 2、8、9 节。
- 凭据、提示词、输出、地址脱敏与 OAuth/API Key 边界：第 2、8 节。
- 许可证门禁、发布链、停机授权：第 3、10、11 节。

## 风险检查

1. `account_monitor_results` 与检测 run 明确分表，避免把检测器结果混入连接探测质量事实。
2. 账号删除使用级联清理设置/检测历史；执行前仍以当前账号状态二次校验，避免幽灵 sidecar 请求。
3. sidecar 不可用时 catalog 为空或 run=failed，主监控 projection 仍可用。
4. 许可证不允许直接复制现有检测器；规格将生产引擎接入设为明确门禁，Sub 侧可以独立测试。

## 计划前置条件

- migration 使用下一个编号 225，保留现有 224 不变。
- 需在 wire 中注入检测服务，但保持旧构造器兼容测试。
- 前端需以现有 `AccountMonitorCard` 为最小扩展，不引入全局摘要或第二页面。
